# epc_qr — платіжний QR-код EPC (SEPA, євро)

Рядок для переказу SEPA Credit Transfer за EPC069-12 і його SVG. Це пара до `payment_qr`: та бібліотека — гривня за правилами НБУ, ця — євро. Знак GiroCode бібліотека не малює.

- Версія: 0.1.0 (`epc_qr.VERSION`).
- Ліцензія: Apache-2.0 (як код транслятора).
- Зображення — лише кодування UTF-8 (елемент 3 дорівнює `1`). `qr_svg` транслятора не має ISO 8859. Кодування `2` можна записати в рядок, але не в SVG.

## Підключення

```sh
ln -s <шлях>/epc_qr lib
```

```prml
|import("lib/epc_qr")
|img(svg=epc_qr.svg("Franz Mustermänn", "DE71110220330123456789", amount=dec("12.3"), bic="BHBLDEHHXXX", version="001"))
```

Імена Franz Mustermänn і François D'Alsace S.A. — приклади з документа EPC, не реквізити особи.

## Функції

| Функція | Результат |
| --- | --- |
| `payload(name, iban, amount=None, bic="", purpose="", reference="", text="", info="", version="002", encoding="utf-8")` | елементи через LF |
| `problem(...)` | причина або `""` |
| `svg(..., module="0.5mm")` | SVG, корекція M, версія не вище 13, тиха зона 4 |
| `rf(reference)` | посилання кредитора ISO 11649 |
| `rf_problem(reference)` | причина або `""` |

`version` — `"001"` або `"002"`. У версії 001 BIC обов'язковий. У версії 002 його можна не давати: бібліотека не перевіряє, чи учасник схеми поза ЄЕЗ. `encoding` — `utf-8` або `iso-8859-1` (також `"1"` і `"2"`).

`amount` — `decimal`. У рядок потрапляє без хвостових нулів: `EUR12.3`, `EUR100`. Межі числа — від 0,01 до 999999999,99 і не більше двох знаків після коми. Окремо весь елемент разом із `EUR` має вміститися в 12 знаків, як у таблиці EPC: `EUR999999999.99` за числом допустимий, за довжиною — ні.

`reference` і `text` разом — помилка. Хвіст після останнього заповненого елемента відрізано; порожні елементи посередині лишаються. Пробіли в IBAN прибираються, у код іде суцільний IBAN.

`module` — довжина одного модуля (`"0.5mm"`). Сторона малюнка — цей розмір, помножений на число модулів разом із тихою зоною.

## Перевірки

IBAN і посилання RF — mod 97, літери `A=10` … `Z=35`, перші чотири знаки в кінець, остача 1. Довжина IBAN — від 15 до 34. Рахунок рахується залишками по одній цифрі, без одного цілого на весь номер: у розгорнутому вигляді він довший за 64 знаки. BIC — 8 або 11 знаків, лише верхній регістр. Навантаження не більше 331 байта: для UTF-8 байти рахує `base64url`, для ISO 8859-1 байт збігається зі знаком, якщо знак увійшов до набору.

Набір кодування `2` — друкований ASCII і знаки U+00A0…U+00FF. Знак євро до нього не входить. Керувальні знаки C1 відхилено.

`rf` бере власне посилання кредитора без префікса `RF`, не довше 21 знака, і повертає не більше 25 знаків.

## Джерела

EPC069-12 v3.1 «Quick Response Code: Guidelines to Enable the Data Capture for the Initiation of a SEPA Credit Transfer», чинний з 19.03.2024. Постановку `libraries/epc_qr.md` звірено з документом 27.10.2026; у цій сесії PDF не відкривався повторно. Приклади розділу 2.3 відтворено байт у байт: V1 — 95 знаків і 96 байтів UTF-8, QR версії 6 при корекції M; V2 — 103 знаки.

IBAN — алгоритм ISO 13616. Текст стандарту платний і не відкривався. Звірено з прикладами EPC `DE71110220330123456789` і `FR1420041010050500013M02606` та з навчальним `UA213223130000026007233566001`. RF — той самий mod 97; приклад EPC `RF18539007547034` дає контрольні цифри 18 для тіла `539007547034`. Текст ISO 11649 не відкривався.

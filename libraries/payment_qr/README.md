# payment_qr — QR-код платежу НБУ для Primula

QR-код для обміну реквізитами кредитових і миттєвих кредитових переказів на рахунку, акті, квитанції: платник сканує його застосунком банку, реквізити й сума заповнюються самі.

- Версія: 0.1.0 (`payment_qr.VERSION`).
- Ліцензія: Apache-2.0 (як код транслятора).
- Правила: постанова Правління НБУ від 19.08.2025 № 97 «Про затвердження Правил формування, передачі та обробки структури даних і графічного зображення QR-коду для обміну реквізитами кредитових та миттєвих кредитових переказів» (зі змінами, постанова № 128 від 11.10.2025), чинна з 01.11.2025 — <https://zakon.rada.gov.ua/laws/show/v0097500-25>; звірено 26.10.2026.
- Потрібен транслятор зі стандартною бібліотекою 1.1 і функціями `qr_matrix`, `qr_svg`, `base64url` (рішення 137, Primula 0.1.0.dev50 і новіші).

## Що робить бібліотека

- Структура даних формату **003** (типово) або **002**: елементи в порядку правил, розділені Lf, кирилиця у Windows-1251 (`encoding="cp1251"`, типово) або UTF-8.
- Гіперпосилання `https://qr.bank.gov.ua/` + Base64URL структури (не більше 507 байтів).
- QR-код версії 10–17 з рівнем корекції M (або Q), білим колом у центрі за версією (17–25 модулів) і знаком гривні в ньому — SVG для `|img(svg=…)`; модуль типово 0,5 мм (менший правила не рекомендують).
- Перевірки: IBAN UA (контрольне число), довжини полів, допустимі знаки (коди 32–255 Windows-1251, крім 127, 152, 160), сума (не більше двох знаків копійок, до 999 999 999,99), форма категорії. Нерозривні пробіли стають пробілами, апостроф U+02BC — U+2019 (у Windows-1251 його немає).

## Підключення

```sh
ln -s <шлях>/libraries/payment_qr lib     # у корені проєкту документа (попередження P2639)
```

або копія каталогу в `lib/`.

```prml
|import("lib/payment_qr")
|img(svg=payment_qr.svg("ФОП Приклад Олена Петрівна", "UA213223130000026007233566001", "1234567890",
                        "Оплата за рахунком № 17 від 26.10.2026, без ПДВ", amount=dec("12500.00")))
```

Повний приклад — `examples/12-payment-qr` (рахунок на оплату).

## Функції

Аргументи всіх функцій однакові: `receiver, iban, code, purpose, amount=None, category=SUPPLIER, function="UCT", reference="", display="", editable=None, valid_until=None, created=None, version="003", encoding="cp1251", check_iban=True`; `svg` додає `module="0.5mm", ecc="M"`.

| Функція | Результат |
| --- | --- |
| `payload(…)` | структура даних (рядки через Lf) до Base64URL |
| `link(…)` | гіперпосилання `https://qr.bank.gov.ua/…` — те, що містить QR-код |
| `problem(…)` | причина українською, чому код не можна побудувати, або `""` |
| `svg(…)` | SVG QR-коду зі знаком гривні; неправильні дані зупиняють збирання з причиною |

| Аргумент | Поле правил | Значення |
| --- | --- | --- |
| `receiver` | 6 Отримувач | ПІБ / найменування, до 140 знаків |
| `iban` | 7 Рахунок отримувача | IBAN UA, пробіли допустимі |
| `code` | 9 Код отримувача | ЄДРПОУ, РНОКПП або інший код, до 10 знаків |
| `purpose` | 12 Призначення платежу | до 420 знаків |
| `amount` | 8 Сума / валюта | `decimal`; без суми платник уводить її сам |
| `category` | 10 Категорія / ціль (003) | `CCCC/PPPP` — коди ISO 20022; див. нижче |
| `function` | 4 Функція (003) | `UCT` — кредитовий, `ICT` — миттєвий, `XCT` — будь-який |
| `reference` | 11 Reference (003) | ідентифікатор рахунку на оплату, до 35 знаків ASCII |
| `display` | 13 Відображення (003) | текст для показу платнику, до 140 знаків |
| `editable` | 14 Код заборони зміни полів (003) | `None` — поле порожнє; список полів, які платник може змінити: `["amount"]` → `FEFF`, решта заборонені |
| `valid_until`, `created` | 15, 16 (003) | `datetime`; записуються як `РРММДДГГХХСС` |

### Категорія / ціль

Формат 003 вимагає поле «Категорія / ціль»: два коди ISO 20022 через `/` — категорія переказу й ціль платежу; за ними банк класифікує переказ. Бібліотека пропонує константи:

| Константа | Коди | Коли |
| --- | --- | --- |
| `SUPPLIER` (типово) | `SUPP/SUPP` | оплата постачальнику за рахунком — товари, роботи, послуги (як приклад правил «Оплата комунальних послуг») |
| `GOODS` | `OTHR/GDDS` | купівля товарів (приклад правил «Оплата товару в інтернет-магазині») |
| `SERVICES` | `OTHR/SCVE` | купівля послуг |

Інші пари — з довідників ISO 20022 (категорія — ExternalCategoryPurpose, ціль — ExternalPurpose); бібліотека перевіряє лише форму `CCCC/PPPP`.

## Перевірка

```sh
PRIMULA=primula ./run-tests.sh
```

Тест звіряє структури з прикладами додатків 3 і 4 до правил (у прикладі 1 формату 002 IBAN має хибне контрольне число — тест вимикає перевірку `check_iban=False`), форми суми, причини для хибних даних і будову SVG. Розпізнавання коду незалежним декодером (`zbarimg`) з PDF прикладу 12 перевіряє тест транслятора `tests/test_example_payment_qr.py`. Перевірку застосунком банку виконує людина.

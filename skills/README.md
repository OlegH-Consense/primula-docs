# Skills для AI-разработки документов и библиотек Primula

Каталог содержит инструкции для моделей (Claude Code, Codex CLI и других агентов, понимающих формат Agent Skills): как писать, править и проверять документы `.prml`. Сами инструкции — на английском (для модели); документы модель пишет на языке задания, по умолчанию украинском.

| Skill | Назначение |
| --- | --- |
| `primula-docs/` | создание, правка, вычитка и исправление документов, фрагментов, модулей, модулей стилей и файлов проекта Primula; цикл «написал → `primula check` → исправил по коду P…» |
| `primula-library/` | разработка, тесты и выпуск библиотеки — каталога модулей `.m.prml` с данными для нескольких проектов; подключение ссылкой, копией или подмодулем Git (решение 136); постановки намеченных библиотек — `docs/libraries/`; готовые библиотеки — `libraries/`, их содержимое — `primula describe` |

## Состав `primula-docs/`

- `SKILL.md` — основная инструкция: где взять транслятор, как узнать контекст (проект, стили, ID, справочник `primula commands --format json`), цикл проверки, главные правила записи, **что нельзя менять при вычитке** (имена стилей, `id=`, `key=`, имена параметров и функций…), типичные ошибки.
- `references/syntax.md` — сжатый обзор синтаксиса (по шпаргалке и спецификации v1.1-draft); аргументы и функции модель берёт из справочника транслятора, а не отсюда.
- `assets/contract.prml` — полный документ-образец (договір про надання послуг), проходит `primula check` без сообщений.

Справочные данные (конструкции, функции, ключи заголовка, диагностика) в skill не переписываются: модель получает их у транслятора (`primula commands`), поэтому они всегда соответствуют версии.

## Состав `primula-library/`

- `SKILL.md` — что модулю доступно и чего нет (и чем заменить), устройство каталога, ошибки для автора через `fail()`, документы-тесты, данные с датой действия, подключение, контрольный список выпуска.
- `assets/template/` — шаблон библиотеки `mylib`: модуль, данные, `project.p.prml`, тест, `run-tests.sh`, README; тест шаблона проходит `primula check`.

Человеку та же схема описана в руководстве автора: `docs/author/ru/11-libraries.md`; полный образец — `examples/11-library`.

## Установка

Claude Code — для всех проектов пользователя или для одного проекта:

```sh
ln -s "$PWD/skills/primula-docs" ~/.claude/skills/primula-docs          # все проекты
ln -s "$PWD/skills/primula-docs" <проект>/.claude/skills/primula-docs   # один проект
ln -s "$PWD/skills/primula-library" ~/.claude/skills/primula-library    # библиотеки
```

Codex CLI с поддержкой skills — так же в каталог skills Codex (`~/.codex/skills/`). Для агента без поддержки skills достаточно строки в `AGENTS.md` проекта документов:

```markdown
For .prml files and Primula projects follow <путь>/skills/primula-docs/SKILL.md.
```

Транслятор должен быть доступен агенту: `primula` в `PATH` (пакет Primula Studio ставит `bin/primula`) или `PYTHONPATH=<primula-docs>/src python3 -m primula`.

## Проверка

`tests/test_skill.py`: образцы `assets/*.prml` и примеры разметки `references/syntax.md` (собранные в один документ) проходят `primula check` без сообщений; заголовок `SKILL.md` содержит `name` и `description`; тест шаблона библиотеки `primula-library` проходит проверку. При изменении языка тест показывает, какой пример устарел.

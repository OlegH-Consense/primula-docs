# Подсветка синтаксиса Primula (`*.prml`) — по спецификации v1.1-draft

Определения для Kate/KWrite/KDevelop, mcedit (Midnight Commander), Geany и VS Code. Основа — `primula-spec-v1.1-draft.ru.md` (разд. 2, 3, 12, прил. 1–2) и `primula-grammar-v1.1.ebnf`.

## Состав

| Каталог | Содержимое |
| --- | --- |
| `kate/` | `primula.xml` (разметка, `*.prml`), `primula-code.xml` (код после заголовка, `*.s.prml`, `*.p.prml`) |
| `mcedit/` | `primula.syntax`, `primula-code.syntax`, `Syntax.prml` (записи для файла `Syntax`) |
| `geany/` | `filetypes.Primula.conf` |
| `vscode/` | расширение VS Code и Cursor (пакет `primula-0.1.0.vsix`; грамматика TextMate `primula.tmLanguage.json`, `primula-code.tmLanguage.json`, `package.json`); грамматику TextMate понимают и другие редакторы (JetBrains, Sublime Text); генерируется `tools/gen_textmate.py`, **не проверялась в самом VS Code** |
| `tests/` | `sample.prml` (все конструкции) и малые файлы для граничных случаев; `check_kate.py`, `check_mcedit.py` |
| `tools/` | генераторы (`gen_kate.py`, `gen_mcedit.py`, `gen_geany.py`, `gen_textmate.py`), словарь `prml_lexicon.py` + `lexicon.json` (из справочника транслятора, `sync_lexicon.py`), отладочные утилиты |
| `install.sh` | установка в профиль пользователя (`./install.sh [kate] [mcedit] [geany]`, `--uninstall`) |

## Установка

`./install.sh` — все редакторы; можно выбрать часть: `./install.sh kate mcedit vscode`.

| Редактор | Что делает скрипт | Вручную |
| --- | --- | --- |
| Kate, KWrite, KDevelop | копирует XML в `~/.local/share/org.kde.syntax-highlighting/syntax/` | перезапустить редактор |
| mcedit | копирует `*.syntax` в `~/.local/share/mc/syntax/`; в пользовательский `Syntax` добавляет блок записей **перед первой строкой `file`** (при отсутствии — создаёт копию системного, резервная копия `Syntax.bak-primula`) | `Ctrl+S` дважды в mcedit перечитывает определения |
| VS Code | `code --install-extension vscode/primula-0.1.0.vsix` (пакет `.vsix` собирает `tools/make_vsix.py`; копировать файлы в `~/.vscode/extensions` недостаточно — программа ведёт `extensions.json`) | перезапустить VS Code |
| Cursor | **не проверялось** (AppImage-версия не дала установить расширение командой; пункта «Install from VSIX» в интерфейсе не нашлось); команда `cursor --install-extension …` (`./install.sh cursor`); VSCodium — `./install.sh codium`; без команды в PATH — Extensions → ⋯ → Install from VSIX… | перезапустить программу |
| Geany | копирует `filetypes.Primula.conf` в `~/.config/geany/filedefs/`, добавляет `Primula=*.prml;` в `[Extensions]` | перезапустить Geany |

Примечание к mcedit: пользовательский `Syntax` **заменяет** системный целиком, поэтому он создаётся как копия системного. После обновления пакета `mc` новые типы файлов в этой копии не появятся.

## Что подсвечивается

Общая модель одинакова; различается только степень точности.

| Элемент Primula | Kate | mcedit | Geany |
| --- | --- | --- | --- |
| YAML-заголовок `---` … `---`: ключи (предопределённые отдельно), строки, числа, даты, `true/false/null`, `#`-комментарии | да (только первая строка файла) | да (`---` в любом месте открывает заголовок) | нет (общий лексер) |
| `|% комментарий`, `|comment:` … `|end` | да (в комментариях выделяются TODO/FIXME) | да | только `|%`, без `|comment:` |
| Экранирования `||` `|{` `|}` `|;` `|~` `|\` | да | да | нет |
| Недопустимые формы: `|` + пробел/цифра/конец строки, `|$ |[ |]`, `|–` (en dash), `|−`; структурные формы `|< |> |- |# |! |:` не в начале строки | да (красным) | частично (без проверки позиции) | нет |
| Заголовки `|<`, `|<<(…)` — маркер и текст жирным | да | вся строка одним цветом | нет |
| Пункты `|>`, списки `|-` `|#`, `|!`, строки таблиц `|:`, ячейки `|&` | да | да (только если в начале строки без отступа) | нет |
| Стили `|.Имя{…}`, `|.Имя:`, `|.(выражение)…`; `|end.Имя` | да | да (аргументы в скобках — нет) | нет |
| Внутристрочные формы `|*{} |/{} |_{} |^{} |,{} |—{} |`{} |"{} |?{}` с вложенностью | да (каждая со своим начертанием/цветом) | до первой `}` (без вложенности) | нет |
| Выражения `|( … )`, формулы `|=( … )` и аргументы команд `(…)` — подмножество Python: строки (в т. ч. f/r, тройные), числа (`1_000`), слова ядра и константы, встроенные и стандартные функции, запрещённые слова (`class import try lambda …`, `:=`) — как ошибка | да, с учётом вложенных скобок и многострочности | до первой `)` | строки "…", числа и часть слов |
| Команды: управляющие (`if elif else for def` и `endif endfor enddef end…`), подключение (`include import`), встроенные (прил. 2.1), пользовательские и модульные (`|имя`, `|мод.имя`) | да | да (имена только латиницей) | только слова из списка |
| `|code:` … `|end` — Python-подмножество, `#`-комментарии; `|verbatim:` и `|verbatim(end="…"):` | да (произвольный маркер) | да (маркеры `EOF` и `END`) | нет |
| Файлы `*.s.prml`, `*.p.prml` (после заголовка — код, разд. 2.2) | отдельный язык `Primula (code)`; в обычном `.prml` переключение по `kind: styles` / `kind: project` | отдельный файл `primula-code.syntax` | не различаются |
| Сворачивание блоков (`|code:`, `|if(…):`, `|table(…):`, `|>(…):` и др. до закрытия; заголовок YAML) | да | нет | частично (по словам `if/for/end`) |

### Ограничения

- **Kate** — точное соответствие лексике; приближения: `XID_Start/Continue` заменены на `\p{L}\p{Nl}` / `\p{L}\p{N}_`; несбалансированная `(` в аргументах «подсвечивает» остаток файла до закрывающей; вложенные окружения внутри `|comment:` не считаются (блок заканчивается первой строкой `|end`).
- **mcedit** — движок без регулярных выражений и вложенности (см. `man mcedit`): `|имя(…)` и `|(…)` заканчиваются на первой `)`, `|*{…}` — на первой `}`; блочные формы с отступом перед `|` не распознаются (`|code:`, `|comment:`, `|verbatim:` и `|end` отступ допускают); имена команд на кириллице не выделяются; в заголовок попадёт любая строка `---`.
- **Geany** — нет собственных лексеров и регулярных выражений (Lexilla встроена), поэтому заимствован лексер «Matlab/Octave». Заметные недостатки: строка после `|#` (нумерованный элемент) показывается как комментарий; команды и структурные формы не различаются. Для точной подсветки в Geany нужен собственный лексер Scintilla (C++), что выходит за рамки конфигурации.

### Допущения при чтении спецификации

1. Структурные формы (`|<`, `|>`, `|-`, `|#`, `|!`, `|:`) вне начала строки считаются ошибкой: в EBNF (разд. 4) среди внутристрочных форм их нет.
2. Закрывающий маркер `|verbatim(end="…")` в Kate принимается с необязательным отступом: грамматика (`EndMarker ::= Indent …`) и текст разд. 3.7 («сравнивается буквально») расходятся.
3. `|end…` в Kate распознаётся только в начале строки (разд. 3.5: «маркер закрытия всегда занимает всю строку»).
4. Списки встроенных команд, ключей заголовка и функций — из разд. 2.3, 10.6, 11.1, 12.10, прил. 2 и стандартной библиотеки v1.1-draft; библиотека версионируется отдельно, поэтому список стандартных функций — в `tools/prml_lexicon.py` (раздел `PY_STDLIB`) и правится там.

## Проверка

| Что | Чем | Результат |
| --- | --- | --- |
| XML Kate | `xmllint --schema language.xsd` (официальная схема KDE) | валидно |
| Токены Kate | `kate-syntax-highlighter` 5.115 (KF5), отладочная сборка с уникальным цветом на атрибут (`tools/kate_dump.py`); 29 проверок на `sample.prml` и 4 граничных файлах | пройдено |
| mcedit | mc 4.8.30, 256-цветный терминал в tmux, снимок цветов (`tools/mc_dump.py`); 8 проверок | пройдено |
| Geany | Geany 2.0, виртуальный X-сервер, снимки экрана (`tools/geany_shot.sh`) | работает в описанных пределах |
| Установка | `install.sh` в изолированном профиле: повторный запуск, удаление | пройдено |

Не проверялись: Kate 6 / KDevelop в графической оболочке (формат XML совместим, но запуск не выполнялся), другие версии mc и Geany. Полный прогон: `XSD=/путь/language.xsd tools/check_all.sh`.

## Сопровождение

Источник списков слов — `tools/prml_lexicon.py`; правила Kate — `tools/gen_kate.py`, mcedit — `tools/gen_mcedit.py`. XML и `*.syntax` — результат генерации, вручную не править. После изменения спецификации: поправить словарь/правила → `tools/check_all.sh` → переустановить.

## Другие редакторы и среды для Linux: предложения

Оценка: точность — насколько механизм выразит лексику Primula (вложенность, многострочные блоки, Unicode); трудоёмкость — относительно готовых определений Kate.

| Редактор / среда | Механизм | Точность | Трудоёмкость | Комментарий |
| --- | --- | --- | --- | --- |
| **Mousepad (XFCE), Pluma (MATE), gedit, GNOME Text Editor, Xed, GNOME Builder** | GtkSourceView `*.lang` (XML, регулярные выражения, вложенные контексты, подключение подсветки Python/YAML) | высокая | низкая | один файл покрывает весь семейство GTK-редакторов — актуально для MATE и XFCE |
| **VS Code / VSCodium** | расширение с грамматикой TextMate (`tmLanguage.json`) + `language-configuration.json` (скобки, комментарий `|%`, сворачивание) | высокая | средняя | та же грамматика импортируется в JetBrains IDE (Plugins → TextMate Bundles) и Sublime Text; позже к расширению можно подключить диагностику `primula check` |
| **Vim / Neovim** | `syntax/primula.vim` + `ftdetect/primula.vim` (регионы, вложенные `syntax include` для Python/YAML) | высокая | средняя | удобно для серверов по SSH |
| **Sublime Text** | `.sublime-syntax` (YAML, контексты, `embed` Python/YAML) | высокая | средняя | то же определение читают `bat` и ряд просмотрщиков |
| **Emacs** | `primula-mode` (`define-derived-mode` + font-lock; комментарий `|%`) | средняя–высокая | средняя | вложенность реализуется через `syntax-propertize` |
| **GNU nano** | `*.nanorc` (регулярные выражения, многострочные `start=`/`end=`) | средняя (без вложенности) | низкая | минимальная подсветка в терминале |
| **Micro** | `primula.yaml` (регионы с вложенностью) | средняя–высокая | низкая | терминальный редактор |
| **Pygments** | лексер на Python (`RegexLexer`) | высокая | средняя | для примеров в документации, Sphinx, Gitea/Forgejo, `pygmentize`; даёт подсветку спецификации и руководства автора |
| **Helix, Zed, Neovim (tree-sitter)** | грамматика tree-sitter | наивысшая (дерево разбора) | высокая | требует отдельной грамматики; даёт структуру документа для навигации и сворачивания; имеет смысл после стабилизации спецификации |

Рекомендуемый порядок: GtkSourceView → TextMate (VS Code, затем JetBrains/Sublime) → Vim → Pygments; остальные — по запросу.

## Словарь и обновление

Команды, ключи заголовка и функции берутся не из ручных списков, а из справочника транслятора: `python3 tools/sync_lexicon.py` переписывает `tools/lexicon.json` по `primula commands --format json`, затем `tools/gen_kate.py kate`, `tools/gen_mcedit.py mcedit`, `tools/gen_geany.py geany`, `tools/gen_textmate.py vscode` перестраивают определения (всё сразу — `tools/check_all.sh`). Тест проекта (`tests/test_editors.py`) падает, если транслятор получил новую команду или функцию, а словарь и сгенерированные файлы не обновлены. Слова грамматики (управляющие конструкции, ключевые слова Python, запрещённые слова) остаются в `prml_lexicon.py`.

Проверки, которые требуют окна или терминала с tmux (`tests/check_kate.py` — `kate-syntax-highlighter` / `kate-syntax-highlighter6`, `tests/check_mcedit.py` — mc в tmux), запускает `tools/check_all.sh` вручную; проект проверяет только словарь, актуальность файлов, XML и регулярные выражения TextMate.

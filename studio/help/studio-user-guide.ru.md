# Primula Studio — краткая справка

Primula Studio — редактор документов на языке разметки Primula (`.prml`) и интерфейс их сборки в ODT и PDF. Сборку выполняет транслятор `primula`: Studio вызывает его как отдельную программу и показывает его сообщения и готовый PDF.

> **Не знаете, что можно сделать в этом месте, — правая кнопка мыши.** Контекстное меню редактора предлагает подсказку (`Ctrl+Shift+Space`), раздел спецификации (`F1`), дополнение (`Ctrl+Space`), а в YAML-заголовке — ключи, которые можно вставить здесь (и на пустой строке), значения ключа строки и недостающие поля метаданных. Те же клавиши работают и без меню.

## Проект и документ

- **Файл → Открыть проект или документ…** (`Ctrl+O`) — файл проекта `project.p.prml` или любой документ `.prml`. Проект документа ищется так же, как его ищет транслятор: вверх от каталога документа до каталога с `.git`.
- Открывается основной документ (у проекта — источник первой цели) либо файлы прошлой сессии; фрагменты, модули и данные открываются по требованию.
- Ошибки в заголовке проекта не мешают его открыть: они показываются в панели «Сообщения», файл проекта можно исправить здесь же.
- **Недавние проекты** — в меню «Файл».

Studio хранит свои данные в служебном каталоге `.primula-studio/` в корне проекта; у проекта заказа (`extends`) — в корне проекта договора, поэтому договор и все его заказы делят один каталог:

| Файл | Что в нём |
|---|---|
| `settings.json` | открытые файлы, позиции курсора и прокрутки, раскладка, PDF, настройки сборки — для каждого открытого проекта или документа |
| `ai-context.md` | постоянный контекст AI для проекта (обычный Markdown) |
| `ai-history/` | запросы к AI и ответы |

## Создание файлов и проектов

- **Файл → Создать** (`Ctrl+N` — документ): документ, фрагмент, модуль определений, модуль стилей, проект, проект заказа. Диалог показывает шаблоны выбранного вида с описанием; задаются имя, заголовок, язык текстов шаблона (по умолчанию — язык проекта) и место; перед созданием перечислены создаваемые файлы, существующие файлы не перезаписываются.
- Шаблоны документов: простой, договор, документ из фрагментов, настанова, деловое письмо; проектов: с одним документом, с пакетной сборкой по CSV, договор и заказы.
- Стили комплекта: документ без стилей проекта называет набор в заголовке — `styles: [std/styles/business]` (договоры, акты), `letter` (письма), `technical` (настановы), `report` (отчёты по ДСТУ 3008), `compact` (памятки). Шаблоны модулей стилей строятся поверх набора (`extends: std/styles/business`) и содержат только отличия; образцы — `examples/08-styles` дерева исходников.
- **Проект заказа** создаётся в `orders/<имя>/` открытого проекта: `extends` на проект договора, свой `order.yaml` (копия `orders/sample.yaml`), заполнители — обычным текстом, цели — документы проекта договора, кроме первой цели.
- Новый проект сразу открывается; новый документ — вкладкой.
- Свои шаблоны — в `~/.config/primula-docs/templates/` (**Файл → Создать → Открыть папку шаблонов пользователя**); формат описан в `studio/templates/README.md` дерева исходников.

Контекстное меню панели «Файлы»: **Создать в этой папке** (документ, фрагмент, модуль, модуль стилей, папку), **Сводка о файле…** (функции и константы модуля, стили модуля стилей, цели проекта — то же, что `primula describe`; есть и в меню вкладки), **Копировать под новым именем…** (файл или папку; у копии папки Studio предлагает заменить старое имя новым в её файлах — так из `orders/cso270101-1` получается следующий заказ), **Открыть во внешней программе** (например, PDF — в системном просмотрщике), **Переименовать…**, **Переместить в корзину** (если корзина раздела недоступна — предложит удалить окончательно), **Открыть папку в файловом менеджере**. Открытые вкладки следуют за переименованием; файл с несохранёнными изменениями переименовать или удалить нельзя.

## Файлы и вкладки

- Панель **«Файлы»** показывает файлы проекта; двойной щелчок открывает файл. **Файл → Открыть файл…** (`Ctrl+Shift+O`) открывает любой текстовый файл, в том числе вне проекта.
- Изображения, ODT и другие нетекстовые файлы открываются внешней программой (ODT — в Writer), PDF — в просмотре PDF.
- **Типы файлов** решают, какие файлы показывает панель «Файлы» и чем они открываются: в редакторе, в просмотре PDF, программой рабочего стола или своей командой. Встроенные типы — файлы проекта Primula, данные, тексты, изображения, PDF, документы и таблицы (ODS, XLSX). **Файл → Типы файлов…** открывает личный файл `~/.config/primula-docs/file-types.json` (при первом вызове он создаётся из шаблона с отключённым примером для PlantUML). Тип: `name`, `patterns` (`["*.puml"]`), `open` (`editor`, `preview`, `system`, `command`), `command` — программа и аргументы (`%f` — файл, `%d` — его каталог, `%r` — путь от корня проекта), `enabled`. Тип с тем же шаблоном заменяет встроенный. После сохранения файла типы применяются сразу; ошибки — во вкладке «Журнал». Файл проекта `.primula-studio/file-types.json` может показывать типы и выбирать редактор или программу рабочего стола, но не команды: чужой проект не должен запускать программы. Пример: `{"types": [{"name": "PlantUML", "patterns": ["*.puml"], "open": "command", "command": ["/home/user/puml_view.sh", "%f"]}]}`. В контекстном меню файла — **Открыть с помощью …** (команда типа, если двойной щелчок открывает иначе) и **Открыть как текст в редакторе**.
- Вкладки закрываются кнопкой, `Ctrl+W` или из контекстного меню вкладки («Закрыть другие вкладки», «Копировать путь»). При закрытии изменённого файла Studio спрашивает: сохранить, не сохранять или отменить.
- На вкладке — короткое имя файла (без `.prml` и подрасширения `.f`, `.m`, `.s`, `.p`, без общего начала имён); полный путь — во всплывающей подсказке. `*` — несохранённые изменения.
- `Ctrl+E` — список всех открытых файлов.
- `Ctrl+\` или `Alt+\` (клавиша обратной косой черты) вставляет управляющий символ `|` в позицию курсора в любой раскладке, без переключения на латиницу; то же — кнопка с чертой на панели инструментов и пункт **Правка → Вставить управляющий символ |**.
- Если файл изменён вне Studio, сверху появляется полоса: **Перезагрузить** или **Оставить редактор** (тогда следующее сохранение перезапишет файл на диске).

## Структура и стили

Панели **«Структура»** и **«Стили»** — вкладки рядом с **«Файлами»** (Вид → панели). Studio получает их от транслятора (`primula check --dump-structure --dump-styles`) с несохранённым текстом открытых файлов — примерно через секунду после остановки ввода, смены вкладки или сборки; сохранять для этого ничего не нужно.

- **Структура**: заголовки, пункты (свёрнуты под заголовками), приложения, таблицы, рисунки, нумерованные списки текущего документа; у элементов фрагментов — имя файла. Элемент под курсором редактора выделяется; двойной щелчок — переход к строке; контекстное меню копирует номер, ID или готовую ссылку `|@("id")`. Параллельные тексты (`|parallel`): строка «Параллельные потоки: uk | en», сегменты и блоки потоков с их состоянием (`status`); элементы неосновного потока помечены его именем («[en] 2 Subject»), устаревший или изменённый после подтверждения перевод выделен цветом.
- **Стили**: слои модулей стилей с происхождением (проект, параметр `--style`, заголовок документа, встроенный, основа `extends`), значения документа по умолчанию и стили по видам с фильтром. Курсив — стили, созданные транслятором (`derive`, варианты); значок предупреждения — сломанный стиль. У выбранного стиля — собственные свойства со слоем, который их задаёт, и унаследованные со стилем-источником. Двойной щелчок по стилю, слою или собственному свойству открывает определение; модули стандартной библиотеки (`std/…`) — только для чтения.
- **Назначение стиля**: **Формат → Применить стиль…** (Ctrl+Shift+Y) — выбор стиля с фильтром; то же — пункт **«Применить X у курсора»** в контекстном меню стиля. Символьный стиль оборачивает выделение: `|.X{…}` (без выделения вставляется `|.X{}`). Абзацный — к строке под курсором `|.X: текст`, к нескольким выделенным строкам `|.X:` … `|end.X`; у строк пунктов и заголовков (`|>`, `|<`) стиль записывается в аргументы: `|>(style="X")`. Блочный — `|block("X"):` … `|end block`. Если у строки уже есть стиль, он заменяется. **Формат → Снять стиль у курсора** (Ctrl+Shift+Alt+Y) или **«Снять X у курсора»** убирает ближайшее к курсору применение. Стили таблиц, списков, рамок и страниц задаются аргументом `style=` их команды. Отмена — Ctrl+Z одним шагом.
- Если в документе ошибки, панели сохраняют прежнее содержимое с пометкой **«Устарело»** и первой ошибкой.

## Вставка конструкций

- **Вставка** — конструкции языка по разделам (текст, структура, таблицы, страницы и графика, техдокументация, модули, код); в подсказке — аргументы со значениями по умолчанию и раздел спецификации. Панель **«Палитра»** (вкладка рядом со «Стилями») — то же с поиском: двойной щелчок по конструкции или Enter в поле поиска вставляет её у курсора.
- Вставляется заготовка; первый аргумент выделен — его можно сразу набрать. Выделенный текст становится телом: выделить слово и выбрать `|*{…}` — получится `|*{слово}`. Окружения (`|block`, `|table`, `|if`, `|appendix`…) оборачивают выделенные строки; строчные формы (`|>`, `|newpage`…) без выделения встают на отдельную строку.
- **Подсказки**: наведите мышь на `|команду`, короткую форму, `|.Стиль` или `|@("id")` — появится описание с аргументами, вид и родитель стиля или текст элемента ссылки; при наборе `|имя(` показывается сигнатура. Подсказка появляется в рамке под конструкцией и закрывается, когда мышь уходит с конструкции, щелчком, клавишей или прокруткой.
- **Дополнение**: после `|` предлагаются команды (выбранная вставляется заготовкой), после `|.` — стили документа, внутри `|@("` — ID элементов. На строке из одного `|end…` первым предлагается закрытие ближайшего открытого окружения (`|end.Figure`, `|end block`, `|end>`, `|endif`…). Список появляется при наборе; Ctrl+Space вызывает его явно; Enter или Tab выбирает, Esc закрывает. Подсказка на закрывающем маркере показывает, какую строку он закрывает.
- **Подсказка сразу**: правый щелчок по конструкции → **«Подсказка: …»** — та же справка без ожидания, в рамке под конструкцией, до щелчка, клавиши или прокрутки; там же — **«Спецификация, раздел …»**. Для конструкции под текстовым курсором — Ctrl+Shift+Space.
- **Tab** после вставки заготовки переходит к следующему аргументу; Esc или щелчок мышью заканчивает переходы.
- **Функции** в коде (блоки `|code:`, код модулей стилей и проекта, аргументы команд, выражения `|(…)`): наведите мышь на функцию — описание, аргументы, пример с результатом и раздел (переменная файла с именем функции, например `count = …`, подсказку этой функции не получает, если это не вызов); при наборе `имя(` — сигнатура; дополнение — с трёх букв имени, после `x.` — методы строк, списков и словарей, после `math.` — функции `std/math`; Ctrl+Space — сразу. F1 на функции открывает её раздел в окне «Стандартная библиотека Primula» (Справка → Стандартная библиотека) или в спецификации. **Вставка → Функция** и разделы «Функции: …» палитры — то же списком; функция, вставленная в текст документа, оборачивается в `|(…)`.
- **F1** (Справка → Справка по месту курсора; в контекстном меню — «Спецификация, раздел N») на конструкции открывает её раздел в окне «Спецификация языка Primula» (на языке интерфейса; нормативен русский оригинал) или «Стандартная библиотека Primula». Конструкция, для которой открыт раздел, отмечается в редакторе жёлтым фоном с пунктирным подчёркиванием, заголовок окна называет её («… — контекст: |table(…)»), а строка над текстом говорит, какой раздел и для какой строки показан. Отметка снимается, когда окно закрыто или спецификация открыта из меню. Вне конструкции F1 открывает эту справку и сообщает об этом в строке состояния. **Справка → Краткая справка** всегда открывает эту справку. Спецификация целиком — Справка → Спецификация языка.
- **Команды библиотек.** Команды, которые подключённые модули задают через `|def` (`|import("lib/смета")` → `|смета.таблица(…)`), появляются в «Палитре», меню «Вставка» и дополнении после проверки документа (по несохранённому тексту тоже): группа «Библиотека: <модуль>», в подсказке — сигнатура, описание (строки `|%` над `|def`) и место определения. Они же попадают в справочник для AI. Видны команды модулей, подключённых в самом документе (не во включаемых фрагментах).
- Контекстное меню палитры: вставить у курсора, копировать форму или заготовку, открыть раздел спецификации (для команды библиотеки — открыть её определение).
- **Вставка → Изображение…** вставляет `|img("путь")` с путём относительно файла; изображение вне проекта можно скопировать в `assets/` (существующие файлы не перезаписываются).
- Ссылка на пункт или заголовок — контекстное меню панели **«Структура»** → «Вставить ссылку … у курсора».
- **YAML-заголовок** (между `---` в начале файла): наведите мышь на ключ — описание, тип, значения, пример и раздел; F1 — раздел спецификации (на пустой строке — раздел блока, в котором она стоит, или заголовка файла). Метаданные документа — `doc:` (в тексте — `|(doc.title)`), значения по умолчанию для всех документов проекта — `doc_defaults:` в файле проекта, документы, на которые ссылаются другие, — `ref_documents:` проекта (решение 129). На `doc:` и `doc_defaults:` подсказка называет незаполненные рекомендуемые поля. Дополнение (`Ctrl+Space`, также на пустой строке) предлагает ключи текущего уровня (кроме уже заданных; в том числе внутри `targets`, `limits` и `{…}`) и значения: допустимые (`kind`, `on_conflict`), языки, сегодняшнюю дату, файлы проекта для `styles`, `extends`, `source`.
- **Контекстное меню заголовка**: **Вставить ключ в X:** и **Вставить ключ верхнего уровня** — ключи с описанием, рекомендуемые отмечены ★, уже заданные недоступны (ключ вставляется на пустую строку, на которой открыто меню, иначе первым в своём блоке); **Значение ключа** — допустимые значения ключа строки; **Добавить недостающие поля метаданных**; **Все ключи заголовка** — раздел спецификации.
- **Вставка → Заголовок: добавить недостающие поля** (и то же в контекстном меню) — в документе добавляет в `doc:` поля `title`, `creator`, `language`, `created`, в файле проекта — `creator` и `organization` в `doc_defaults:` (значения по умолчанию для всех документов проекта, документ может их заменить); Tab — к следующему значению. Окно сообщения говорит, что и куда добавлено, или почему добавлять нечего.

## Проверка и сборка

| Команда | Клавиши | Что делает |
|---|---|---|
| Проверить документ | `Ctrl+Shift+Enter` | `primula check` текущего документа, без записи файлов |
| Собрать документ (ODT и PDF) | `F9` | ODT и PDF текущего документа: цель проекта — в свой выходной файл, другой документ — в `build/` корня проекта |
| Собрать все цели проекта | `Shift+F9` | `primula build project.p.prml --pdf` |

- Фрагмент, модуль или модуль стилей проверяется и собирается в составе документа, показанного в PDF.
- Перед проверкой и сборкой все файлы сохраняются.
- **Строго: предупреждения — ошибки** — параметр `--strict`.
- **Сборка → Параметры документа: ИМЯ…** — параметры проекта и документа ИМЯ (`params:`; когда открыт файл проекта — основного документа) с типом и значением по умолчанию. Значение задаётся в последнем столбце одним щелчком (для `true`/`false` и дат — список), пишется как в `--param` (текст, `true`/`false`, число, дата), запоминается для документа в `.primula-studio/settings.json` и действует при проверке, сборке документа, в панелях и в консоли; файлы не меняются; пустое — значение по умолчанию. Сборка всех целей проекта использует параметры целей. Пояснение — в самом окне.
- Сообщения транслятора — в панели **«Сообщения»**: двойной щелчок открывает файл на строке и столбце (в том числе во фрагменте). Строки с сообщениями подчёркнуты в редакторе. Вывод транслятора — во вкладке **«Журнал»**.
- **Сборка → Экспорт** (и пункт «Экспорт» в контекстном меню документа на панели «Файлы» и на вкладке) — `primula export` через pandoc: **Markdown**, **HTML (один файл)**, **DOCX (Word)**, **Другой формат…** (`gfm`, `latex`, `epub`, `rst`, `json` — AST pandoc, без pandoc — и другие), **Экспортировать как…** (выбор файла). Файл ложится рядом с ODT документа (`build/документ.md`; ODT через pandoc — `документ.pandoc.odt`, чтобы не заменить ODT сборки); учитываются параметры документа и «Строго». Сохраняются номера пунктов, ссылки, сноски, таблицы и подписи; разметка страниц — нет (предупреждение в «Сообщениях»). После экспорта — окно с кнопками **Открыть файл** и **Открыть каталог**; если pandoc не установлен — окно с объяснением, как его поставить.

## Параллельные потоки

Для документов с `|parallel` (двуязычный договор, протокол разногласий; руководство автора, страница «Параллельные тексты») — подменю **Сборка → Параллельные потоки** и то же подменю в контекстном меню редактора, если в документе есть `|parallel`. Команды запускают `primula parallel`; документ перед этим сохраняется, переписанный транслятором файл перечитывается в редакторе, отчёт команды — во вкладке **«Журнал»**, сообщения — в **«Сообщениях»**.

- **Подтвердить перевод сегмента X, поток Y…** — для блока перевода под курсором: записывает в него `rev` (хеши основного блока и перевода) и, если выбрано, состояние (`reviewed`, `translated`, `draft` или своё). Курсор в блоке основного потока или вне сегмента — пункт недоступен и говорит, куда поставить курсор.
- **Подтвердить все блоки потока…** — то же для всех сегментов потока.
- **Дописать заготовки блоков потока…** — в сегменты без блока потока дописывается копия структуры основного блока с заполнителями `|?{…}`.
- **Проверить состояние переводов…** — все ли блоки неосновных потоков в заданном состоянии и без устаревших `rev`; несоответствия — в «Сообщениях».
- Если основной текст изменён после подтверждения, проверка документа выдаёт P5320 «перевод устарел», а изменённый подтверждённый перевод — P5321; в панели «Структура» такие блоки выделены.

## PDF

- **Вид → Раскладка**: исходник и PDF рядом или PDF отдельной вкладкой; кнопка на панели инструментов переключает раскладку.
- `F4` — переключение между исходником и PDF. PDF открывается на странице заголовка, перед которым стоит курсор (по закладкам PDF; после первой сборки документа).
- **Сборка → Показывать PDF после успешной сборки**: если PDF был виден (по умолчанию), всегда или никогда.
- `Ctrl+колесо` над PDF меняет масштаб вокруг точки под курсором; без `Ctrl` колесо прокручивает. Положение и масштаб сохраняются в сессии.

## AI

- **AI → Спросить AI о документе…** (`Ctrl+Alt+Enter`): задача, выделенный текст или весь файл; по желанию — файл проекта, сообщения последней проверки или сборки, модули стилей проекта и другие открытые файлы. AI получает текст только для чтения и не меняет файлы.
- **Язык Primula** — что AI узнаёт о языке: *Справочник* (по умолчанию) — каталог транслятора, каждая конструкция и функция с описанием и разделом (около 18 тыс. знаков); *Вся спецификация и библиотека* (около 100 тыс. токенов: медленнее и дороже); *Ничего*. **Разделы полностью** — разделы спецификации, отправляемые как есть (`6.8, 10.5`; стандартная библиотека — `stdlib:3`); предлагается раздел конструкции под курсором. Выбор запоминается для проекта.
- **Рецепт** (в окне запроса) — готовая задача: вычитка, проверка терминов договора, единые апострофы и кавычки, перевод выделенного на украинский, английский или русский, дописывание потока перевода в `|parallel`, объяснение фрагмента. Текст рецепта попадает в поле задачи и остаётся редактируемым; рецепт сам включает «правки» и нужный охват. Свои рецепты — файл `~/.config/primula-docs/ai-recipes.json` (того же вида, что встроенный `studio/resources/ai-recipes.json`; тот же `id` заменяет).
- **Правила записи Primula** (галочка, по умолчанию включена) — три раздела из skill `primula-docs` (правила записи, что нельзя менять при вычитке, частые ошибки; около 6 тыс. знаков) добавляются к запросу. Четвёртый вариант «Языка Primula» — **Локальный skill primula-docs**: справочник не отправляется, агент сам загружает установленный у него skill (установка — `skills/README.md`); он должен написать в первой строке «Skill: loaded», иначе skill ему недоступен. Для Claude при этом включается инструмент `Skill`. Вариант нужен для сравнения: справочник и skill можно сопоставить по ответам и размеру запроса (вкладка «Полный запрос»).
- **Рецепт** (в окне запроса) — готовая задача: вычитка, проверка терминов договора, единые апострофы и кавычки, перевод выделенного на украинский, английский или русский, дописывание потока перевода в `|parallel`, объяснение фрагмента. Текст рецепта попадает в поле задачи и остаётся редактируемым; рецепт сам включает «правки» и нужный охват. Свои рецепты — файл `~/.config/primula-docs/ai-recipes.json` (того же вида, что встроенный `studio/resources/ai-recipes.json`; тот же `id` заменяет).
- **Правила записи Primula** (галочка, по умолчанию включена) — три раздела из skill `primula-docs` (правила записи, что нельзя менять при вычитке, частые ошибки; около 6 тыс. знаков) добавляются к запросу. Четвёртый вариант «Языка Primula» — **Локальный skill primula-docs**: справочник не отправляется, агент сам загружает установленный у него skill (установка — `skills/README.md`); он должен написать в первой строке «Skill: loaded», иначе skill ему недоступен. Для Claude при этом включается инструмент `Skill`. Вариант нужен для сравнения: справочник и skill можно сопоставить по ответам и размеру запроса (вкладка «Полный запрос»).
- В окне запроса показан контекст AI проекта (сколько знаков в нём или что он пуст) и кнопка **«Редактировать контекст AI…»**: окно правки того же `ai-context.md` без выхода из запроса. Кнопка нужна, чтобы про контекст не забывали: он добавляется к каждому запросу.
- **AI → Редактировать контекст AI проекта** открывает `ai-context.md`: что AI должно знать о документах (назначение, стороны, термины, стиль). Контекст добавляется к каждому запросу.
- **Просить правки, которые можно проверить и применить** (в окне запроса): AI отвечает блоками «было → стало» (`<<<<<<< ORIGINAL` … `=======` … `>>>>>>> REPLACEMENT`), а у ответа появляется вкладка **«Правки»**. Studio находит каждый фрагмент «было» в документе (допускаются пробелы в конце строк и неразрывные пробелы), показывает состояние правки (готова, не найдена, встречается несколько раз, перекрывается) и по кнопке **«Проверить отмеченные правки»** запускает проверку транслятором (`primula check --overlay`) для каждой правки отдельно и для всех вместе: правка, которая вносит новые ошибки, помечается и не отмечается по умолчанию. **«Применить отмеченные правки»** вносит правки в редактор одним шагом — **Правка → Отменить** возвращает всё; файл не сохраняется. Контекстное меню списка: применить или проверить одну правку, скопировать текст, отметить все. Если правки вносят новые ошибки, перед применением Studio спрашивает подтверждение.
- Ответы сохраняются в `ai-history/` и открываются вкладкой «AI».
- Инструмент — Codex CLI (`codex`), Claude CLI (`claude`) или Grok CLI (`grok`). **Запрос можно отправить сразу нескольким инструментам**: в окне запроса отметьте нужные (запоминается), а пути к программам задаются в **Файл → Настройки**. Инструменты работают параллельно, окно ждёт ответов всех; каждый ответ — отдельная вкладка «AI» с пометкой инструмента, и правки можно применять из любого (даже частями из разных; если одно и то же место уже изменено, у второй правки состояние «не найдена» — решает пользователь). Перед отправкой нескольким сервисам Studio спрашивает подтверждение: текст документа и контекст уходят каждому. Все запускаются только для чтения: Codex в `--sandbox read-only`, Claude и Grok — только с инструментами чтения, без права менять файлы и запускать команды. Инструменты описаны данными (`agents.json`); свой инструмент добавляется файлом `~/.config/primula-docs/agents.json` того же вида (имя, программа, аргументы, как передаётся запрос и как читается ответ; тот же `id` заменяет встроенный). Проверить, что инструмент действительно не меняет файлы: `python3 studio/tools/check_ai_agent.py grok`.
- **Сравнение ответов нескольких инструментов.** В «Правках» каждого ответа у каждой правки стоит метка: «одинаково у всех», «различается: совпадают N из M» или «это изменили только N из M инструментов» (правки разных ответов сопоставляются по одному и тому же исходному фрагменту, пробелы не в счёт). Под списком — сводка («совпадают 31 из 35, различаются 4…»), флажок **«Только где инструменты различаются»**, кнопка **«Выбрать совпавшие правки»** (выбирает то, что все предложили одинаково) и пункт контекстного меню **«Сравнить с другими инструментами…»**: окно с текстом документа и вариантами всех инструментов, различия по словам. Лучшим ответ не объявляется: решение за вами. **AI → Сравнить ответы последнего запроса…** показывает целиком ответы без блоков правок (базовый ответ выбирается, остальные — различиями против него).
- **Создать проект с помощью AI** (Файл → «Создать проект с помощью AI…»). Опишите проект: документы, язык, данные, цели сборки. Файлы можно получить **в ответе инструмента** (по умолчанию: инструмент работает только на чтение и присылает текст файлов блоками `<<<<<<< FILE путь … >>>>>>> END FILE`, а файлы во временном каталоге делает Studio — работает с любым инструментом, права записи не нужны) или чтобы **инструмент записывал сам** (нужны `writeArguments` и работающая песочница инструмента; у Codex в Linux песочница `bubblewrap` может не запускаться, если AppArmor запрещает пользовательские пространства имён). В обоих случаях работа идёт во временном каталоге, в ваши файлы ничего не попадает. После ответа Studio показывает список файлов с просмотром, проверяет проект транслятором (каждый документ целей) и, если есть ошибки, предлагает **«Попросить инструмент исправить ошибки»** (те же файлы, новый запрос с текстом ошибок). Выберите нужные файлы — **«Создать проект»** запишет их в новую папку (замену существующих файлов подтверждаете вы) и откроет проект. Скрытые файлы, ссылки, двоичные и очень большие файлы, а также больше 200 файлов не берутся. Проверить, что инструмент правда не пишет за пределами каталога: `studio/tools/check_ai_agent.py ID --write`.
- **Изменить проект с помощью AI** (AI → «Изменить проект с помощью AI…», нужен открытый проект). Опишите изменение (добавить приложение, вынести условия во фрагмент, переименовать параметр…) и **отметьте файлы, которые уходят инструменту**: в сервис отправляются тексты отмеченных файлов (по умолчанию файл проекта и документы Primula в пределах 600 КБ) и список всех файлов проекта. Инструмент работает только на чтение и отвечает новым текстом файлов, которые меняет или добавляет, и блоками удаления. Изменения кладутся в **копию проекта** во временном каталоге и проверяются транслятором там; в окне — список файлов (новый / изменён / удалён) с `diff` и число ошибок до и после, а при ошибках — «Попросить инструмент исправить ошибки». «Применить отмеченные изменения»: сначала резервная копия (`before-ai-apply`), открытые файлы изменяются в редакторе (шаг Undo, **не сохраняются**), остальные записываются, удалённые уходят в корзину. Пути через ссылки проекта (`lib` → библиотека), скрытые и небезопасные отклоняются.
- **Импортировать документ** (Файл → «Импортировать документ…»; в панели «Файлы» — контекстное меню файла «Импортировать в Primula…» и «Создать в этой папке → Импортировать документ…»). Документ DOCX, ODT, старый DOC, RTF, Markdown, HTML или EPUB превращается в черновик Primula командой `primula import`: текст, заголовки (набранные номера «1.», «2.1.» становятся нумерацией Primula, заголовки-списки Word и жирные строки — заголовками, набранное содержание — `|toc()`), списки, таблицы с объединениями, изображения (рядом в `assets/`), сноски, ссылки. В окне: путь результата (по умолчанию рядом с источником; существующий файл заменяется — об этом сказано), язык документа, «Распознавать структуру», «Оставить набранные номера», файл соответствия стилей (`import-styles.yaml` рядом с результатом или выше) и кнопка «Стили источника…» (стили DOCX и во что они переходят). После импорта — сводка: что преобразовано, что пропущено, какие стили не сопоставлены и результат проверки; «Открыть результат» открывает документ. Нужен pandoc (для старого `.doc` и LibreOffice); без pandoc импорт недоступен (в сборке для Windows pandoc нет).

## Консоль вычислителя

**Вид → Консоль** (`Ctrl+Alt+C`) — отдельное немодальное окно над главным (положение, размер и шрифт запоминаются), вроде терминала, для проверки и изучения функций библиотеки и собственных функций.

- **Контекст**: *текущий файл* — документ (параметры заголовка с значениями из «Сборка → Параметры документа…», `doc`, проект, стили, определения кода; текст не вычисляется), фрагмент, модуль, модуль стилей или файл проекта; *проект*; *только библиотека*. Смена контекста и **«Перезапустить»** начинают новый сеанс.
- Ввод — код Primula: `x = …`, `def`, выражения; значение последнего выражения показывается, `debug(…)` печатает, ошибки — с местом. Имена вводов сохраняются до перезапуска; имя можно определить заново (только в консоли). `math` (`std/math`) в консоли доступен всегда; в документе пишите `|import("std/math")`.
- **Enter** выполняет ввод; **Shift+Enter** переносит строку; блок (`def …:`, `for …:`) и незакрытая скобка продолжаются, блок заканчивается пустой строкой. **Ctrl+↑/↓** — история вводов (хранится в `.primula-studio/`). Подсказки и дополнение функций — как в редакторе.
- **«Прервать»** (или Ctrl+C в строке ввода без выделения) останавливает долгое вычисление; имена остаются. **«Очистить»** очищает журнал.
- Справа две вкладки. **Функции** — список функций с поиском и описанием; двойной щелчок вставляет пример в строку ввода; контекстное меню: вставить пример, вставить имя, `:help`, открыть раздел библиотеки или спецификации, копировать имя. **Имена** — имена, видимые следующему вводу: сначала имена вводов (жирным), затем контекста, с типом и значением (ещё не вычисленные имена контекста не вычисляются ради списка); поиск; двойной щелчок вставляет имя, контекстное меню — вставить, показать значение, копировать. Команды консоли: `:help ИМЯ`, `:functions ТЕКСТ`, `:vars` (имена консоли и контекста), `:reset` (забыть имена консоли), `:context`.
- **Шрифт окна**: `Ctrl+колесо` над журналом или вводом, `Ctrl++`, `Ctrl+-`, `Ctrl+0`.

## Редактор

| Клавиши | Действие |
|---|---|
| `Ctrl+S` / `Ctrl+Shift+S` | сохранить файл / все файлы |
| `Ctrl+F`, `F3`, `Shift+F3` | поиск, следующее, предыдущее |
| `Ctrl+H` | замена |
| `Ctrl+колесо`, `Ctrl++`, `Ctrl+-`, `Ctrl+0` | размер шрифта редактора |

Файлы `.prml` подсвечиваются по синтаксису Primula: заголовок YAML, команды, короткие формы, стили, ссылки, выражения, код в `|code:`; ошибочные формы (`|` перед пробелом или цифрой, зарезервированные `|$ |[ |]`) подчёркнуты красной волной. В модулях стилей и файлах проекта текст после заголовка подсвечивается как код.

## Резервные копии

Большой документ легко повредить, а Undo живёт только пока открыт файл. Поэтому Studio хранит копии файлов проекта в `.primula-studio/backups/` (каталог на каждую копию: файлы по своим путям и `backup.json` — причина, примечание, время, контрольные суммы; если проект лежит в Git, добавьте `.primula-studio/` в `.gitignore`).

- Копия делается автоматически **перед применением правок AI** (из текста в редакторе, в том числе несохранённого), **перед восстановлением** версии и, если включено в **Файл → Резервные копии → Копировать файл перед сохранением**, перед каждым сохранением (версия на диске; одинаковые версии не дублируются).
- На панели инструментов — две кнопки: **сделать копию проекта сейчас** (`Ctrl+Alt+B`) и **показать копии** (`Ctrl+Alt+Shift+B`); рядом с ними кнопка консоли вычислителя (`Ctrl+Alt+C`), а запрос к AI обозначен значком-искрой.
- **Файл → Резервные копии → Сделать копию проекта сейчас** копирует исходные файлы проекта (`.prml`, YAML, Markdown, текст, CSV, JSON до 5 МБ; без `build/`, `out/`, `.git/` и служебного каталога).
- **Файл → Резервные копии → Показать копии…**: список копий (новые сверху), в нём — файлы копии. **Сравнить с текущим файлом** показывает разницу (`diff -u`: «-» — копия, «+» — текущий файл), **Восстановить эту версию** возвращает файл (перед этим делается копия текущего состояния; в открытый файл версия вносится правкой, которую отменяет Undo, и не сохраняется сама), **Удалить копию**, **Открыть папку**; те же команды — в контекстном меню списка.
- Хранятся последние 100 автоматических копий (настройка `backups/keep`); копии «Вручную» не удаляются сами.

## Настройки

**Файл → Настройки**: путь к транслятору `primula` (пусто — из `PATH` или запускатель дерева исходников рядом со сборкой Studio) инструмент AI (Codex CLI, Claude CLI, Grok CLI или свой из `agents.json`) и путь к его программе. **Вид → Язык интерфейса**: английский, украинский, русский (после перезапуска).

**Справка → Шпаргалка команд (PDF)** открывает четырёхстраничную сводку команд Primula (четвёртая страница — отличия кода Primula от Python) на языке интерфейса в системном просмотрщике PDF (черновик — до расширенной справки). **Справка → Руководство автора (PDF)** открывает руководство автора одним документом — все страницы, приложения (конструкции, функции, ключи заголовка, сообщения, стили) и глоссарий — на языке интерфейса; удобно читать и искать. Файл входит в пакет установки (`guide/<язык>/`); если его нет, Studio называет, где искала.

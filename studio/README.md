# Primula Studio

Настольный редактор и интерфейс сборки документов Primula (Qt 6, C++20). Основа — ODT Markdown Studio 0.4.3 из комплекта `odt-markdown-kit-v0.4-studio-v0.4.3/` (импортирована как есть коммитом 32459d2; исходный комплект не изменяется). План адаптации — разделы 2 и 4 `../issues&answers/primula-spec-issues-13.12-13.14.md` (подэтап 13.14).

Версия Studio совпадает с версией транслятора: CMake читает её из `../pyproject.toml` (`primula-studio --version`).

## Как устроена

Studio не знает семантики языка: она редактирует файлы, вызывает транслятор `primula` как процесс и показывает его сообщения (JSON) и PDF.

- **Открытие.** «Открыть проект или документ…» (Ctrl+O): `project.p.prml` или любой `.prml`. Проект документа ищется так же, как его ищет транслятор (вверх от документа, до каталога с `.git`); описание проекта (корень, имя, цели, стили) — из `primula check project.p.prml --dump-project`. Ошибки заголовка проекта не мешают открыть его: они показываются в «Сообщениях».
- **Служебный каталог** `.primula-studio/` в корне проекта; для проекта с `extends` — в корне базового, поэтому договор и все его заказы делят один каталог:
  - `settings.json` — сессии (для каждого открытого файла проекта: открытые файлы, позиции курсора и прокрутки, активная вкладка, раскладка, PDF), настройки сборки (`strict`, показ PDF после сборки);
  - `ai-context.md` — контекст AI проекта (AI → «Редактировать контекст AI проекта»), обычный Markdown;
  - `ai-history/` — запросы и ответы AI.
- **Рабочее место** (замечания З1–З5): открывается только основной документ (или файлы прошлой сессии); остальные — из панели «Файлы» или «Открыть файл…» (Ctrl+Shift+O, в том числе вне проекта). Вкладки закрываемые (Ctrl+W, «Закрыть другие вкладки»), с короткими именами (без `.prml` и подрасширения, без общего префикса; одинаковые имена — с каталогом), полный путь — в подсказке; список открытых файлов — Ctrl+E. Закрытие изменённого файла спрашивает «Сохранить / Не сохранять / Отмена».
- **Проверка и сборка.** «Проверить документ» (Ctrl+Shift+Enter) — `primula check`; «Собрать документ» (F9) — `primula build … -o … --pdf …`: цель проекта — в свой выход, другой документ — в `build/<имя>.odt|.pdf` корня; «Собрать все цели проекта» (Shift+F9) — `primula build project.p.prml --pdf`. Фрагмент, модуль и модуль стилей проверяются в составе документа, показанного в PDF. Сообщения — в панели «Сообщения» (двойной щелчок — переход к файлу, строке и столбцу, в том числе во фрагменты), строки с сообщениями подчёркнуты в редакторе; вывод транслятора — во вкладке «Журнал». Флажок «Строго» — `--strict`.
- **Нетекстовые файлы** (изображения, ODT, файлы с нулевыми байтами) открываются внешней программой, PDF — в просмотре PDF.
- **PDF.** Раскладка «исходник и PDF рядом» или «PDF отдельной вкладкой» (кнопка на панели инструментов). `Ctrl+колесо` масштабирует вокруг точки под курсором. F4 переключает исходник и PDF; PDF открывается на странице заголовка, перед которым стоит курсор (по закладкам PDF и выгрузке структуры). «Показывать PDF после успешной сборки»: если PDF был виден (по умолчанию) / всегда / никогда.
- **Структура и стили** (14.6): панели «Структура» и «Стили» — вкладками рядом с «Файлами» (Вид → панели). Данные — `primula check документ --dump-structure --dump-styles` с несохранёнными буферами через `--overlay`, через 0,7 с после остановки ввода, смены вкладки и сборки. «Структура»: заголовки, пункты (вложены в заголовки, свёрнуты), приложения, таблицы, рисунки, нумерованные списки; у элементов фрагментов — имя файла; курсор редактора выделяет свой элемент; двойной щелчок — переход к строке. «Стили»: слои, значения документа по умолчанию, стили по видам с фильтром (родитель; курсив — созданные транслятором, значок — сломанные); у выбранного — собственные свойства (со слоем) и унаследованные (со стилем-источником); двойной щелчок по стилю, слою или свойству открывает определение (модули `std/` — только для чтения). При ошибке документа панели сохраняют прежнее содержимое с пометкой «Устарело» и первой ошибкой.
- **Назначение стилей** (14.7): «Формат → Применить стиль…» (Ctrl+Shift+Y, выбор с фильтром), «Формат → Снять стиль у курсора» (Ctrl+Shift+Alt+Y), в меню стиля панели «Стили» — «Применить X у курсора» и «Снять X у курсора». Символьный стиль оборачивает выделение в `|.X{…}` (без выделения — `|.X{}` с курсором внутри); абзацный — строка `|.X: текст`, несколько строк — `|.X:` … `|end.X`, а у строк пунктов и заголовков (`|>`, `|<`) записывается или заменяется `style="X"` в аргументах; блочный — `|block("X"):` … `|end block`. Повторное применение к строке с `|.Y:`/`|block("Y")` меняет имя, а не вкладывает. «Снять» убирает ближайшее применение вокруг курсора: `|.X{…}`, `|.X:` в начале строки, `style=` пункта или заголовка, строки окружения. Стили таблиц, списков, рамок и страниц задаются аргументом `style=` своей команды — пункт неактивен. Studio не разбирает Primula: правка текстовая (баланс скобок, строки окружений), вычисляемые `|.(выражение)` не распознаются; результат проверяет транслятор при следующей инспекции. Каждая правка — один шаг отмены.
- **Вставка конструкций** (14.8): меню «Вставка» — подменю по разделам языка (текст, структура, таблицы, страницы и графика, техдокументация, модули, код) с кратким описанием, аргументами и разделом спецификации в подсказке; панель «Палитра» (вкладка рядом со «Стилями») — те же конструкции с поиском по форме и описанию, двойной щелчок или Enter в поле поиска вставляет. Источник — `primula commands --format json --lang <язык интерфейса>`, загружается один раз при первом открытии меню или палитры. Вставляется заготовка: первый аргумент выделен, выделенный текст становится телом (`|*{…}`, `|link(…){…}`), строки вокруг выделения — содержимым окружения (`|block`, `|table`, `|if`…); строчные формы без выделения встают на свою строку. «Вставка → Изображение…»: файл вне проекта копируется (по вопросу) в `assets/` без перезаписи, вставляется `|img("путь")` относительно файла. В меню панели «Структура» — «Вставить ссылку `|@("id")` у курсора». Переход по заполнителям Tab, подсказки и дополнение — 14.8а.
- **Подсказки и дополнение** (14.8а, без LSP — по данным транслятора): при наведении на `|команду`, короткую форму, `|.Стиль` или `|@("id")` — подсказка (аргументы с типами и значениями по умолчанию, раздел спецификации; вид и родитель стиля; текст элемента ссылки); при наборе `|имя(` — сигнатура. Дополнение: после `|` — команды (вставляются заготовкой), после `|.` — абзацные и символьные стили документа, внутри `|@("` — ID элементов; появляется при наборе, Ctrl+Space — по запросу. Tab переходит к следующему аргументу вставленной заготовки (Esc или щелчок — конец). В контекстном меню редактора — «Подсказка: …» (та же справка сразу, до щелчка; Ctrl+Shift+Space — для конструкции под курсором) и «Спецификация, раздел …». F1 (Справка → Справка по месту курсора) на конструкции открывает её раздел спецификации (окно «Спецификация языка Primula», текст на русском; также Справка → Спецификация языка): конструкция отмечается в редакторе, заголовок и строка окна называют её; отметка снимается при закрытии окна. Вне конструкции F1 открывает справку Studio с сообщением в строке состояния; «Справка → Краткая справка» всегда открывает справку Studio. Контекстное меню палитры: вставить, копировать форму или заготовку, раздел спецификации.
- **Параллельные потоки** (16.6): «Сборка → Параллельные потоки» и контекстное меню редактора — `primula parallel` (подтверждение перевода сегмента под курсором или всего потока, заготовки, проверка состояния); после команды переписанный файл перечитывается; «Структура» показывает потоки, сегменты и блоки потоков с состоянием и отмечает устаревшие переводы.
- **Транслятор**: настройка «Файл → Настройки» (`tools/primula`); пусто — `primula` из `PATH`, иначе запускатель `../../primula` рядом со сборкой в дереве исходников.

## Сборка и тесты

Нужны Qt 6.4+ (Core, Gui, Widgets, Pdf, PdfWidgets, LinguistTools; для тестов — Test), CMake 3.20+, Ninja, компилятор C++20.

```
./build-studio.sh                       # build/primula-studio; каталог сборки — PRIMULA_STUDIO_BUILD_DIR
./build-and-run-studio.sh               # собрать и запустить

cmake -S . -B build -G Ninja -DPRIMULA_STUDIO_BUILD_TESTS=ON
cmake --build build
QT_QPA_PLATFORM=offscreen build/studio-tests   # Qt-тесты (31); сборка с PDF — при наличии soffice
python3 test_studio.py                          # статические проверки (исходники в CMake, переводы, ресурсы)
```

Тесты запускают транслятор этого репозитория (`../primula`, параметр CMake `PRIMULA_STUDIO_TEST_TRANSLATOR`) на временном проекте; тест сборки с PDF требует LibreOffice (`soffice`), иначе пропускается.

Замечание о среде: `QSaveFile` (сохранение файлов и настроек) создаёт безымянный файл `O_TMPFILE` и даёт ему имя через `linkat` по `/proc/self/fd`. Если процесс ограничен профилем AppArmor без флага `mediate_deleted` и права `l` на каталог, это связывание запрещено (`Failed name lookup - deleted entry` в `audit.log`), и Studio не может сохранять файлы — так было с агентом, запущенным под профилем `claude-cli` (26.10.2026). На обычном рабочем столе ограничения нет.

# Устройство прототипа Primula

Документ разработчика. Описывает модули, границы между ними и решения, которые приняты при реализации и не следуют прямо из спецификации. Обновляется на каждом подэтапе этапа 13.

## Конвейер (§3.8)

```
файл ──► source ──► header ──► parse ──► definitions ──► evaluate ──► structure ──► pages ──► odf
        (13.0)     (13.0)     (13.1)      (13.3)        (13.2–13.4,      (13.6)     (13.8)    (13.5)
                                                         таблицы 13.7)
```

`frontend.analyze()` выполняет реализованные фазы и записывает состояние каждой в `FrontendResult.phases`: `done`, `failed`, `not-implemented` или `skipped`. CLI и отчёт JSON по этим состояниям честно сообщают, что проверено. Новые подэтапы добавляют фазы в `analyze()`, не меняя CLI.

## Модель текста и позиций (`source.py`)

- Все фазы работают с **нормализованным** текстом: UTF-8 декодирован, BOM снят, CR LF и одиночный CR заменены на LF, применена NFC. Адрес в тексте — смещение в символах (`int`, с 0).
- `Span(source, start, end)` — полуинтервал смещений. Все узлы дерева (13.1) и все диагностики хранят `Span`.
- Пользователю позиция показывается как `Position(line, column)`: строка и столбец с 1, столбец — номер кодовой точки **исходной** строки до NFC (решение 26). Номера строк нормализация не меняет. Для редких строк, изменённых NFC, хранится таблица столбцов (`_nfc_column_map`).
- Перевод строки — только LF. `str.splitlines()` не используется: он режет и по U+2028, U+0085, FF.
- `utf8_column_to_chars()` переводит байтовые `col_offset` модуля `ast` в символы. Это понадобится в 13.1 для аргументов `(…)`, которые разбираются `ast.parse`: кириллица в UTF-8 занимает два байта.
- `SourceManager` загружает файл один раз (кэш по разрешённому пути) и хранит список файлов для отчёта с SHA-256 исходных байтов.

## Диагностика (`diagnostics.py`, `i18n.py`, `messages/`)

- `Diagnostic` хранит код, серьёзность, `Span` (или имя файла без позиции), **аргументы** шаблона, примечания (`note` с позицией, `help` без неё) и стек вызовов. Текст сообщения собирается при выводе на выбранном языке.
- Аргумент, который сам является ключом каталога (название типа), передаётся как `i18n.Key("type.mapping")` и тоже переводится.
- `DiagnosticSink` применяет `--strict` (серьёзность меняется, код остаётся, ставится `escalated`), считает ошибки, ограничивает их число (по умолчанию 100; при превышении — `TooManyErrors`). `ordered()` сортирует для вывода: сначала сообщения без позиции, затем по файлам и смещению.
- `PrimulaError` — исключение для фатальной ошибки фазы; граница фазы перехватывает его и передаёт диагностику в sink.
- Ключи шаблонов `key`, `file`, `code`, `span` допустимы: параметры `Catalog.text()` и фабрик `error()`/`warning()` позиционные, имя файла без позиции передаётся как `at_file=`.
- Каталоги — модули Python со словарём `MESSAGES`, без gettext: без компиляции `.mo`, проверяются тестами (полнота uk/ru, совпадение плейсхолдеров, соответствие реестру `diagnostics.md`).

## YAML (`yamlio.py`, решение 25)

- Из PyYAML используются только сканер, парсер и композитор, то есть граф узлов. Разрешение тегов — свои регулярные выражения схемы YAML 1.2 core плюс правило дат. Преобразование узлов в значения — своё. Конструкторы PyYAML не вызываются, поэтому из YAML нельзя создать произвольный объект Python.
- Типы: `true`/`false` — bool; целые (десятичные, `0o`, `0x`) — `int`; дробь без экспоненты — `Decimal` с цифрами как в записи; экспонента, `.inf`, `.nan` — `float`; `YYYY-MM-DD` и `YYYY-MM-DDTHH:MM[:SS]` без кавычек — `DateTime` (с 13.8a), несуществующая дата — ошибка, значение с поясом — ошибка `zone` (P1119); в кавычках — всегда строка.
- Ошибки сверх PyYAML: повторный ключ (PyYAML молча берёт последний), рекурсивный псевдоним, составной ключ, неизвестный тег.
- Предупреждения: `yes`/`no`/`on`/`off` (в YAML 1.1 — bool, в 1.2 — строка) и целые с ведущими нулями (`01234567` → 1234567). Оба — типичные ошибки при переходе с Kit; спецификация их не требует, это дополнение прототипа.
- Позиции — `Mark.index` PyYAML (символы потока `str`) плюс смещение YAML-текста в файле.
- Типы `record` (доступ через точку) и неизменяемость появятся в ядре (13.2); `yamlio` возвращает обычные `dict`/`list`.

## Заголовок (`header.py`)

- Заголовок есть, только если первая строка файла — ровно `---`. Закрывает его следующая строка, равная `---`. Конец текста считается концом строки.
- `Header.body_start` — смещение начала тела и `Header.kind` (ключ `kind`, иначе подрасширение имени файла, решение 100). Вид нужен парсеру: выбор между разметкой и кодом (`styles`, `project`). Режима строк с 13.8a нет: ключ `primula.lines` — ошибка P1116.
- Неизвестные ключи (верхнего уровня, `primula.*`, `doc.*`, `doc_defaults.*`) — предупреждение P1104; ключи, переименованные решением 129 (`document` → `doc`, в проекте `document` → `doc_defaults`, `documents` → `ref_documents`), — ошибка P1120 с новым именем (`header.RENAMED_KEYS`). Типы ключей-отображений и ключей-списков проверяются (P1105). Семантика значений (`params`, стили, цели проекта) проверяется в своих подэтапах.
- `primula.version`: принимаются строка `"1.0"` и десятичное `1.0` (без кавычек это `Decimal("1.0")`). Целое `1` даёт P1107 (не та версия), а не P1105.

## Командная строка (`cli.py`)

- Справка и сообщения локализованы: `--lang` находится до разбора аргументов (`_prescan_language`), чтобы `--help` уже был на нужном языке. Служебные слова argparse («usage», «options») остаются английскими.
- Любое необработанное исключение превращается в P0002, код возврата 2; трассировка выводится с `--debug`.
- Диагностика и итоговая строка пишутся в stderr; stdout оставлен под вывод команд (`fmt`).
- `build` (с 13.5) пишет ODT только без ошибок (с `--strict` — и без предупреждений); фаза `odf` в отчёте `--report`: `done`, `failed` (ошибка записи ODT или PDF) или `skipped` (ошибки предыдущих фаз). Для `check` она остаётся `not-implemented`.

## Стенд проверки ODT (`tests/odftools.py`)

Три уровня проверки, выбранные для этапа 13:

1. Структура пакета: `mimetype` первым и без сжатия, манифест перечисляет все части, XML корректен.
2. Валидация `content.xml`, `styles.xml`, `meta.xml` и манифеста по схемам OASIS ODF 1.3 через `xmllint --relaxng`. Проверено, что xmllint обрабатывает схему ODF 1.3 и находит ошибки; jing не нужен.
3. Конвертация LibreOffice headless в PDF (отдельный профиль `-env:UserInstallation`) и извлечение текста `pdftotext`.

Для golden-тестов — `canonical_xml()` (C14N 2.0 из stdlib).

Проверка PEP 701 (решение 30): f-строка, которую `ast` 3.12+ читает целиком, должна быть целым литералом и для сканера 3.11 |

| `inline.py` | Внутристрочный разбор; `Context` задаёт, где кончается содержимое (тело `{…}`, строка, абзац, ячейка) |

| `regions.py` | Второй проход: неявные области (решение 31), списки (32), окружения `|list:` (33) |

### Решения реализации

- **Разбор без отдельного токенизатора**: курсор по нормализованному тексту. Режим зависит от контекста (разметка, Python, сырой текст), поэтому общий поток токенов только усложнил бы разбор.
- **Плоские списки + отдельный проход `regions.organize`.** `|include` прозрачен для неявных областей (решение 31), значит, окончательные области можно построить только после вставки фрагментов. Вычисление (13.3) вызовет `parse(..., organize=False)`, подставит фрагменты в плоские списки и затем выполнит `organize`. В 13.1 `|include` — обычный блок, входящий в область.
- **Закрытия.** `Frame` на каждое открытое окружение. Помеченный маркер закрывает ближайшее подходящее окружение, вложенные получают P1216. Неподходящий маркер пропускается. `unwind_to` разматывает рекурсию до нужного уровня. `|else`/`|elif` внутри вложенного окружения `|if` тоже разматывают стек до `|if`, сообщив о незакрытых окружениях.
- **`|comment:`** (§3.7: проверяется только баланс). Внутри строчное содержимое не разбирается (`opaque`), чтобы незакрытая `{` не поглотила строки. Диагностику фильтрует `_BalanceSink`: проходят только коды баланса.
- **Восстановление после незакрытой `{`.** Тело закрывается перед строкой, которая может быть только блоком (`lines.BLOCK_ONLY`): заголовок, пункт, маркер закрытия и т. п. Строковая команда без тела (`|img(…)`) и формы `|name:` в этот набор не входят: внутри тела они допустимы.
- **Нормализация текста** (§4.1). Перевод строки внутри абзаца и отступ после него — один пробел. Пробелы в конце абзаца и строковой формы отбрасываются; внутри тел `{…}` пробелы сохраняются (`|for(x in xs){|(x), }`). `|~` хранится как U+00A0.
- **Перевод строки сразу после `|\`** пробела не даёт: иначе следующая строка в Writer начиналась бы с пробела (реквизиты «…|\» + «Код ЄДРПОУ …»). Толкование §4.1; найдено на примерах 02 и 05.
- **Таблицы.** Компактная строка `|:` делится на ячейки по `|&` вне тел. `|&` сразу после `|:` задаёт аргументы первой ячейки и не создаёт пустую (§6.4). Строка без содержимого не имеет ячеек; число ячеек проверяется в 13.7.
- **Предупреждения** P1236–P1238 (§14.2):
  - P1236 — после строковых форм с текстом; заголовки и команды без тела не учитываются;
  - P1238 — порог 30 строк (решение 35).
- **Производительность**: документ на 11 000 строк разбирается примерно за 0,6 с (Python 3.13). Проверка f-строк выполняется, только если во фрагменте есть префикс `f`.

### Решения 36–39 (ответ на `primula-spec-issues-13.1b.md`)

- область `|!` закрывают любой пункт и следующее `|!` (решение 38) — реализовано в `regions._closes`;
- `|end clause` закрывает пункт любого уровня (решение 39) — `blocks._matches`;
- `|include` допустим в теле `|table:` и `|row:`, `|let` и `|set` — ошибки (решение 37); проверку вставленных блоков выполнит 13.3;
- аргумент продолжения — `continues=` (решение 36); `continue=` остаётся синтаксической ошибкой Python.

### Что парсер не проверяет

Существование команд, стилей и имён; значения аргументов (`level=`, `when=`, `span=`); пути `|include`/`|import`; ID и ссылки; число ячеек; пропуск уровня заголовков в нумерованной зоне; `|?{…}` и `|fmt` (предупреждения зависят от отбора вариантов). Белый список узлов Python применяется в ядре (13.2).

### Решения реализации

- **Изоляция.** Код Primula не обращается к атрибутам объектов Python: атрибуты и методы берутся только из таблиц `builtins.py`; имена `__x__` и атрибуты с `_` запрещены статически (P2102); `str.format` не допускает доступ к атрибутам (решение 45). Ввода-вывода нет — `load_*` подключит 13.3 через `EvalContext.extra_builtins`.
- **Литералы `decimal`.** `ast` превращает `12.50` в `float`; ядро берёт исходный текст литерала и создаёт `Decimal("12.50")` (цифры сохраняются). Значение кэшируется в узле AST.
- **Позиции — лениво.** Перевод столбцов AST (байты UTF-8) в позицию файла дорог; интерпретатор передаёт `Where(фрагмент, узел)`, позиция вычисляется только при создании диагностики. Это вдвое ускорило ядро.
- **Быстрые пути** для целых (`int`), `decimal` и `float` в `+ - *`, `//`, `%` и сравнениях — с точной проверкой типа (`bool` не попадает); остальные случаи идут через `numbers.py`.
- **Скорость**: 0,5–0,75 млн узлов/с на Python 3.13. С 13.8a счётчик узлов служит только для того, чтобы раз в 4096 узлов смотреть на часы (лимит времени одного вычисления — 20 с).
- **Рекурсия.** Один вызов функции Primula занимает 10–20 кадров Python; при создании интерпретатора предел стека Python поднимается до `recursion × 40 + 2000`; `RecursionError` превращается в P2402.
- **Перебор и изменение.** Во время перебора список или словарь нельзя изменять (P2319), как в Starlark; замороженные значения — P2318 с подсказкой (решение 40).
- **Генераторные выражения** вычисляются сразу в список (побочных эффектов нет, отличается лишь порядок ошибок).
- **Верхний уровень** (решение 40): блок кода с запрещённой конструкцией не регистрируется целиком; ошибка одного действия не останавливает следующие.

### Что ядро не делает (следующие подэтапы)

`|let`, `|code` в документе, `|if`/`|for` разметки, макросы `|def`, `markup()`, операции `content`, `load_*`, `|include`/`|import` и отчёт об использовании лимитов — 13.3; стандартная библиотека (`num`, `money`, `words`, `days`…) — 13.9; объекты стилей — 13.4.

## Вычисление документа (подэтап 13.3, `src/primula/evaluate/`)

### Фазы (решение 54)

1. **Определения**: параметры заголовка, `doc`, глобальные `|let`, определения `|code:`, макросы `|def`, `|import`, фрагменты `|include` (вне тел `|if`/`|for`/`|def`) с их определениями; затем экспорты фрагментов в область корневого документа (`ns=`, `rename=`, `override=True`, конфликты P2620/P2621).
2. **Действия** всех блоков `|code:` в порядке документа, включая фрагменты; действия модуля — при его загрузке.
3. **Разметка**: выражения, `|if`/`|for`, `when=`, вызовы макросов и функций, вставка фрагментов; в конце — `regions.organize` (неявные области строятся после вставки, решение 31).

### Решения реализации

- **Вычисленное дерево** использует те же классы узлов, что и разбор; `args` содержит `EArgs` (значения аргументов), управляющие конструкции раскрыты, выражения заменены текстом или вставленным содержимым; формулы `|=` хранят окружение строки (атрибут `env`, для 13.7); исключённые `when=` блоки в режиме `--review` остаются с атрибутом `condition` (оформление — 13.10).
- **Один разбор.** Фронтенд разбирает файл без областей (`organize=False`); `regions.organize` больше не изменяет вход (копирует изменяемые узлы), поэтому одна плоская копия служит и для `--dump-parsed`, и для вычисления. Ошибки списков сообщаются по вычисленному дереву (или по дереву разбора, если вычисление не выполняется).
- **Области видимости** (решение 50): фрагмент — своя `GlobalScope` с родителем «корневой документ»; модуль — своя область без родителя, в файле подключения — `ModuleValue` (атрибуты — публичные имена) или выбранные имена; тела `|for`/`|def` — локальные `Env`.
- **Статический путь** `|include`/`|import` вычисляется в отдельной области, где есть только параметры заголовка файла с командой и корневого документа (P2612 для прочих имён). `key=` требует карты ключей из файла проекта (13.11) — пока P2619.
- **`|include` внутри `|for`/`|if`/`|def`** вычисляется на месте при каждом проходе (новая область фрагмента); экспорт из такого фрагмента — ошибка P2610 (иначе экспорт был бы условным, решение 49).
- **Макросы** (решение 48) — значения `Macro` (наследник `Builtin`): из кода вызов возвращает `content`; команда-строка или окружение вставляет блоки, вызов внутри строки — содержимое тела из одного абзаца. Абзац, состоящий только из `|(x)` со значением-блоками (например, `|(body)`), заменяется этими блоками.
- **Текст из `|(…)`** (решение 47): `str`, `int` — как есть; `decimal`, `float`, `date`, `length` — с предупреждением P2604; `None`, `bool`, коллекции, запись, стиль, функция — P2603.
- **Данные**: файлы `load_*` читаются через `SourceManager`, поэтому попадают в отчёт с SHA-256; ошибки указывают строку в файле данных и место вызова (кадр стека).
- **Стек ошибок**: кадры `include`, `import`, `macro`, `call` (markup) добавляются к диагностикам при выдаче (`_FrameSink`).
- **Отчёт**: раздел `evaluation` — параметры, условия `when=` с результатами, записи `debug`, использование лимитов.
- **Скорость**: документ на 10 000 строк с выражениями, циклами и условиями проходит разбор и вычисление примерно за 2 с.

## Стили (подэтап 13.4, `src/primula/styles/`)

### Поток

1. До сбора определений документа загружаются модули стилей из ключа `styles` заголовка документа (список проекта добавится в 13.11); без них — встроенный `std/styles/default` (`src/primula/stdlib/styles/default.prml`, решение 55). Каждый модуль — слой: YAML-группы, затем код (определения и действия по решению 40).
2. Публичные имена модулей образуют уровень «стили» — родитель области документа (решение 58). Уровень растёт по мере загрузки: модуль видит имена предыдущих модулей (так локальный слой берёт `spacing` и `indent_step` базового), более поздний модуль заменяет одноимённое имя.
3. Документ и его фрагменты — последний слой (`StyleRegistry.begin_layer("document")`); при загрузке модуля `|import` текущий слой снимается, и определение стиля даёт P3114 (решение 59), а функция модуля, вызванная действием документа, определяет стиль в слое документа.
4. После вычисления `StyleRegistry.finalize()` сливает слои (§11.7) и проверяет наследование; `StyleApplier` размечает вычисленное дерево.

### Решения реализации

- **Форматы значений** (решение 57) проверяются при определении; ошибка указывает позицию значения в YAML. Список атрибутов `odf=` генерируется из схемы ODF 1.3 (`tools/gen_odf_attributes.py`).
- **Имена** (решение 56): `Base-before-l-after-s`, `derive` — `Base-<свойство>-<значение>…` по алфавиту, хеш для длинных имён и недопустимых символов; одинаковые свойства — одно имя; занятое имя с другими свойствами — P3111.
- **Каскад** (решение 61): родитель — самый внутренний явный стиль абзаца, иначе стиль конструкции; `extra` — свойства внешних слоёв (стиль конструкции, внешние `|.Name:`), которых нет в цепочке `parent` родителя; выравнивание ячейки — последним.
- **Стиль конструкции абзацев внутри окружений**: в `|>:` — стиль пункта своего уровня (на него действует `|set(clause=…)`, а не `paragraph`); в `|block:` — свойство `paragraph` блочного стиля, если задано; в ячейках — `paragraph` / `header_paragraph` стиля таблицы; в списках — `paragraph` стиля списка.
- **`|set`** (решение 60): область — структурное окружение; `None` — сброс; `|set` фрагмента превращается при вставке в атрибут `set_overrides` следующих блоков фрагмента.
- **Короткие формы** `|*`, `|/`, `|_`, `|^`, `|,`, `` |` ``, `|"` в 13.4 стилей не получали; с 13.5 по решению 62 все короткие формы, кроме `|"`, выводятся именованными стилями символов (см. раздел «Генератор ODT»).
- Встроенный модуль кроме перечисленных в решении 55 стилей содержит `Heading` (общий родитель заголовков), `Admonition`, `TableText` (абзац ячейки `TableGrid`), `Group` (блочный стиль) и шкалы `spacing`, `indent_step`.
- **`|verbatim:`** получает стиль абзаца своего места, как обычный абзац: внутри `|.Зразок:` — стиль `Зразок` (до 15.10.2026 — всегда стиль конструкции `paragraph`). Имя родителя в YAML (`parent: Реквізити`) и в `next`/`paragraph` проверяется как Unicode-имя стиля (решение 102), а не по ASCII-шаблону.

### Отображение дерева

- Абзац → `text:p` со стилем из `style_use` (13.4); если каскад добавляет свойства к родителю — автоматический стиль `P<n>`, одинаковые сочетания делят один стиль. Заголовок → `text:h` с `text:outline-level`.
- Пункт в строчной форме → `text:p`, его область — следующие соседние блоки; `|.Name:` и `|!` — абзац или блоки окружения.
- Списки → `text:list` / `text:list-item`, вложенные списки — внутри элемента. Блоки, которые пока нельзя поместить в элемент списка, пропускаются с P8006.
- Короткие формы → `text:span` с именованными стилями символов (решение 62; ключи `structure_styles`: `strong`, `emphasis`, `underline`, `superscript`, `subscript`, `code`, `strike`, `placeholder`). `|"{…}` — кавычки языка документа, чередование уровней (решение 63; переопределение — `quotes(…)` в модуле стилей).
- `|\` → `text:line-break`; серии пробелов → `text:s`; табуляция → `text:tab`; поля `|field.page`, `count`, `title`, `chapter` → `text:page-number`, `text:page-count`, `text:title`, `text:chapter`.
- `|newpage` → `fo:break-before="page"` на автоматическом стиле следующего абзаца или таблицы; `|fmt` — прямое оформление в автоматическом стиле, неизвестное свойство — P8007.
- Первый блок получает мастер-страницу стиля страницы по умолчанию (ключ `page` в `structure_styles`, по умолчанию `Portrait`, решение 64).
- **Простые таблицы** (предварительная версия до 13.7): колонки с ширинами, строки шапки (`table:table-header-rows`), рамки ячеек по `frame`/`rules`, стили абзацев ячеек; лишние ячейки строки отбрасывались с P8005. С 13.7 заменены полными таблицами (раздел «Таблицы»), P8005 удалён.
- Конструкции следующих подэтапов (`_LATER` в `content.py`: приложения, оглавление, сноски, рисунки, колонтитулы, разделы и др.) дают P8001 и видимый заполнитель с именем конструкции; содержимое областей (`appendix`, `section`, `page`) выводится, чтобы текст не терялся.

- **Встроенные части** (решение 67): `Primula/report.json` — сокращённый отчёт (версии, файлы с SHA-256 и путями от корня проекта, имена параметров варианта без значений, модули стилей и материализованные стили, использование лимитов, предупреждения без стека; без вывода `debug`), отключается `--no-embed-report`; полный отчёт — только внешним файлом `--report`. `--embed-sources` добавляет `Primula/sources/…` с путями от корня проекта; встроенные модули `std/` не вкладываются.

### Решения реализации (толкования, не противоречащие решениям 68–76)

- **Номер заголовка** — составной номер с префиксом области; ненумерованный заголовок не двигает счётчики, а пункты после него нумеруются от последнего нумерованного заголовка (§5.3). Предупреждение P4203 (решение 68) выдаётся на подраздел, если в его родительском разделе уже были пункты.
- **`continues=`**: продолжение пункта номера не получает; подпункты продолжают счётчик цели. Цель должна стоять раньше (P4205), в том же разделе, области и на том же уровне (P4206).
- **Таблица нумеруется, если у неё есть подпись** (`caption=` или `|caption:`). Таблица с `id=`, но без подписи — цель только для режима `page`; `number`, `label`, `title` для неё — P4304. Рисунок нумеруется всегда; до 13.8 вместо изображения — заполнитель, подпись выводится.
- **Нумерация в приложении и области с префиксом**: таблицы и рисунки — `префикс.k` независимо от `by_chapter`; заголовки — `префикс.n`; пункты без заголовка — `префикс.k`. Записи оглавления внутри приложения сдвигаются на уровень вниз.
- **Словари меток и тексты профилей** заданы в `structure/settings.py` как значения профиля, а не вызовами во встроенном модуле: так они действуют и при собственном модуле стилей с `structure_profile(…)`. Для языка без текстов подписи и обозначения берутся английские, а режим `label` — ошибка P4305 (решение 72).
- **Закладки**: у цели с ID — сам ID; заголовки, приложения и подписи, попавшие в оглавление или перечень, получают автоматические закладки `__toc_N`. Метки `text:toc-mark` и `text:user-index-mark` и автоматические закладки пишутся, только если в документе есть `|toc` или `|list_of` соответствующего вида: иначе оглавление, вставленное в Writer вручную, получило бы записи дважды (по меткам и по уровням).
- **Сноски**: `text:id` — `ftnN`/`ednN` по порядку; цитата вычисляется для `restart="none"` (Writer пересчитывает сам); формат `"*"` пишется как собственная метка `text:label` («*», «**»…).
- **`--review`**: блоки с `when=` остаются в документе, ссылка на них — предупреждение P4303; невыбранные ветви `|if` не сохраняются, ссылка на их ID — ошибка P4302.
- **`|list_of("abbr"|"index")`** — подэтап 13.10 (заполнитель, P8001); неизвестный вид — P4401.

### Где выполняется

- **Сетка и каскад** строятся в `StyleApplier._table` (фаза стилей): стиль абзаца и выравнивание каждой ячейки зависят от каскада колонки и строки. Сетка сохраняется в `block.table_grid`.
- **Значения одиночных выражений** запоминает вычислитель: если содержимое ячейки — ровно одно `|(…)`, значение кладётся в `cell_value` узла вместо текста (так не выдаётся P2604, решение 80). Это компактные ячейки, тело `|cell(…){…}`, строчная форма `|cell:` и окружение `|cell:` с одним абзацем из одного выражения.
- **Фаза таблиц** (`TableProcessor`) запускается вычислителем после стилей: формулам нужен интерпретатор. Затем идёт фаза `structure`.
- **Генератор** пишет ширины колонок, `table:number-columns-spanned`/`-rows-spanned` и `table:covered-table-cell`, стили строк (высота, `keep`), `style:may-break-between-rows`, повтор шапки, блочное содержимое ячеек (абзацы, списки, вложенные таблицы), `office:value-type`/`office:value`/`office:currency`/`office:date-value`, `table:formula`.
- **Парсер**: формула `|=(…)` теперь разрешена и в развёрнутой ячейке `|cell:` (строчная форма и окружение). Раньше — только в компактной строке (P1228).
- **Отчёт**: ширины таблиц — в `evaluation.tables` полного отчёта и в `tables` встроенного (файл, строка, ширины в мм).

### Решения реализации (толкования)

- **Типы колонок разбирают литералы только в строках тела.** Шапка и итоговые строки содержат подписи («Кількість» над колонкой `int`, как в примере §6.9). Выражения и формулы получают значение в любой строке.
- **Литерал с разметкой** (`|*{…}`) в колонке с типом — строка, не разбирается.
- **Пустая ячейка тела** в колонке с типом — значение `None`, вывод пустой.
- **Ширины**: к измеренному содержимому добавляются отступы ячейки, толщина левой и правой рамок и запас 0,5 мм на округление позиций символов в Writer. Без запаса Writer переносил последнюю букву («1 200,00 гр|н»). Кернинг не учитывается.
- **Шрифт ячейки** — по цепочке стиля абзаца ячейки, свойствам каскада и `header_*` (полужирная шапка). `fc-match` принимается, только если вернул запрошенное семейство; иначе — приближённый расчёт и P5112.
- **Таблица без `*`-колонок** может стать уже заданной ширины (шаг 5); ширина таблицы в ODT — сумма колонок.
- **Границы в ODT**: внутреннее вертикальное ребро записывается один раз — левой границей правой ячейки; внутреннее горизонтальное — у обеих ячеек (нижняя граница верхней и верхняя нижней, одно значение каскада), чтобы обе части таблицы, разорванной между страницами, были закрыты линией (Writer на разрыве её не добавляет; замечание Э12). Таблица пишется с `table:border-model="collapsing"`: две границы ребра дают одну линию.
- **Цикл формул** сообщается один раз, у внешней ячейки цепочки; все ячейки цепочки остаются без значения.
- **Текстовый вывод значения** (`plain_text`) больше не схлопывает неразрывные пробелы: они нужны в числах («1 500,00») и метках ссылок.
- **Формулы Writer (`live=True`)**: префикс `ooow:` в значении `table:formula` разрешается через объявления пространств имён части, а ElementTree объявляет только префиксы, использованные в именах. Поэтому корень `content.xml` всегда объявляет `xmlns:ooow` (без него LibreOffice выводит «** Expression is faulty **»; найдено на примере 05 в 15.10.2026). Числовые ячейки таблицы с `live=True` получают числовой формат ODF (`number:number-style`: группы разрядов, знаки после запятой как в выведенном тексте, символ валюты, язык документа) — Writer пересчитывает формулы при загрузке и выводит результат по этому формату.

### Где выполняется

- **Вычислитель**: путь `|img`/`|figure` разрешается по правилам §10.1 относительно файла с командой (`image_path`); встроенная `img(path, …)` возвращает значение-изображение (`ImageValue`) для `watermark=` (решение 84).

- **Фаза `pages`** выполняется после `structure` (и в `check`).
- **Генератор**:
  - смена страницы — `style:master-page-name` и `style:page-number` в стиле первого абзаца или таблицы после смены (механизм «ожидающих» элементов); `|newcolumn` — `fo:break-before="column"`;

### Решения реализации

- **Writer различает свои врезки и изображения по стилям-родителям `Frame` и `Graphics`.** Без них `draw:frame` импортируется как графическая фигура, а изображение внутри текстового фрейма не отображается (проверено на LibreOffice 26.8). Эти стили пишутся в `styles.xml`, автоматические стили фреймов наследуют от них. Атрибуты `draw:fill`/`draw:stroke` у текстовых фреймов не используются по той же причине; прозрачность — `fo:background-color="transparent"`.
- **Рисунок по умолчанию** (по центру, без обтекания) — абзац стиля `Figure` с изображением «как символ» и абзац подписи; `keep_with_next` удерживает их вместе. С `place`/`wrap`/`x`/`y` — плавающий фрейм с текстовой областью, внутри — изображение и подпись.
- **Водяной знак** — изображение в каждом варианте верхнего колонтитула мастер-страницы, за текстом (`run-through` + `background`), положение от края страницы (`from-left`/`from-top`, `rel="page"`) по геометрии стиля: Writer отсчитывает `page-content` объекта в колонтитуле от колонтитула. Без колонтитула создаётся колонтитул с абзацем-носителем минимальной высоты (тело страницы сдвигается не больше чем на ~0,5 мм). Размер текста ограничен так, чтобы повёрнутая строка помещалась в область: LibreOffice не обрезает SVG по `viewBox`.
- **`rel="page"`** — привязка к абзацу с положением от страницы и `style:flow-with-text="false"`; `anchor="page"` пишет `text:anchor-page-number="1"`.
- **`rotate=`** пока не выводится (P6107): поворот фреймов изображений Writer хранит в собственных расширениях.
- **Колонтитулы**: `style:header` — нечётные (правые) страницы или все; `style:header-left` — если задан `left` или `right` (решение 89); `style:header-first` — первая страница каждого участка стиля (решение 88). Пустое окружение — пустой колонтитул на соответствующих страницах.
- **Отступ колонтитула** по умолчанию 2,5 мм (`header_gap`/`footer_gap`), минимальная высота 0.
- **Наследование колонтитулов по сторонам**: для `left`/`right` выигрывает ближайший стиль цепочки `parent`, в котором задана эта сторона или `all`; `all` потомка закрывает `left`/`right` родителя (пустой `footer("Титульна", markup(""))` убирает колонтитул титульной страницы, даже если у `Portrait` разные левый и правый).

## Переход на спецификацию v1.1 (подэтап 13.8a)

Подэтапы 13.0–13.8 написаны по v1.0-draft; 13.8a переводит их на v1.1 (решения 100–114). Описания разделов выше относятся к v1.0 там, где здесь сказано иное.

- **Unicode** (`unicode.py`, `unicode_data.py`). Язык фиксирует Unicode 15.1 (решение 114). Таблицы `XID_Start`, `XID_Continue` и категорий `P*`/`S*` сгенерированы `tools/gen_unicode_tables.py` (нужен Python с `unicodedata` 15.1, например 3.13) и поставляются с транслятором, поэтому классы символов не зависят от версии интерпретатора. NFC/NFKC берутся из `unicodedata`; версия Unicode среды пишется в отчёт (`unicode.runtime`).
- **Лексика.** После `|` буква любого алфавита начинает длинную команду (`|підпис(…)`), символ `P*`/`S*` — короткую форму; неопределённая — P1202, похожая на `—` (`–`, `−`) — P1203 с подсказкой. Имена стилей и `id=` — Unicode-идентификаторы с дефисом (и точкой у ID). Режим `para` удалён: строковая форма заканчивается в конце строки, абзац по-прежнему продолжается на следующих строках текста.
- **NFKC.** Имена из кода Python нормализует сам `ast` (PEP 3131). Имена из разметки (команды, ID в `id=` и `|@`, имена стилей, ключи YAML/JSON/CSV, поля записей в `r["…"]` и `getattr`) нормализуются транслятором; ключи, совпавшие после нормализации, — ошибка (YAML — `duplicate`, `record()` — P2325).
- **Подсказка `|;`.** Неизвестная команда, начало которой — известная команда или имя (`|sellerом`), получает подсказку `help.glued_name` (§3.2).
- **Числа.** Один тип `decimal`: целое значение хранится как Python `int` (быстро; `5 == 5.00` с равным хешем), остальное — `Decimal`; `type()` даёт `"decimal"`. Точные операции идут в контексте 64 цифр с ловушкой `Inexact` — переполнение P2309; деление и дробные степени — 28 цифр. Смешение с `float` даёт `float` (и в сравнениях: `0.1 == 0.1e0`). Индексы, срезы, `range` и повторение принимают числа с целым значением (`numbers.as_integer`).
- **`datetime`** (`values.DateTime`). Хранится целое число секунд от 1899-12-30 — наблюдаемо равно модели `float64` §12.3. `dt ± n` — сутки с округлением до секунды половиной от нуля; `dt - dt` — `decimal` суток; `float(dt)` и `datetime(serial)` — серийное число. Дата сборки остаётся `datetime.date` внутри CLI и упаковки ODT, в ядро она попадает как `DateTime`.
- **`length`** (`values.Length`): десятичное значение и единица; `inches` — вычисляемая точная дробь, поэтому вёрстка таблиц и страниц не менялась. Сравнения в коде Primula — с допуском 0,001 мм (в интерпретаторе); Python `==` класса точный (для внутренних таблиц).
- **Стиль — строка** (решения 111, 114). `derive(…)` резервирует детерминированное имя (`StyleRegistry.reserve`: конфликт с другими свойствами — сразу P3111 с подсказкой `name=`), стиль записывается при первом применении (`StyleSystem.ensure`). Имена: буквы и цифры Unicode, `_`, `-`, прочее → `_`; хеш — только для имён длиннее 128 символов (решение 103).
- **Слои стилей** (решение 106): `--style` (в порядке указания) → `styles` документа → код документа; любой названный модуль отключает автоподключение `std/styles/default`. Основа модуля (`extends`, решение 133): `Evaluator._load_styles_layer` рекурсивно подключает основу перед модулем; множество `done` (по `Path.resolve()`) даёт каждому модулю один слой на первом месте, список `chain` ловит цикл (P2615); путь — `_styles_path` (как `|import`; у модуля `--style` вне корня — рядом с ним, без проверки корня). Файл `--style` вне корня проекта во встроенном отчёте ODT — только по имени.
- **Файлы** (решение 100). Вид файла — `kind`, иначе подрасширение; расхождение — P7001. Путь без `.prml` ищется сначала с подрасширением команды (`Loader.find`). Имя модуля `|import` — имя файла без расширения и подрасширения.
- **`level=` заголовка** вычисляется на фазе вычисления (решение 114): `evaluator._heading_level`, вне 1–6 — P4212; `|<<(level=…)` — синтаксическая ошибка P1244 по наличию ключа.
- **Лимиты** (решение 113, `core/limits.py`). Три лимита: время одного вычисления (`Meter.begin()` перезапускает часы для каждого действия и каждого блока разметки верхнего уровня; внутри вызова макроса часы идут дальше), рекурсия, размер значения (`size`: P2403 для коллекций, P2404 для строк). `--timeout` — срок всей сборки (P0004). Память: на время вычисления `RLIMIT_AS` = текущий размер + 1 ГиБ (Linux), после — восстановление, чтобы не задеть LibreOffice; `MemoryError` → P0005. В отчёт пишутся наибольшие глубина, размер и время; время — только во внешний отчёт, иначе ODT не был бы побайтно воспроизводим.
- **Линтер имён** (`evaluate/lint.py`): P2502 — смесь алфавитов в имени, P2503 — пара имён, различающихся только омоглифами; проверяются глобальные имена файлов проекта и стили автора.
- **Версия.** Принимается только `primula: {version: "1.1"}` (иначе P1107, для 1.0 — с перечнем несовместимостей); `primula: {stdlib: "X.Y"}` проверяется против `STDLIB_VERSION`.

### Решения реализации (толкования)

- **`fmt_date(dt, "contract")`** пишет день двумя цифрами: «02» березня (пример библиотеки — «12»).
- **`month_name`** принимает и номер месяца 1–12; **`qty`/`qty_range`** принимают `digits=`, как `num`.
- **`convert`** для `decimal` отбрасывает конечные нули дроби (`convert(1.5, "kW", "W")` → 1500).
- **Календарь**: даты `holidays`/`workdays`/`rest_days` — без времени суток (иначе P2714); проверенный календарь кэшируется в `Library` по значению данных.
- **`workdays`** учитывает лимит времени вычисления (шаг счётчика на день).
- **Деньги**: отрицательная сумма прописью — «мінус …»; `EUR` — средний род («одне євро»); `money_words` в en: «two US dollars 01 cent».
- **`translit` uk**: таблица постановы КМУ № 55; «начальная» позиция — начало слова (не после буквы и не после апострофа); регистр: слово прописными → результат прописными, иначе заглавная первая буква. Проверено по примерам таблицы постановы.
- **`sort_key`** возвращает кортеж (первичные веса без учёта регистра, апострофа и дефиса; затем регистр; затем текст); пробел меньше любой буквы, цифры перед буквами, буквы алфавита языка — в его порядке, прочие — по коду.
- **`typography(nbsp_short=True)`** до 13.9d — явная заглушка: настройка сохраняется, выдаётся предупреждение P2726.
- **Повторные ошибки**: ошибка неудавшегося ленивого определения выдаётся один раз — промежуточный приёмник вычислителя пропускает уже выданный объект диагностики.
- **`live=True` и пустое тело таблицы**: `sum`/`count` по пустому диапазону — формула `0` (у Writer нет пустого диапазона), `avg`/`min`/`max` — P5114.

- **`review_marks(true=…, false=…)`** задают слова подписи; цвета подложки берутся из фона стилей `ReviewTrue`/`ReviewFalse` (по умолчанию светло-зелёный и светло-красный).
- **Пути `admonition_symbols`** разрешаются от файла модуля стилей с этим вызовом, `symbol=` у блока — от файла блока.
- **Невыбранные ветки `|if` в `--review`** получают условие, поэтому ссылки на цели в них дают P4303, как ссылки на отключённые `when=`.
- **Соседние таблицы предупреждений** стоят вплотную: внешних отступов у таблиц ODF нет.
- **Перечень сокращений** — вычисленная таблица, а не обновляемый указатель Writer; указатель терминов — указатель Writer (номера страниц заполняются при обновлении, `--pdf` с мостом UNO).

## QR-коды и Base64URL (решение 137, `library/qr.py`)

- Кодер QR в байтовом режиме по ДСТУ ISO/IEC 18004:2019 на стандартной библиотеке Python, по структуре библиотеки Project Nayuki (MIT): биты данных, блоки Reed–Solomon (GF(256), 0x11D) и их чередование, функциональные узоры, размещение «змейкой», восемь масок со штрафами N1–N4, информация о формате и версии. `encode(payload, ecc, min_version, max_version)` — наименьшая подходящая версия, маска с наименьшим штрафом.
- Функции библиотеки: `qr_matrix` (запись), `qr_svg` (SVG: тёмные модули горизонтальными отрезками одного `path`, тихая зона, белый круг `circle`), `base64url` (`utf-8`/`cp1251`, без `=`); ошибки P2728, P2729, P2704.
- Проверка (`tests/test_library_qr.py`): `zbarimg` раскодирует коды всех версий, модули совпадают с `qrencode` до выбора маски (libqrencode иначе считает штрафы), коды с кругом НБУ раскодируются; без этих программ тесты пропускаются.
- Правила НБУ — пользовательская библиотека `libraries/payment_qr` поверх этих функций.

## Граница корня проекта (решение 136, `paths.py`)

- `paths.within(path, root)` — путь относительно корня или `None`. Сначала проверяется записанный путь (`os.path.abspath`, `..` сокращается по тексту, ссылки не раскрываются), затем настоящий (корень, открытый под другим именем: `/home/u/dev` → `/works/u/dev`).
- `paths.outside_link(path, root)` — первая ссылка на пути от корня, ведущая за настоящий корень, и её цель; `Loader._inside` выдаёт по ней P2639 раз на ссылку.
- Загрузчик возвращает записанный путь (не `resolve()`): относительные пути внутри библиотеки за ссылкой отсчитываются от него и подчиняются той же проверке. Тем же правилом пользуются `Loader.display_name`, `Project.contains`, `xrefs.source_files` (хеши файлов в отчёте и реестре), `odf/writer._relative` (`--embed-sources`), `Evaluator._styles_path` (модуль стилей «вне корня» из `--style`).
- Studio дополняет пути `|import`/`|include` и файлами за ссылками (`QDirIterator::FollowSymlinks`).

  - уровень «проект» (`_load_project`): параметры проекта — значения, имя `project` — `ModuleValue` над уровнем проекта; секция кода проверяется белым списком ядра, её определения ленивы, действия выполняются сразу; стили в ней не определяются (слоя нет). Уровень «стили» — потомок уровня проекта (§10.4: … → стили → проект → встроенные);
  - слои стилей: проект (пути от файла проекта) → `--style` → `styles` документа → код документа;
  - `_define_header`: параметр документа с именем параметра проекта — переопределение, тип сверяется (P7110); значения цели и `params=` части заменяют объявленные (P7106 при другом типе), параметр только проекта определяется в документе, неизвестный — P2617;
  - `build()`/`batch_mode()` — встроенные функции, которые проверяют, что вызов стоит в файле проекта (P7111); `build()` складывает цели в `EvalOptions.targets` (только при планировании пакетной сборки);
  - карта ключей (`_key_path`): ключи проекта, поверх — ключи цели; путь от корня проекта (`Loader.resolve_root`); `#часть` только у `|include` (P7113); `key=` вместе с путём или `part=` — P7114; без проекта — P7112; неизвестный ключ — P2619;
  - `on_conflict`: `first`/`last` — предупреждение P7115 и выбор экспорта; `error` — P2620, как раньше;
  - части `|document`: на фазе 1 корня собираются узлы (P7116 вне верхнего уровня), затем каждая часть готовится (`_prepare_part`): своя область имён над уровнем «стили», параметры (`params=` вычисляется в корне), `doc`, фрагменты и их экспорт; на фазе 3 (`_expand_part`) часть разворачивается в узел `document` (аргументы `scope`, `page`). На время части `self.root` и `header_data` переключаются на неё: язык библиотеки, `has()`, владелец фрагментов, префикс исключённых ID.
- **Стили**: `StyleRegistry.allow_identical` — при наличии частей одинаковое определение стиля из другого файла не ошибка (P3103 только для различающихся).
- **Структура**: узел `document` — своя область нумерации (заголовки, пункты, таблицы, рисунки, приложения с начала), ID получают префикс `область:`; ссылки внутри части ищут сначала `область:id`, затем ID корня; ID с `:` — полный. Сноски, оглавление, перечни, сокращения — общие.
- **Страницы и ODT**: часть начинается с новой страницы (`fo:break-before`); `page=` — смена стиля страницы; без `page=` — стиль страницы корня по умолчанию; после части восстанавливается прежний стиль, если часть его меняла.
- **Таблицы**: ширина доступной области теперь учитывает стиль страницы `|page`, `|appendix(page=…)` и `|document(page=…)` (раньше таблицы в альбомной области считались по книжной странице).
- **Язык**: `document_language(…, project_language)` — `doc.language` → `language` проекта → `defaults.language` стилей → `uk-UA`.

### Решения реализации (толкования)

- **`project.*`** даёт и параметры описательной секции, и определения секции кода (вычисляемые параметры): оба — имена уровня «проект».
- **Секция кода проекта** выполняется при каждой сборке документа проекта и при планировании пакетной сборки; в сборке целей `batch_mode()` тоже `True`, но `build()` там ничего не регистрирует. Ошибки секции кода при планировании останавливают пакетную сборку (цели повторили бы их).
- **Вид файла проекта** (решение 118): пакетная сборка включается по `kind: project` заголовка, а не по имени; проект без подрасширения `.p.prml` — предупреждение P7001; файл `project.p.prml` с другим `kind` собирается как то, что указано в `kind`, и сам себе проектом не служит. При `--project ФАЙЛ` имя не проверяется, обязателен `kind: project`. Поиск проекта вверх по-прежнему ищет имя `project.p.prml`.
- **`|document` в `|if`/`|for` и с `when=`** (решение 118): такая часть готовится в момент вычисления команды (`deferred_parts`), а не на фазе определений; `scope=` и `params=` вычисляются в её окружении (переменная цикла даёт каждой части свою область и параметры), путь статический (решение 104); действия секций кода такой части выполняются сразу (действия корня к этому моменту выполнены). Часть, отключённая `when=` или невыбранной веткой, не читается. В окружениях — P7116. `|if`/`|for`, содержащие `|document`, закрывают неявную область пункта, как сама команда. Для `has()` и `markup()` часть находится по исходному файлу на время её развёртывания (несколько частей из одного файла).
- **Область части** без `scope=` — основа имени файла (`act.prml` → `act`); имя области — как ID, без `:`; повтор — P7118.
- **`structure`** в заголовке части тоже игнорируется с P7117 (в спецификации названы только `styles`): настройки структуры — корня.
- **Порядок действий**: действия секций кода частей выполняются после действий корня (каждая часть — в своём порядке).
- **Нумерация приложений** начинается заново в каждой части; сноски нумеруются сквозно.
- **Отчёт**: у отчёта документа появился блок `project` (файл, хеш, имя, язык, параметры, ключи); у пакетной сборки — `project` и `targets` (`source`, `output`, `pdf`, `origin`, `result`, `report`).

### Решения реализации (толкования)

- **`nbsp_short`** — по языку корневого документа (часть сводного документа со своим языком получает слова корня); вне uk/ru/en — слова en, как у функций библиотеки. Пробелы после короткого слова заменяются одним неразрывным.
- **`--param`**: значение — скаляр YAML; строковый параметр получает текст как написан (`--param номер=17` → «17», кавычки не нужны); неизвестное имя — P7124, другой тип — P7106 (без позиции); при сборке проекта — P7125.
- **`level_shift=`** вычисляется при развёртывании (не статический); часть со сдвигом продолжает номера заголовков объемлющего документа («1.2» → «1.2.1»), иначе её первые заголовки дали бы P4201. Уровень больше 6 — P2636, остаётся 6. Применение `level=` при оформлении стилей убрано (дублировало вычислитель и мешало сдвигу).
- **`|table(data=…)`**: строка заголовков — `titles`, иначе имена полей (для данных-списков без `titles` строки заголовков нет: нужен `header=0`); поле, отсутствующее в записи, — P5115; строки тела окружения идут после данных; допустима строчная форма без тела.
- **`letters=`**: нумерация текстом не обновляется Writer при правке; продолжение списка (`continues=`) по буквам не учитывается — счёт с начала блока или с `start`. Набор букв профиля `report` (uk) взят из ответа темы спецификации и требует сверки с ДСТУ 3008:2015: у приложений в `LETTERS` исключена ещё и «И».
- **`--format json`** — массив в stdout (поля как в отчёте: `code`, `severity`, `message`, позиция, `notes`, `stack`), сообщения целей проекта включены; вместе с `--dump-*` — ошибка разбора аргументов.
- Отступы таблиц: у `AdmonitionTable` по 3 мм — соседние блоки `|!` больше не соприкасаются.

## Параллельные потоки (этап 16, решение 134, `src/primula/parallel/`)

Подэтап 16.2 — разбор, вычисление и вывод. Нумерация по потокам, заголовки и сноски неосновных потоков, `track=` у `|toc` — 16.3; проверки `parity` — 16.4; `rev`/`status` и `primula parallel` — 16.5.

### Модули

| Модуль | Назначение |
| --- | --- |
| `parallel/model.py` | функция кода `track(…)` (запись `Track`), проверка аргументов `\|parallel` (`ParallelSpec`), `\|segment` (`SegmentArgs`) и блока потока (`TrackBlockArgs`); все ошибки описания — P5305 с конструкцией, переведённой причиной и значением; перечень команд, запрещённых в сегменте |

### Где выполняется

- **Парсер.** Строка `|segment(…) |track(…){…} …` — отдельный вид строки `Kind.SEGMENT` (`lines.classify`), разбирается в `Command("segment", form="line")` с детьми `Command("track", form="inline")`. Блок потока `|track("id"):` — окружение без собственного закрытия: его тело кончается на следующей строке `|track(…):` (`BlockParser._end_track`; открытые внутри окружения — P1216), анонимный `|end` внутри блока потока закрывает сегмент, помеченное закрытие сегмента не считает блок потока незакрытым. Содержимое `|parallel` проверяется сразу (P5303). `parallel` и `segment` — только блочные команды (P1210 в тексте).
- **Вычислитель.** `_expand_parallel` проверяет аргументы, вычисляет содержимое с контейнером `parallel` (сегменты, `|if`/`|for`, `|code:`, `|include`, разрывы страниц; прочее — P5303) и заменяет окружение таблицами. `_expand_segment` и `_expand_track` вычисляют блоки потока в окружении с записями `track` и `segment`; язык потока кладётся в стек `track_languages`, и `Library` через `_language()` берёт его вместо языка документа (неподдерживаемый язык — P5308 и английские формы, без P2701). Запрещённые в сегменте команды — P5304 после вычисления (ловит и вставки фрагментов, и макросы).
- **ID.** Блоки потока помечаются как вложение с пространством имён id потока (механизм `ns=`, решение 74, `_tag_track`): полный ID — `uk.services`, ссылка внутри потока сначала ищет ID своего потока, затем документа. «Путь» вложения уникален для каждого блока потока, поэтому повтор ID — обычный P4102.
- **Стили.** Таблица `|parallel` получает стиль `structure_styles(parallel_table=…)` (по умолчанию `ParallelTable`), ячейки строки названий — `parallel_header` (`ParallelHeader`); оба стиля — во встроенном `std/styles/default`.
- **ODT.** Ячейка с `track_language` пишется с этим языком: `fo:language`/`fo:country` в автоматических стилях её абзацев, кавычки языка; `typography(nbsp_short=True)` берёт короткие слова языка потока для элементов ячейки (`apply_nbsp_short(…, own=…)`).

### Решения реализации (толкования)

- `|parallel` после вычисления — обычная таблица (`|table` с `cols`, `header`, строками и ячейками-окружениями) с атрибутами `parallel`, `segment`, `track`, `track_language`. Стили, ширины, каскад и генератор ODT отдельной ветки не требуют. Промежуток `gap` — внутренние отступы столбцов (по половине у соседних), `rule` — левая граница столбцов, кроме первого.
- Блок потока, исключённый `when=`, — пустая ячейка без P5301 (поток исключён намеренно). Отсутствующий блок обязательного потока — P5301 и заполнитель `|?{…}`.
- Вставка `|include` в блоке потока вычисляется на языке потока, но записи `track`/`segment` фрагменту не видны: у фрагмента собственная область имён (10.4).
- `id=` окружения `|parallel` в таблицу не передаётся: это не цель ссылок (7.7).
- Сноски, заголовки и счётчики по потокам — подэтап 16.3 (ниже).

### Подэтап 16.3: нумерация, ссылки, сноски, указатели

- **Счётчики.** `StructureBuilder._parallel` держит для каждого потока пару (стек областей `_Scope`, счётчики сносок): основной поток работает на состоянии документа, остальные — на глубокой копии, сделанной при входе. Таблицы одного `|parallel` после разрыва страницы продолжают те же состояния (`parallel_states` по `id` описания). Сегмент на всю ширину нумеруется основным потоком, после него нумеруемые потоки получают копию его счётчиков (толкование «продвигают одинаково», внесено в 7.7). После окружения документ продолжает от основного потока.
- **Язык.** Блок потока с `lang` нумеруется с настройками своего языка (`language_settings` из `build_structure`: подписи, словарь меток, названия указателей) и его кавычками; каждая ссылка запоминает настройки места (`ref_settings`), поэтому метка — «п. 2.1» в украинском блоке и «cl. 2.1» в английском.
- **Ссылки.** Кандидаты ID: свой поток, затем основной (вычислитель ставит ссылкам неосновного потока `track_primary`), затем без префикса; вне потоков короткий ID, не найденный в документе, ищется в основных потоках (`primaries`).
- **Заголовки неосновного потока** — `outline = False`: генератор пишет `text:p` со стилем заголовка (закладка ID и метки указателей сохраняются).
- **Сноски.** В нумеруемом неосновном потоке — `NoteInfo.label` = номер по счётчику потока; при `footnotes(restart="page"|"chapter")` метки нет (нумерует Writer) и P5316 один раз; в потоке `numbered=False` — P5304.
- **Указатели.** Записи `IndexEntry` знают поток и признак основного; оглавление документа берёт записи вне потоков и основного потока. Записи неосновного потока помечаются метками `toc:en` (`figure:en`, `table:en`) — пользовательский указатель `Contents-en` (`Figures-en`, `Tables-en`); для `|toc(track="en")` записи вне потоков получают такие же метки (`_track_indexes`). Название по умолчанию — на языке потока; неизвестный поток — P5302. Проверено в Writer: указатель обновляется с уровнями и номерами страниц.
- **Проверки соответствия (16.4, `parallel/parity.py`).** Сведения, которым нужен исходный текст (имена значений в `|(…)` и числа, записанные литералом, до слияния значений выражений с текстом), собирает вычислитель для каждого блока потока (`source_facts`, `EvaluatedSegment.facts`); ID и цели ссылок — из вычисленных блоков. Структуру (после группировки списков и построения сеток таблиц) и счётчики сравнивает структурная фаза: `_parity` после нумерации строки сегмента, P5315 — после последней таблицы окружения (`parallel_last`). Толкования: имя функции в `|(…)` не сравнивается (перевод может оформить то же значение другой функцией); число приводится к цифрам; счётчики необязательного потока не сравниваются; P5301 не выдаётся при `parity="none"`. Расхождение структуры в профиле `translation` обычно даёт и P5315 — это ожидаемо.
- **Контроль актуальности (16.5, `parallel/rev.py`).** Хеш блока потока считает вычислитель (`block_hash`) по исходному тексту разобранного блока: тело без строки `|track(…)` (у строчной формы — текст в скобках), после строки `|include` — текст фрагмента без заголовка (рекурсивно, через подготовленные вставки `prepared`), без `|comment:` и `|%`, NFC, пробелы и пустые строки свёрнуты. `_check_revs` после всех блоков сегмента сверяет `rev`: P5307 (вид, `rev` в основном потоке), P5320 (основной блок изменён), P5321 (сам блок изменён); признаки — `EvaluatedSegment.stale/changed`, они идут в выгрузку структуры. В `--review` блок неосновного потока со `status` (своим или сегмента) получает первой строкой ячейки метку `ReviewLabel` «[status]» (с «rev ≠» для устаревшего).
- **`primula parallel` (`parallel/tool.py`).** Документ анализируется как при `check`; правки — текстовые вставки и замены в исходном тексте названного файла (аргументы `|track(…)` пересобираются из исходных фрагментов аргументов с новыми `rev`/`status`; заготовка `--stub` строится по строкам основного блока через `lines.classify`). Файл пишется, только если в документе нет ошибок и сырой текст равен нормализованному (LF, NFC, без BOM) — тогда смещения совпадают и остальное не меняется. Ошибки задания — P0106, несоответствия `--check-status` — P0107 (группа P0, командная строка). Толкование: `--check-status` проверяет блоки неосновных потоков; основной поток — образец и состояния не имеет.
- **Studio и документация (16.6).** Studio показывает потоки в «Структуре» и запускает `primula parallel` из меню; при `--format json` отчёт команды идёт в stderr (stdout — JSON сообщений). В наборе `report` у `ParallelHeader` нет абзацного отступа `Body`. Пример `examples/09-parallel`, страница руководства `docs/author/09-parallel.md` с переводами, раздел справки Studio, блок шпаргалки, раздел skill.
- **Выгрузка структуры.** Элементы `parallel` (потоки, основной, профиль), `segment` (`id`, `span`, `status`), `track_block` (поток, сегмент, `status`, `rev`, `stale`, `changed`); элементы внутри блока потока — с полем `track`.

# Конвертеры через pandoc (направление 19, подпункт 19.1)

Записка о подходе к конвертации Primula в другие форматы и из них. Экспорт реализован (`primula export`, решение 139); импорт описан и не реализован.

## Почему pandoc

[pandoc](https://pandoc.org) читает и пишет десятки форматов через одно промежуточное представление — AST (дерево документа). AST сериализуется в JSON (`pandoc -t json`), его версия — `pandoc-api-version` (pandoc 3.x — 1.23). Поэтому транслятору достаточно уметь записывать этот JSON: Markdown, HTML, DOCX, LaTeX, EPUB, reStructuredText, Org, AsciiDoc и другие форматы делает pandoc. Транслятор не зависит от pandoc как от библиотеки: AST — обычный JSON, `--to json` работает и без pandoc.

Проверено с pandoc 3.10 (openSUSE Tumbleweed, 26.10.2026).

## Экспорт: `primula export FILE --to FORMAT [-o OUT]`

Абзац записывается одной строкой (`--wrap=none`: по умолчанию pandoc переносит текстовые форматы по 72 символа), автономный HTML — шириной 60em (шаблон pandoc ограничивает текст 36em — треть широкого экрана; замечание пользователя 26.10.2026). Свои аргументы pandoc — `--pandoc-arg` (повторяется, идут последними): `--pandoc-arg=-Vmaxwidth=none` — во всю ширину (своё значение `maxwidth` заменяет значение по умолчанию, а не склеивается с ним), `--pandoc-arg=--reference-doc=шаблон.docx` — стили DOCX из шаблона.

Документ вычисляется так же, как для `build`: параметры, условия, фрагменты, модули, нумерация, подписи, ссылки, сноски, таблицы с вычисленными ячейками. Затем `src/primula/export/pandoc.py` (`PandocWriter`) обходит вычисленное дерево — то же, что получает писатель ODT, — и строит AST; `--to json` записывает его, остальные форматы получает `pandoc -f json -t FORMAT -o OUT` (для HTML — `--standalone --embed-resources`: один файл с встроенными изображениями).

| Primula | AST pandoc |
| --- | --- |
| заголовок `\|<` | `Header` с номером в тексте («2. Ціна») и закладкой как идентификатором |
| пункт `\|>`, абзац | `Para` с номером пункта в начале; закладка — пустой `Span` с идентификатором |
| стиль абзаца, `\|.Стиль:` | `Div` с `custom-style` (только для `docx`, `odt`, `json`) |
| стиль символов `\|.Стиль{…}` | `Span` с `custom-style` (то же) |
| `\|*{}` `\|/{}` `\|_{}` `\|^{}` `\|,{}` `\|—{}` | `Strong`, `Emph`, `Underline`, `Superscript`, `Subscript`, `Strikeout` |
| `\|`{}` | `Code` |
| `\|"{}` | кавычки языка документа текстом («…», вложенные „…“) |
| `\|?{}` | `Span` класса `placeholder` |
| списки `\|-`, `\|#` | `BulletList`, `OrderedList` (начальный номер сохраняется) |
| таблица | `Table` из вычисленной сетки: строки заголовка и итогов, объединения, относительные ширины столбцов, отображаемый текст ячеек |
| подпись «Таблиця 1 — …», «Рисунок 1 — …» | подпись `Table` / `Figure` |
| `\|img`, `\|figure` | `Image` (путь относительно выходного файла внутри проекта, иначе абсолютный; SVG из кода — `data:`-URI), размеры — атрибуты `width`, `height` |
| ссылка `\|@` | `Link` на `#закладка` с вычисленным текстом («п. 2.1», «табл. 1.1») |
| `\|link` | `Link` |
| сноски | `Note` |
| оглавление, перечни рисунков и таблиц | заголовок и список ссылок на элементы (без номеров страниц) |
| предупреждающие блоки | таблица, как в ODT (значок и текст); остаток — `Div` класса `admonition` |
| `\|verbatim` | `CodeBlock` |
| приложение | `Header` с обозначением, подзаголовок и название |
| параллельные потоки `\|parallel` | таблица потоков, как в ODT |
| метаданные `doc.*` | `title`, `author`, `date`, `lang`, `subtitle`, `abstract`, `keywords` |

Не имеет соответствия и пропускается — разметка страниц: стили страниц, колонки, разрывы, рамки с обтеканием, колонтитулы, водяные знаки, поля номеров страниц и ссылки на страницы (предупреждение P8101 один раз на конструкцию). Ошибки: P8102 — pandoc не найден (кроме `--to json`), P8103 — pandoc завершился с ошибкой.

Ограничения прототипа:

- стили в DOCX передаются только именами (`custom-style`): pandoc создаёт одноимённые стили, их оформление задаёт шаблон (`--reference-doc` pandoc), а не модуль стилей Primula;
- предупреждающие блоки выводятся таблицей со значком, как в ODT: в Markdown это громоздкая таблица; отдельный вид для форматов без таблиц — позже;
- ширины столбцов передаются относительными долями; объединения ячеек поддерживает не каждый формат (Markdown — нет, pandoc упрощает).

## Импорт: `primula import ИСТОЧНИК [-o ВЫХОД.prml]` (19.3, первый этап — 0.4.27)

Реализован на Python (`src/primula/importer/`), а не на Lua-writer: `reader.py` — чтение через pandoc (`pandoc -f ФОРМАТ -t json --extract-media=assets`; формат по расширению: `.docx`, `.odt`, `.rtf`, `.md`/`.markdown` (GFM), `.html`, `.epub`, `.txt`; старый `.doc` pandoc не читает — его сначала переводит в DOCX LibreOffice); `convert.py` — `Converter`, дерево AST → разметка Primula; `run.py` — команда (заголовок YAML из метаданных, изображения, запись, проверка `primula check`, сводка). `tools/md_to_prml.py` — тот же `Converter` под старым именем (им собирается PDF руководства автора).

Что переносится: заголовки `|<`…, абзацы, списки `|-`/`|#` с вложением (маркеры вложенных пунктов повторяют родителей; пункт с несколькими блоками — окружение `|list:` вплоть до верхнего уровня), таблицы (объединения `span`/`rows`, выравнивание, ширины столбцов из источника), изображения `|img` с размерами в мм (EMF/WMF Word → SVG через LibreOffice, остальные — в `assets/`), рисунки с подписью `|figure`, сноски, ссылки, цитаты, код, определения. Не переносится и называется в сводке: разметка страницы (колонтитулы, поля, колонки), стили Word, исправления и комментарии, поля, формулы (остаётся текст исходника), таблица в ячейке таблицы (текст склеивается), сырая разметка. Результат — черновик; существующий файл не заменяется без `--force`; код возврата 2, если после импорта `check` находит ошибки (файл всё равно записан).

Решения пользователя (11.11.2026): набранные номера пунктов превращаются в автонумерацию `|>` (этап 2, `--keep-numbers` оставляет текст); результат — `имя.prml` рядом с источником и `assets/`; pandoc — внешняя зависимость (в Windows без pandoc импорт недоступен); порядок форматов — Markdown и HTML, затем DOCX и ODT. Образцы настоящих документов автора — `import/` (в Git не входят; тест читает их, если каталог есть): два счёта DOCX, паспорт и руководство ODT (16 изображений, 31 таблица), договор в старом DOC.

Этап 19.3.2 (0.4.28) — нормализатор структуры `src/primula/importer/normalize.py` (перед `Converter`; `--no-structure` отключает, `--keep-numbers` оставляет набранные номера текстом и ставит `number=False`). Правила, каждое называется в сводке: (1) нумерованный список из одного пункта (автонумерация заголовков Word; в ODT руководства — все 56 заголовков) — заголовок, если текст короткий (до 120 знаков, не оканчивается на `.;,:!?`), иначе пункт `|>`; вложенные нумерованные списки — следующие уровни; пустой родительский пункт продолжает нумерацию; (2) абзац, начинающийся с набранного номера («1.», «2.1.», «2.1.1)», «**2.1.** текст», «2.1.Текст»): число компонентов — уровень; заголовок (короткий, без точки в конце; для «2.1» — жирный, ЗАГЛАВНЫМИ или за ним «2.1.1») или пункт `|>`/`|>>` (уровень = компоненты минус уровень последнего заголовка); (3) короткая строка целиком жирным после первого настоящего заголовка — заголовок следующего уровня (на титульной странице — нет: «©…», строки до первого заголовка); (4) уровни заголовков без пропусков (первый — 1, не глубже последнего + 1; пустые заголовки пропускаются); (5) набранное содержание (строки «Название ….. 5» не меньше трёх подряд или список внутренних ссылок под «Зміст/Содержание/Contents») — `|toc()` с удалением названия; (6) набранные номера сверяются с нумерацией Primula (симуляция счётчиков): различия считаются в сводке, номера результата следуют структуре; Div стилей Word раскрываются. Тесты: `tests/test_import_structure.py` (14), образцы `tests/data/import/contract.md` (набранные номера, содержание) и `page.html`. На образцах автора все пять документов проверяются без ошибок (в инструкции 56 заголовков до 4 уровней, договор: первый заголовок поднят до 1).

Этап 19.3.3 (0.4.29) — стили источника (`src/primula/importer/styles.py`): DOCX читается как `docx+styles` (абзацные стили — `Div`, символьные — `Span` с `custom-style`; для ODT pandoc имён стилей не даёт). Встроенные правила: «Heading N» / «Заголовок N» / `HeadingN` → заголовок N; `Clause` и `SubClause` Primula → пункты `|>` и `|>>` (DOCX нашего экспорта возвращается с пунктами и стилями абзацев); «Quote», «Block Text», «Цитата» → `|.Quote:`; «Normal», «Body Text», «Основной текст», «List Paragraph», «Hyperlink» и т. п. — обычный абзац без записи; имена стилей `std/styles/*` (абзацных и символьных) переносятся как есть (`|.Body:`, `|.Strong{…}`). Свои соответствия — `import-styles.yaml` рядом с результатом или выше (`--styles ФАЙЛ`): `paragraphs:` / `characters:`, значения `{heading: N}`, `{clause: N}`, `{style: Имя}`, `plain`, `ignore`; файл важнее встроенных правил, ошибки файла идут в сводку. Не сопоставленный стиль остаётся обычным абзацем и называется в сводке; `--list-styles` показывает все стили источника и их судьбу без записи; `--write-styles ФАЙЛ` пишет заготовку (существующий файл — только с `--force`, P8205). Нормализатор теперь снимает набранные номера и с заголовков Header, и с пунктов-стилей (с учётом пустого якоря-закладки в начале), а уровни пунктов не пропускаются (иначе P4204). Тесты: `tests/test_import_styles.py` (7).

## Где в коде

- `src/primula/export/pandoc.py` — `PandocWriter` (дерево → AST), `run_pandoc` (вызов pandoc);
- `src/primula/importer/` — импорт: `reader.py`, `convert.py`, `run.py`; `tests/test_import.py`;
- `src/primula/cli.py` — команда `export` (`_export`);
- `tests/test_export.py` — AST без pandoc; примеры через pandoc в Markdown, HTML, DOCX, если pandoc установлен.

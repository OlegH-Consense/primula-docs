# Конвертеры через pandoc (направление 19, подпункт 19.1)

Записка о подходе к конвертации Primula в другие форматы и из них. Экспорт реализован (`primula export`, решение 139); импорт описан и не реализован.

## Почему pandoc

[pandoc](https://pandoc.org) читает и пишет десятки форматов через одно промежуточное представление — AST (дерево документа). AST сериализуется в JSON (`pandoc -t json`), его версия — `pandoc-api-version` (pandoc 3.x — 1.23). Поэтому транслятору достаточно уметь записывать этот JSON: Markdown, HTML, DOCX, LaTeX, EPUB, reStructuredText, Org, AsciiDoc и другие форматы делает pandoc. Транслятор не зависит от pandoc как от библиотеки: AST — обычный JSON, `--to json` работает и без pandoc.

Проверено с pandoc 3.10 (openSUSE Tumbleweed, 26.10.2026).

## Экспорт: `primula export FILE --to FORMAT [-o OUT]`

Абзац записывается одной строкой (`--wrap=none`: по умолчанию pandoc переносит текстовые форматы по 72 символа), автономный HTML — шириной 60em (шаблон pandoc ограничивает текст 36em — треть широкого экрана; замечание пользователя 26.10.2026). Свои аргументы pandoc — `--pandoc-arg` (повторяется, идут последними): `--pandoc-arg=-Vmaxwidth=none` — во всю ширину (своё значение `maxwidth` заменяет значение по умолчанию, а не склеивается с ним), `--pandoc-arg=--reference-doc=шаблон.docx` — стили DOCX из шаблона.

Документ вычисляется так же, как для `build`: параметры, условия, фрагменты, модули, нумерация, подписи, ссылки, сноски, таблицы с вычисленными ячейками. Затем `src/primula/export/pandoc.py` (`PandocWriter`) обходит вычисленное дерево — то же, что получает писатель ODT, — и строит AST; `--to json` записывает его, остальные форматы получает `pandoc -f json -t FORMAT -o OUT` (для HTML — `--standalone --embed-resources`: один файл с встроенными изображениями).

| Primula | AST pandoc |
| --- | --- |
| заголовок `\|<` | `Header` с номером в тексте («2. Ціна») и закладкой как идентификатором |
| пункт `\|>`, абзац | `Para` с номером пункта в начале; закладка — пустой `Span` с идентификатором |
| стиль абзаца, `\|.Стиль:` | `Div` с `custom-style` (только для `docx`, `odt`, `json`) |
| стиль символов `\|.Стиль{…}` | `Span` с `custom-style` (то же) |
| `\|*{}` `\|/{}` `\|_{}` `\|^{}` `\|,{}` `\|—{}` | `Strong`, `Emph`, `Underline`, `Superscript`, `Subscript`, `Strikeout` |
| `\|`{}` | `Code` |
| `\|"{}` | кавычки языка документа текстом («…», вложенные „…“) |
| `\|?{}` | `Span` класса `placeholder` |
| списки `\|-`, `\|#` | `BulletList`, `OrderedList` (начальный номер сохраняется) |
| таблица | `Table` из вычисленной сетки: строки заголовка и итогов, объединения, относительные ширины столбцов, отображаемый текст ячеек |
| подпись «Таблиця 1 — …», «Рисунок 1 — …» | подпись `Table` / `Figure` |
| `\|img`, `\|figure` | `Image` (путь относительно выходного файла внутри проекта, иначе абсолютный; SVG из кода — `data:`-URI), размеры — атрибуты `width`, `height` |
| ссылка `\|@` | `Link` на `#закладка` с вычисленным текстом («п. 2.1», «табл. 1.1») |
| `\|link` | `Link` |
| сноски | `Note` |
| оглавление, перечни рисунков и таблиц | заголовок и список ссылок на элементы (без номеров страниц) |
| предупреждающие блоки | таблица, как в ODT (значок и текст); остаток — `Div` класса `admonition` |
| `\|verbatim` | `CodeBlock` |
| приложение | `Header` с обозначением, подзаголовок и название |
| параллельные потоки `\|parallel` | таблица потоков, как в ODT |
| метаданные `doc.*` | `title`, `author`, `date`, `lang`, `subtitle`, `abstract`, `keywords` |

Не имеет соответствия и пропускается — разметка страниц: стили страниц, колонки, разрывы, рамки с обтеканием, колонтитулы, водяные знаки, поля номеров страниц и ссылки на страницы (предупреждение P8101 один раз на конструкцию). Ошибки: P8102 — pandoc не найден (кроме `--to json`), P8103 — pandoc завершился с ошибкой.

Ограничения прототипа:

- стили в DOCX передаются только именами (`custom-style`): pandoc создаёт одноимённые стили, их оформление задаёт шаблон (`--reference-doc` pandoc), а не модуль стилей Primula;
- предупреждающие блоки выводятся таблицей со значком, как в ODT: в Markdown это громоздкая таблица; отдельный вид для форматов без таблиц — позже;
- ширины столбцов передаются относительными долями; объединения ячеек поддерживает не каждый формат (Markdown — нет, pandoc упрощает).

## Импорт (описание; первый шаг — конвертер Markdown)

Первый шаг сделан на Python, а не на Lua: `tools/md_to_prml.py` (класс `Converter`) переводит AST pandoc в разметку Primula — заголовки `|<` с ID, абзацы, списки `|-`/`|#` (элементы из нескольких блоков — окружение `|list:`), таблицы `|table` (ширины столбцов — по длине текста, не уже самого длинного слова), код — `|verbatim` в стиле `Preformatted` (собственный маркер конца, если в коде есть строка `|end`), внутристрочные формы, `|link` (внутренние ссылки — `|link("#id")` по карте якорей), сноски; экранирование `||`, `|{`, `|}`. Им собирается PDF руководства автора (`tools/author_docs.py pdf`); путь к команде `primula import` — тот же конвертер с читателями pandoc для DOCX/ODT/HTML.

Цель — получить из документа другого формата (DOCX, ODT, Markdown, HTML) черновик `.prml`: текст, заголовки, нумерованные пункты, списки, таблицы, сноски, ссылки, изображения — для дальнейшей правки автором. Возможный путь — **пользовательский writer pandoc на Lua**:

```sh
pandoc договір.docx -t tools/pandoc/primula-writer.lua -o договір.prml --extract-media=img
```

- pandoc читает исходный формат в тот же AST; writer на Lua (`Writer` и функции по видам элементов, https://pandoc.org/custom-writers.html) обходит AST и пишет разметку Primula: `Header` → `|<`…, `Para` → абзац, `OrderedList` → `|#`, `BulletList` → `|-`, `Table` → `|table:` с `|:` / `|&`, `Note` → `|footnote{…}`, `Link` → `|link("url"){…}`, `Image` → `|img("путь")`, `Strong`/`Emph` → `|*{}`/`|/{}`, `Code` → ``|`{}``, `Span`/`Div` с `custom-style` → `|.Стиль{…}` / `|.Стиль:`.
- Экранирование: символ `|` в тексте → `||`; фигурные скобки в теле форм — `|{`, `|}`.
- Нумерация: номера пунктов, набранные вручную («2.1.»), распознаются по шаблону в начале абзаца и становятся `|>` / `|>>`; ссылки «п. 2.1» в тексте остаются текстом (автор заменяет их на `|@` с `id=`).
- Заголовок YAML: `doc.title`, `doc.language`, `doc.creator` из метаданных pandoc.
- Проверка результата — `primula check`; writer не обязан давать документ без предупреждений, но должен давать документ без ошибок разбора.
- Альтернатива для DOCX/ODT с богатой структурой — фильтр Lua, который сначала нормализует AST (объединяет стили Word в стили Primula по таблице соответствий проекта), затем тот же writer.

Отложенный `primula convert` из Kit (перевод документов Kit в Primula) остаётся отдельной задачей направления 19.

## Где в коде

- `src/primula/export/pandoc.py` — `PandocWriter` (дерево → AST), `run_pandoc` (вызов pandoc);
- `src/primula/cli.py` — команда `export` (`_export`);
- `tests/test_export.py` — AST без pandoc; примеры через pandoc в Markdown, HTML, DOCX, если pandoc установлен.

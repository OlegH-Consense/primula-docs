# Проект из нескольких документов

Когда документов несколько — договор, акты, счета, письма одной компании, — общие данные, стили и повторяющиеся тексты собирают в проект. Проект — каталог с файлом `project.p.prml`. Транслятор находит его сам, поднимаясь от документа вверх (до каталога с `.git`).

```
договори-2026/
  project.p.prml        параметры, стили, ключи, цели сборки
  договір.prml
  акт.prml
  fragments/            тексты для |include (*.f.prml)
  lib/                  макросы и функции для |import (*.m.prml)
  styles/               свой модуль стилей (*.s.prml)
  data/                 CSV, YAML, JSON
```

## Файл проекта

```prml file=project.p.prml
---
kind: project
name: "Договори 2026"
language: uk-UA
styles: [styles/компанія.s.prml]
doc_defaults: {organization: "ТОВ «Виконавець»", creator: "Відділ договорів"}
params:
  місто: "м. Харків"
  виконавець: {назва: "ТОВ «Виконавець»", код: "00000000", директор: "П. П. Петренко"}
  ставка_пдв: 20
targets:
  - {source: договір.prml, output: out/договір.odt, pdf: true}
---
```

- `params:` — общие параметры. Документ видит их по имени (`|(місто)`) и как `|(project.місто)`. Параметр документа с тем же именем заменяет значение проекта для этого документа.
- `doc_defaults:` — метаданные ODT по умолчанию для всех документов; ключ `doc:` документа заменяет их поштучно.
- `styles:` — модули стилей проекта; они подключаются ко всем документам.
- `targets:` — цели пакетной сборки.

Свой модуль стилей проекта построен на наборе комплекта (страница [«Стили»](07-styles.md)):

```prml file=styles/компанія.s.prml
---
kind: styles
extends: std/styles/business
paragraphs:
  Реквізити: {parent: Details, keep_together: true}
---
```

## Документ проекта

```prml
---
doc: {title: "Договір про надання послуг"}
---
|(виконавець.назва), |(місто). Ставка ПДВ — |(percent(ставка_пдв)).

|.Реквізити: Код ЄДРПОУ |(виконавець.код)
```

Документ не называет ни стилей, ни языка: всё приходит из проекта.

## Фрагменты: общий текст

Фрагмент `*.f.prml` — кусок текста для вставки. Параметры фрагмента объявляются в его заголовке и передаются аргументами `|include`:

```prml file=fragments/гарантія.f.prml
---
params: {місяців: 12}
---
|> Гарантійний строк становить |(місяців) |(plural(місяців, "місяць", "місяці", "місяців")).
```

```prml
|< Гарантія
|include("fragments/гарантія.f.prml", місяців=24)
```

- Путь — от файла с командой; расширение можно опустить (`fragments/гарантія`).
- Имена, определённые во фрагменте, документу не видны; чтобы передать значение наружу, фрагмент экспортирует его: `|export(строк=…)`, функцию — декоратором `@export` над `def`, готовый макрос — `|export("підпис")` (страница [«Код»](10-code.md#модули-и-фрагменты)).
- Часть фрагмента помечают `|part("назва"):` … `|end part` и вставляют `|include("файл", part="назва")`.

## Модули: макросы и функции

Модуль `*.m.prml` содержит только определения — макросы `|def`, функции и данные в `|code:`. Текста в нём нет.

```prml file=lib/підписи.m.prml
|def підпис(сторона, особа):
|.SignatureRole: |(сторона)
|.SignatureLine: ______________ |(особа)
|enddef
```

```prml
|import("lib/підписи")
|підписи.підпис("Виконавець", виконавець.директор)
```

После `|import("lib/підписи")` определения доступны как `підписи.имя`; `|import("lib/підписи", "підпис")` — без префикса, `alias="п"` — под коротким именем. Экспортировать из модуля ничего не нужно: открыты все имена, кроме начинающихся с `_`. `|import` документа действует и в его фрагментах. Модуль вычисляется один раз на сборку.

### Общая библиотека нескольких проектов

Путь `|import` не выходит за корень проекта, но символическая ссылка, созданная внутри проекта, может вести к общему каталогу (решение 136):

```sh
ln -s ../shared-lib lib     # в корне проекта
```

После этого `|import("lib/ціни")` берёт модуль из `../shared-lib`. Сборка выдаёт предупреждение P2639 с именем ссылки и её целью: каталог вне проекта не попадает в архив исходников, поэтому храните его вместе с проектами (или в том же репозитории). Пути внутри библиотеки отсчитываются от `lib/…`, и `../` в тексте по-прежнему не выводит за корень. В отчёте и сообщениях файл записывается как `lib/ціни.m.prml`.

## Данные из файлов

```csv file=data/акти.csv
номер,дата,сума
1,2026-10-31,5400.00
2,2026-11-30,5400.00
```

```prml
|code:
акти = load_csv("data/акти.csv", types={"номер": "decimal", "дата": "datetime", "сума": "money"})
|end
|for(а in акти):
|- Акт № |(а.номер) від |(fmt_date(а.дата, "short")) на |(money(а.сума, "UAH")).
|endfor
```

Без `types=` все значения CSV — строки (коды с ведущими нулями не портятся). YAML и JSON читают `load_yaml` и `load_json`; отображения становятся записями с доступом через точку.

Таблицы LibreOffice Calc и Excel читают `load_ods` и `load_xlsx` (решение 138): лист — `sheet="Позиції"` или номер с 1, диапазон — `range="A1:D20"`, первая строка — имена полей (`header=False` — поля `A`, `B`, …), `types` — как у CSV.

```prml skip
|code:
позиції = load_ods("data/позиції.ods", sheet="Позиції", types={"ціна": "money"})
|end
```

Формулы не вычисляются: берётся результат, сохранённый в файле, — сохраните таблицу в Calc или Excel после правки. Числа — `decimal` до 15 значащих цифр, даты — `datetime`; ошибка в ячейке (`#DIV/0!`) или формула без результата останавливают сборку с именем листа и ячейки. Файлы `.xls` сначала сохраните как `.xlsx` или `.ods`.

Весь текстовый файл одной строкой возвращает `load_text` (решение 140): UTF-8, концы строк — LF, без разбора. Так удобно держать вне документа SVG рисунка, знака или схемы и вставлять его через `svg=`:

```prml skip
|img(svg=load_text("img/знак.svg"), width="12mm")
```

## Сборка проекта

```sh
primula build project.p.prml --pdf      # все цели проекта
primula check project.p.prml            # проверка всех целей без записи
primula build договір.prml              # один документ (с параметрами и стилями проекта)
primula check project.p.prml --dump-project   # описание проекта в JSON
```

Цели можно порождать кодом: секция кода файла проекта (после заголовка) читает данные и вызывает `build()` — например, по акту на каждую строку CSV:

```prml skip
---
kind: project
---
for row in load_csv("data/акти.csv", types={"номер": "decimal", "сума": "money"}):
    build("акт.prml", params={"номер": row.номер, "сума": row.сума}, output=f"out/акт-{row.номер}.odt", pdf=True)
```

Ошибка одной цели не останавливает остальные. Полный пример с договором, актами из CSV, картой ключей и сводным пакетом — `examples/07-project`.

## Экспорт в Markdown, HTML, DOCX

`primula export` записывает вычисленный документ в другие форматы через [pandoc](https://pandoc.org): номера пунктов, ссылки, сноски, таблицы и подписи сохраняются, разметка страниц (колонтитулы, колонки, номера страниц) — нет.

```sh
primula export договір.prml                    # договір.md
primula export договір.prml --to html          # один файл HTML с изображениями
primula export договір.prml --to docx          # стили абзацев — по именам (custom-style)
primula export договір.prml --to json          # AST pandoc, pandoc не нужен
```

## Сводный документ

Несколько документов собираются в один ODT командой `|document`:

```prml skip
|document("договір.prml", scope="договір")
|document("акт.prml", scope="акт1", params={"номер": 1})
```

Каждая часть начинается с новой страницы, нумеруется в своей области и вычисляется отдельно; оглавление и нумерация страниц — общие. Ссылка на другую часть — по полному ID: `|@("акт1:перелік")`.

## Ссылки на другой документ

Акт может ссылаться на пункт договора, если договор назван в `ref_documents:` проекта, а акт перечисляет его в `references:` своего заголовка: `|@("оплата", "label")` в акте даст «п. 2.2» договора. Текст ссылки берётся из реестра договора, который транслятор обновляет при сборке.

## Карта ключей

Ключи `keys:` проекта дают ресурсам и фрагментам имена: `|img(key="логотип")`, `|include(key="умови.оплата")`. Цель сборки может подменить ключ (`keys:` у цели) — так один текст собирается с разными логотипами или вариантами условий.

## Проект заказа

Для серии заказов по одному договору делают проект в подкаталоге с `extends: ../../project.p.prml`: он наследует параметры, стили, ключи и документы базового проекта и добавляет свои данные заказа. В Studio — «Файл → Создать → Проект заказа».

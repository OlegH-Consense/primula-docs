# Код: диалект Python

Код Primula пишется как Python: выражения `|(…)`, аргументы команд, блоки `|code:`, функции и макросы. Синтаксис — подмножество Python 3.11, но смысл кое-где другой: числа десятичные, глобальные имена неизменяемые, вывода (`print`) нет. Эта страница перечисляет то, что надо знать автору, который знает Python; что работает как в Python, здесь не повторяется.

Полный пример с таблицами «выражение → Primula → Python 3» — `examples/10-code` (документ `code.prml`, фрагменты по темам, файлы ошибок `forbidden.prml` и `mistakes.prml`). Пример показывает исходный текст: код и определения в PDF не печатаются, поэтому PDF читается вместе с исходником. Функции библиотеки — в приложении [«Функции выражений»](generated/functions.md).

## Где пишется код

| Запись | Назначение |
| --- | --- |
| `\|(сума * 2)` | вывести значение в текст |
| `\|table(cols=["*", "30mm"])` | аргументы команд — выражения |
| `\|if(n == 1){день}\|else{дні}`, `\|for(p in позиції){…}` | условие и цикл; тело — разметка, а не код |
| `\|code:` … `\|end` | определения, функции, расчёты |
| `\|let(n=5)` | определение посреди текста |
| `\|def підпис(роль):` … `\|enddef` | макрос: функция, тело которой — разметка |

## Числа: decimal вместо int и float

Целое число и число с точкой без экспоненты — `decimal`: точное десятичное число до 64 значащих цифр, которое помнит количество знаков после запятой. Отдельного `int` нет: `type(5)` — `"decimal"`. Двоичный `float` получается только из литерала с экспонентой (`1.5e3`) или `float(x)`; `decimal` вместе с `float` даёт `float`.

| Выражение | Primula | Python 3 |
| --- | --- | --- |
| `0.1 + 0.2 == 0.3` | `True` | `False` |
| `2.20 * 3` | `6.60` | `6.6000000000000005` |
| `7 / 2` | `3.5` (`decimal`) | `3.5` (`float`) |
| `round(2.5)` | `3` | `2` |
| `round(2.675e0, 2)` | `2.68` | `2.67` |
| `10 ** 70` | ошибка P2309 | целое из 71 цифры |
| `True + 1` | ошибка P2304 | `2` |

Округление одно для всех чисел — половина от нуля, `float` округляется по своей десятичной записи. Деньги — только `decimal`: денежные функции не принимают `float`.

```prml
Ціна: |(money(2.20 * 3, "UAH")), разом із ПДВ |(money(round(2.20 * 3 * 1.2, 2), "UAH")).
```

## Строки

Строка — символы Unicode, как в Python 3: `len("Київ") == 4`. Отличия:

- есть только методы из списка спецификации (раздел 12.10): `split`, `join`, `strip`, `replace`, `startswith`, `find`, `upper`, `lower`, `title`, `zfill`, `format` и некоторые другие; `center`, `partition`, `encode` — ошибка P2313;
- f-строки — по синтаксису Python 3.11: внутри фигурных скобок нельзя кавычки того же вида, что вокруг строки (P1208); пишите `f"{d['k']}"`;
- `"{0.name}".format(r)` — ошибка P2330; поле записи читается по ключу: `"{0[name]}"`;
- спецификация формата (`f"{x:,.2f}"`) — английская и языка документа не знает; для текста есть `num()`, `money()`, `fmt_date()`.

```prml
|code:
сума = 1234.5
|end
Python-формат: |(f"{сума:,.2f}"); формат документа: |(num(сума, 2)).
```

## Списки, кортежи, словари

Как в Python, включая генераторы списков и словарей и распаковку. Отличия:

- множеств нет: `{1, 2}` — ошибка P2101; уникальность — словарём или `not in`;
- операторов `|`, `&`, `^`, `<<`, `~` нет; словари объединяют `{**a, **b}`;
- `is` — только с `None` (P2103);
- ключ словаря — неизменяемое значение; `float` и длина ключом быть не могут (P2317); `5` и `5.00` — один ключ;
- `range()` и `reversed()` возвращают список;
- `lambda` нет: функция для `key=` — обычный `def`.

```prml
|code:
def мінус(x):
    return -x
порядок = sorted([3, 1, 2], key=мінус)
|end
|(join_list([str(x) for x in порядок]))
```

## Записи

Запись (`record`) — неизменяемое значение с полями: `r.назва` или `r["назва"]`. Записями становятся параметры заголовка YAML, данные проекта, результаты `load_csv`, `load_yaml`, `load_json`. В Python похож `namedtuple`, но запись — не последовательность:

- `"назва" in r` и `len(r)` — ошибки; поле проверяют `hasattr(r, "назва")`;
- отсутствующее поле — ошибка P2314; `getattr(r, "ціна", 0)` даёт значение по умолчанию;
- новая запись с изменённым полем — `r.replace(кількість=4)`; в словарь — `dict(r)`.

```prml
---
doc: {language: uk-UA}
params:
  сторона: {назва: "ТОВ «Альфа»", код: "12345678"}
---
|(сторона.назва), ІПН: |(getattr(сторона, "ІПН", None) or "—").
```

YAML читается по правилам Primula: `15.00` — `decimal` с двумя знаками, дата без кавычек — `datetime`.

## Даты и длины

Дата и момент — один встроенный тип `datetime`, без `import`; точность — секунда, поясов нет.

- `дата + 30`, `дата - 30` — сдвиг на сутки; `дата - дата` — число суток (`decimal`), а не `timedelta`;
- `hours(36)`, `weeks(2)` — числа суток: `дата + hours(36)`; календарные месяцы — `add_months(дата, 1)` (31 января + 1 месяц = 28 февраля);
- `weekday` — атрибут от 1 (понедельник) до 7, а не метод от 0;
- в текст дата выводится `fmt_date(дата, "contract")`.

Длина — число с единицей: `10*mm` или `"10mm"`; константы `mm`, `cm`, `pt`, `inch` (не `in`). Результат — в единице левого операнда, сравнение — с допуском 0,001 мм.

```prml
|code:
підписано = date(2026, 10, 12)
оплата = підписано + 10
|end
Оплата до |(fmt_date(оплата, "contract")) — через |(оплата - підписано) днів, |(fmt_date(add_months(підписано, 1), "long")) — через місяць.
```

## Функции

`def` с умолчаниями, `*args`, `**kwargs`, параметрами только по имени, рекурсией, вложенными функциями и замыканиями; внутри функции переменные изменяемы, есть `while`. Отличия:

- нет `lambda`, генераторов (`yield`), `global`, `nonlocal`; декоратор единственный — `@export` (раздел «Модули и фрагменты»);
- значения по умолчанию вычисляются один раз и замораживаются: ловушка Python `def f(x, acc=[])` здесь — ошибка P2318 при первом `append`;
- глобальный список, переданный в функцию, тоже заморожен: строится новый список;
- вместо предела рекурсии Python — лимиты: глубина 500, 20 с на одно вычисление, 10 000 000 элементов.

```prml
---
doc: {language: uk-UA}
params:
  позиції:
    - {назва: "Папір", кількість: 20, ціна: 120.50}
    - {назва: "Ручки", кількість: 100, ціна: 15.00}
---
|code:
def рядки(позиції):
    result = []
    for i, p in enumerate(позиції, 1):
        result.append(record(n=i, назва=p.назва, сума=p.кількість * p.ціна))
    return result
|end
|table(cols=["10mm", "*", "35mm"]):
|: № |& Найменування |& Сума, грн
|for(р in рядки(позиції)):
|: |(р.n) |& |(р.назва) |& |(num(р.сума, 2))
|endfor
|end table
```

## Глобальные имена: ленивые и неизменяемые

Это второе большое отличие после чисел. Python выполняет модуль сверху вниз и позволяет переприсвоить имя. В Primula определения верхнего уровня — `x = …`, `def`, `|let`, параметры заголовка — собираются со всего файла заранее, вычисляются при первом обращении и замораживаются.

- Порядок в тексте не важен: имя можно использовать выше его определения.
- Повторное определение — ошибка P2203, `x += 1` на верхнем уровне — P2105, цикл определений — P2204. Параметр заголовка тоже нельзя переопределить в коде.
- Определение, которое никто не читает, не вычисляется — и его ошибка не проявится, пока имя не понадобится.
- Остальные операторы верхнего уровня (`for`, `if`, вызовы) — действия: выполняются после сбора определений, а имена внутри них локальны (предупреждение P2501).
- Условное значение — условное выражение: `ставка = 20 if платник_пдв else 0`.
- Накопление — генератор списка или функция, а не `append` в цикле верхнего уровня (P2318).

```prml
|code:
разом = ціна * кількість
ціна = 250.00
кількість = 4
ставка = 20 if разом > 500 else 0
|end
Разом |(num(разом, 2)), ПДВ |(ставка) %.
```

```prml error=P2203
|code:
x = 1
x = 2
|end
```

## Модули и фрагменты

**Модуль** (`.m.prml`, `|import`) содержит только определения. Все его имена без `_` в начале открыты, экспортировать ничего не надо; имя с `_` закрыто по-настоящему (`модуль._имя` — ошибка).

```prml file=lib/ціни.m.prml
|code:
_ставка = 20

def з_пдв(сума, ставка=_ставка):
    return round(сума * (100 + ставка) / 100, 2)
|end
```

| Подключение | Обращение |
| --- | --- |
| `\|import("lib/ціни")` | `ціни.з_пдв(…)`, макрос — `\|ціни.ім'я(…)` |
| `\|import("lib/ціни", "з_пдв")` | `з_пдв(…)` без префикса |
| `\|import("lib/ціни", alias="ц")` | `ц.з_пдв(…)` (`as` — ключевое слово Python) |

`|import` документа действует и во фрагментах, которые документ подключает; `|import` внутри фрагмента — только в этом фрагменте. Путь пишется от файла с командой.

```prml
|import("lib/ціни")
Разом із ПДВ: |(num(ціни.з_пдв(1000.00), 2)) грн.
```

**Фрагмент** (`.f.prml`, `|include`) — текст документа со своими определениями, и они закрыты: один фрагмент можно подключить дважды без конфликта. Документ видит только экспортированное (решение 135):

| Запись во фрагменте | Что экспортируется |
| --- | --- |
| `@export` над `def f(…)` верхнего уровня `\|code:` | функция под своим именем |
| `@export(name="g")` над `def _f(…)` | функция под именем `g`; `_f` остаётся закрытой |
| `\|export("підпис", "f")` | уже определённые имена: макросы `\|def`, функции, `\|let` |
| `\|let(x=…, export=True)`, `\|export(x=…)` | новое значение |

```prml file=fragments/знижки.f.prml
---
kind: fragment
---
|code:
@export
def знижка(сума, відсоток):
    return round(сума * (100 - відсоток) / 100, 2)
|end
|def рядок(назва, сума):
|(назва) — |(num(сума, 2)) грн
|enddef
|export("рядок")
```

```prml
|include("fragments/знижки")
|рядок("Папір зі знижкою", знижка(2410.00, 5))
```

Если два фрагмента экспортируют одно имя, конфликт решается при подключении: `|include(…, ns="f")` кладёт экспорт в `f.*`, `rename={…}` переименовывает. `@export` вне фрагмента — ошибка P2610, над вложенной функцией — P2106, в модуле — предупреждение P2638 (там всё и так открыто). Функции, которыми пользуются несколько документов, место в модуле; из фрагмента экспортируют то, что относится к его тексту.

## Значения в тексте и макросы

Вывода нет: значение попадает в документ только выражением `|(…)`, и тип решает, как.

- Строка, число, дата, разметка (`content`) вставляются. Дробное число или дата без оформления — предупреждение P2604: оформляйте `num()`, `money()`, `fmt_date()`.
- `None`, `bool`, список, словарь, запись — ошибка P2603, а не «None» или «[1, 2]», как дал бы `str()`. Необязательное значение — `|(x or "—")`, список — `join_list()`.
- Разметка непрозрачна: `markup("…") + "…"` — ошибка; строки сначала соединяют, потом вызывают `markup()`.
- Функция из `|code:`, вызванная как команда `|f(…)`, вставляет свой результат; макрос `|def` получает тело вызова параметром `body`.

```prml error=P2603
|(None)
```

```prml
|code:
def жирно(текст):
    return markup("|*{" + текст + "}")
|end
|def позначка(текст, body):
|.Note: |*{|(текст):} |(body)
|enddef
|позначка("Увага"):
Текст із |жирно("виділенням").
|end
```

## Чего в ядре нет

Документ должен собираться одинаково на любой машине, поэтому в ядре нет ввода-вывода (кроме `load_*`), часов (`build_date()` фиксируется `--build-date`), случайных чисел и доступа к внутренностям Python. Запрещены `import` (модули подключаются `|import` в разметке), `class` (данные — `record`), `try`/`raise` (ошибка останавливает сборку с позицией; `fail("…")` — намеренная ошибка), `lambda`, `yield`, `async`, `global`, `nonlocal`, `del`, `with`, множества, побитовые операторы, аннотации, `else` у циклов, декораторы кроме `@export`, имена вида `__class__`. Всё это находится ещё при разборе кода, до вычисления; полный список с заменами — в примере (`forbidden.prml`) и в разделе 12.2 спецификации.

```prml error=P2101
|code:
квадрат = lambda x: x * x
|end
```

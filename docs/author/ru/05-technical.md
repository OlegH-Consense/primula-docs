# Техническая документация

Руководства, инструкции, технические описания оформляются набором стилей `std/styles/technical` (или `report` — для отчётов по ДСТУ 3008). Ниже — средства, которые нужны именно техническим документам: предупреждения, варианты для разных исполнений изделия, сокращения, указатель, рисунки.

## Предупреждения и примечания

`|!("вид")` — смысловая разметка: автор называет вид, а сигнальное слово на языке документа, цвет и оформление берутся из стилей.

| Вид | Слово (uk) | Когда |
| --- | --- | --- |
| `danger` | НЕБЕЗПЕКА | неминуемая угроза жизни |
| `warning` | ПОПЕРЕДЖЕННЯ | возможная угроза жизни или тяжёлая травма |
| `caution` | ОБЕРЕЖНО | возможная лёгкая травма |
| `notice` | УВАГА | возможное повреждение имущества |
| `note` | Примітка | пояснение |
| `tip` | Порада | рекомендация |

```prml
|!("warning", hazard="Висока напруга", consequence="Ураження електричним струмом"):
Перед обслуговуванням від'єднайте пристрій від мережі.

|- Вимкніть автоматичний вимикач.
|- Перевірте відсутність напруги.
|end!

|!("notice") Не встановлюйте пристрій поблизу джерел тепла.

|!("note") Значення наведено для температури 20 °C.
|!("note") Допуск — ±5 %.
```

- Строчная форма `|!("вид") текст` — блок из одного абзаца; окружение `|!(…):` … `|end!` — из нескольких абзацев и списков.
- У `danger` и `warning` нужен `hazard=` (вид и источник опасности); без него проверка предупредит.
- Несколько `note` подряд объединяются в группу «Примітки:» с нумерацией.

## Варианты для разных исполнений

Один исходный текст обслуживает несколько исполнений изделия. Свойства исполнения перечисляются в параметре `features`, а условные части помечаются `when=`:

```prml
---
doc: {title: "Настанова з експлуатації", language: uk-UA}
styles: [std/styles/technical]
params:
  модель: "X300"
  features: [wifi]
---
|< Підключення
|> Під'єднайте кабель живлення.
|>(when=has("wifi")) Підключіть пристрій до мережі Wi-Fi.
|>(when=has("bluetooth")) Увімкніть Bluetooth на телефоні.
|table(header=1, cols=["*", "30%"]):
|: Параметр |& Значення
|: Напруга |& 230|~В
|:(when=модель == "X300") Потужність |& 2,2|~кВт
|end table
|if(has("wifi")):
|< Бездротова мережа
|> Пристрій підтримує стандарт 802.11n.
|endif
```

- `when=` есть у любой блоковой команды, окружения и строки таблицы; `|if(…):` … `|endif` — у произвольной группы блоков.
- `has("wifi")` истинно, если `wifi` есть в `features`. Набор свойств задают заголовок документа, проект или цель сборки проекта (`params: {features: [wifi, bluetooth]}` в `targets`): так из одного текста собираются настановы всех исполнений. Параметр командной строки `--param` списков не принимает.
- Удалённые части не попадают в ODT; нумерация, оглавление и ссылки считаются по оставшемуся тексту. Ссылка на удалённую часть — ошибка.
- `primula build настанова.prml --review` собирает все варианты сразу и помечает каждую условную часть её условием (зелёным — включена в текущем исполнении, красным — нет), а на страницы ставит водяной знак «НЕ ДЛЯ ВИПУСКУ». Так проверяют весь текст одним файлом.

## Сокращения

```prml
|abbr("ПЗ", "програмне забезпечення") встановлюється з диска.
Оновлення |abbr("ПЗ") виконується автоматично.
|list_of("abbr", title="ПЕРЕЛІК СКОРОЧЕНЬ")
```

При первом употреблении выводится «програмне забезпечення (ПЗ)», дальше — только «ПЗ». Падеж расшифровки в этом месте — `text="програмного забезпечення"`. `|list_of("abbr")` строит перечень сокращений таблицей.

## Указатель, оглавление, перечни

```prml
|toc(max_level=2, title="ЗМІСТ")
|< Живлення
Напруга|index("напруга живлення") подається через адаптер.
|list_of("index", title="ПОКАЖЧИК")
```

Оглавление, перечни рисунков и таблиц (`|list_of("figure")`, `|list_of("table")`) и алфавитный указатель — обновляемые указатели Writer; номера страниц в них заполняет Writer или транслятор при сборке PDF.

## Рисунки

```prml
|figure(svg='<svg xmlns="http://www.w3.org/2000/svg" width="40mm" height="20mm"><rect x="1" y="1" width="38" height="18" fill="none" stroke="black"/></svg>', id="рис-схема"):
Схема підключення
|end figure
Див. |@("рис-схема", "label").
```

- `|figure(путь или svg=…, id=…):` … `|end figure` — нумерованный рисунок; тело — подпись («Рисунок 1 — Схема підключення»). `|img(…)` — изображение без номера и подписи.
- Путь к файлу — относительно документа: `|figure("assets/схема.svg", width="120mm")`. Форматы — PNG, JPEG, SVG.
- `svg=` — изображение из строки SVG, вычисленной кодом (график, шкала, QR-код из функции модуля).
- Размер — `width=` или `height=`; размеры по стилю — `style="Illustration"` (наборы `business`, `letter`).

## Текст программ и интерфейс

Набор `technical` даёт стили для элементов интерфейса и команд:

```prml
---
doc: {title: "Інструкція", language: uk-UA}
styles: [std/styles/technical]
---
|list("StepList"):
|# Натисніть |.Key{Ctrl+S}.
|# Виберіть |.MenuItem{Файл → Зберегти} і вкажіть файл |.FileName{звіт.odt}.
|end list
|.StepResult: Файл буде збережено.

|.Preformatted: primula check звіт.prml
```

Символьные `Key`, `MenuItem`, `FileName`, `Command`, `Variable`; абзацные `Preformatted`, `ProgramOutput`, `StepResult`, `DefinitionTerm`/`DefinitionText`; список шагов `StepList`; таблица `TableRevisions` для листа регистрации изменений. Полный перечень — приложение [«Стили комплекта»](generated/styles.md). Текст, который нужно сохранить буква в букву (листинг с символами `|`), пишут в `|verbatim:` … `|end`.

## Общие фрагменты и ключи

Повторяющиеся тексты (общие меры безопасности, гарантия) выносят во фрагменты `*.f.prml` и подключают `|include`; в проекте их можно подменять по исполнению через карту ключей `keys:` — страница [«Проект»](06-project.md). Полный пример — `examples/03-manual` и `examples/06-safety`.

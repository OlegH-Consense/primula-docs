# Библиотеки: разработка и подключение

Библиотека Primula — каталог с модулями `.m.prml` и их данными, который используют несколько проектов: проверка реквизитов, имена в падежах, графики платежей, QR платежа. Её разрабатывают, проверяют и выпускают отдельно от транслятора и от документов: библиотека — это обычный текст Primula, она не меняет язык и не требует сборки транслятора.

Готовый образец — `examples/11-library`: библиотека `shared/ua-iban` (IBAN UA: проверка, группы по четыре знака, построение) и проект `project/`, который подключает её символической ссылкой.

## Что может библиотека

Модуль содержит только определения: функции и константы в `|code:`, макросы `|def`, `|import` других модулей (раздел [«Модули: макросы и функции»](06-project.md#модули-макросы-и-функции)). Ему доступно всё ядро — диалект Python (страница [«Код: диалект Python»](10-code.md)) — и функции стандартной библиотеки: числа и деньги, слова и падежи, даты и рабочие дни, `load_csv`, `load_yaml`, `load_json`, изображение из строки SVG (`img(svg=…)`).

Чего у модуля нет, и что делать:

| Нет | Вместо этого |
| --- | --- |
| кода Python, `import`, ввода-вывода, сети, часов | данные — файлы рядом с модулем (`load_yaml("data/…")`), дата — аргументом функции |
| `doc.*` документа (модуль вычисляется один раз на сборку) | язык и дату документ передаёт аргументом (`lang="uk"`); функции стандартной библиотеки внутри модуля сами следуют языку документа |
| `ord()`, `chr()`, побитовых операций | позиция в строке-алфавите: `"ABC…".find(ch)`; таблицы значений |
| `assert` | `fail("…")` — останавливает сборку с сообщением и местом вызова |
| тяжёлых вычислений | цикл ядра выполняет порядка десятков тысяч шагов в секунду, лимит — 20 с на вычисление; алгоритм на сотни тысяч шагов (QR-код, хеш) просят как функцию транслятора, а библиотека строит поверх неё |

## Устройство каталога

```text
ua-iban/                 библиотека (свой репозиторий или каталог)
  README.md              назначение, версия, лицензия, функции, источники правил
  project.p.prml         корень для тестов: tests/ импортирует ../iban
  iban.m.prml            публичный модуль: имя файла — имя пространства (iban.*)
  _tables.m.prml         вспомогательный модуль (необязательно)
  data/                  данные модуля: YAML, CSV, JSON
  tests/iban-test.prml   документы-тесты
  run-tests.sh           primula check для каждого теста
```

- Имена без `_` в начале — интерфейс библиотеки; имена с `_` закрыты (`iban._digits` — ошибка). Меняйте закрытые имена свободно, открытые — только с новой версией.
- Первая строка тела функции — строка-описание на английском, как комментарии кода: `"""IBAN in groups of four."""`. Её показывает исходник, в дальнейшем — подсказки Studio (направление Д3).
- Версия — константа `VERSION = "0.1.0"` в главном модуле и запись в README; несовместимое изменение — новая старшая цифра.
- Файл проекта `project.p.prml` нужен тестам: без него корень — каталог теста, и `|import("../iban")` выходит за корень (P2613). Проект, который подключает библиотеку, этот файл не читает.
- Пути `load_*` и `|import` внутри библиотеки — от файла модуля, без `../` за пределы каталога библиотеки.

## Модуль

```prml file=lib/iban.m.prml
---
kind: module
---
|code:
VERSION = "0.1.0"
_LETTERS = "ABCDEFGHIJKLMNOPQRSTUVWXYZ"


def normalized(text):
    """IBAN without spaces, in capitals."""
    return "".join(text.split()).upper()


def problem(text):
    """Why the text is not an IBAN UA, or "" if it is valid."""
    s = normalized(text)
    if not s.startswith("UA") or len(s) != 29 or not s[2:].isdigit():
        return "очікується UA і 27 цифр"
    digits = "".join([c if c.isdigit() else str(_LETTERS.find(c) + 10) for c in s[4:] + s[:4]])
    return "" if int(digits) % 97 == 1 else "не збігається контрольне число"


def check(text):
    """The normalized IBAN; a wrong one stops the build with the reason."""
    reason = problem(text)
    if reason:
        fail(f"IBAN «{text}»: {reason}")
    return normalized(text)
|end
```

Ошибку данных документа библиотека сообщает через `fail()`: сборка останавливается с сообщением библиотеки, местом `fail` в модуле и строкой документа, откуда пришёл вызов. Для мягкой проверки рядом даётся функция, которая возвращает причину (`problem`) или `True`/`False`.

## Тесты

Тест — обычный документ: код сравнивает результаты с ожидаемыми и вызывает `fail()` при первом расхождении. Вызовы на верхнем уровне `|code:` — действия, они выполняются при каждой проверке.

```prml
|import("lib/iban")
|code:
def expect(name, got, wanted):
    if got != wanted:
        fail(f"{name}: отримано {repr(got)}, очікувалося {repr(wanted)}")


expect("check", iban.check("ua21 3223 1300 0002 6007 2335 6600 1"), "UA213223130000026007233566001")
expect("problem", iban.problem("UA223223130000026007233566001"), "не збігається контрольне число")
|end
Бібліотека ua-iban |(iban.VERSION).
```

`primula check tests/iban-test.prml` завершается кодом 0, если все ожидания совпали, и кодом 2 с сообщением `fail` иначе; `run-tests.sh` образца проверяет все `tests/*.prml`. Проверяйте граничные случаи и ошибки, а не только удачный путь: неправильная контрольная цифра, неверная длина, чужая страна.

## Подключение к проекту

Три способа, от удобного для разработки к самому воспроизводимому:

| Способ | Как | Когда |
| --- | --- | --- |
| символическая ссылка | `ln -s ../shared/ua-iban lib` в корне проекта | разработка, несколько проектов на одной машине; сборка выдаёт предупреждение P2639 |
| копия | каталог библиотеки копируется в `lib/` проекта | выпуск документа: проект собирается одинаково без внешних каталогов |
| подмодуль Git | `git submodule add <url> lib/ua-iban` | проект в Git: версия библиотеки закреплена коммитом |

```sh
cd мій-проєкт
ln -s ../shared/ua-iban lib
```

```prml skip
|import("lib/iban")
IBAN: |(iban.grouped(рахунок)) (код банку |(iban.bank_code(рахунок))).
```

Ссылка проверяется по записанному пути (решение 136): `lib` внутри проекта может вести куда угодно, а `../` в тексте документа и модуля по-прежнему не выходит за корень. Файлы библиотеки попадают в отчёт сборки и в `--embed-sources` как `lib/iban.m.prml`, с хешами — по отчёту видно, какой версией библиотеки собран документ.

## Данные с датой действия

Ставки, справочники и календари меняются со временем, а старый документ должен собираться так же, как при выпуске. Храните значения с датой начала действия и выбирайте по дате, которую передаёт документ (дата документа, а не дата сборки):

```yaml file=lib/data/rates.yaml
vat:
  - {from: 2011-01-01, value: 20}
```

```prml
|code:
_rates = load_yaml("lib/data/rates.yaml")


def vat_on(day):
    """VAT rate on a date; the document passes doc.created or the contract date."""
    found = None
    for r in _rates.vat:
        if r["from"] <= day:
            found = r["value"]
    if found is None:
        fail(f"немає ставки на {fmt_date(day, 'short')}")
    return found
|end
Ставка ПДВ: |(vat_on(date(2026, 10, 26))) %.
```

Новое значение добавляется строкой с новой датой; старые строки не меняются.

## Выпуск

- README: назначение, функции с примерами, версия, лицензия, источники правил (стандарт, закон, постановление) — и дата, на которую они сверены.
- Перед выпуском: `run-tests.sh` без ошибок; номер в `VERSION` и в README совпадает; изменения описаны.
- Не добавляйте в библиотеку реальные персональные данные и реквизиты в примерах — используйте заведомо учебные значения.

Для разработки библиотеки с помощью AI есть skill `skills/primula-library`: он ведёт ту же схему — модуль, тесты, проверка транслятором.

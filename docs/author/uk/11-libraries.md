# Бібліотеки: розробка й підключення

Бібліотека Primula — каталог із модулями `.m.prml` та їхніми даними, яким користуються кілька проєктів: перевірка реквізитів, імена у відмінках, графіки платежів, QR платежу. Її розробляють, перевіряють і випускають окремо від транслятора й від документів: бібліотека — звичайний текст Primula, вона не змінює мову й не потребує збирання транслятора.

Готовий зразок — `examples/11-library`: бібліотека `shared/ua-iban` (IBAN UA: перевірка, групи по чотири знаки, побудова) і проєкт `project/`, який підключає її символічним посиланням.

## Що може бібліотека

Модуль містить лише визначення: функції й константи в `|code:`, макроси `|def`, `|import` інших модулів (розділ [«Модулі: макроси й функції»](06-project.md#модулі-макроси-й-функції)). Йому доступне все ядро — діалект Python (сторінка [«Код: діалект Python»](10-code.md)) — і функції стандартної бібліотеки: числа й гроші, слова й відмінки, дати й робочі дні, `load_csv`, `load_yaml`, `load_json`, зображення з рядка SVG (`img(svg=…)`).

Чого в модуля немає і що робити:

| Немає | Натомість |
| --- | --- |
| коду Python, `import`, вводу-виводу, мережі, годинника | дані — файли поруч із модулем (`load_yaml("data/…")`), дата — аргументом функції |
| `doc.*` документа (модуль обчислюється один раз на збирання) | мову й дату документ передає аргументом (`lang="uk"`); функції стандартної бібліотеки всередині модуля самі дотримуються мови документа |
| `ord()`, `chr()`, побітових операцій | позиція в рядку-абетці: `"ABC…".find(ch)`; таблиці значень |
| `assert` | `fail("…")` — зупиняє збирання з повідомленням і місцем виклику |
| важких обчислень | цикл ядра виконує близько десятків тисяч кроків за секунду, ліміт — 20 с на обчислення; алгоритм на сотні тисяч кроків (QR-код, геш) просять як функцію транслятора, а бібліотека будує поверх неї |

## Будова каталогу

```text
ua-iban/                 бібліотека (свій репозиторій або каталог)
  README.md              призначення, версія, ліцензія, функції, джерела правил
  project.p.prml         корінь для тестів: tests/ імпортує ../iban
  iban.m.prml            публічний модуль: ім'я файла — ім'я простору (iban.*)
  _tables.m.prml         допоміжний модуль (необов'язково)
  data/                  дані модуля: YAML, CSV, JSON
  tests/iban-test.prml   документи-тести
  run-tests.sh           primula check для кожного тесту
```

- Імена без `_` на початку — інтерфейс бібліотеки; імена з `_` закриті (`iban._digits` — помилка). Закриті імена змінюйте вільно, відкриті — лише з новою версією.
- Перший рядок тіла функції — рядок-опис англійською, як коментарі коду: `"""IBAN in groups of four."""`. Його показує вихідний текст, надалі — підказки Studio (напрям Д3).
- Версія — константа `VERSION = "0.1.0"` у головному модулі й запис у README; несумісна зміна — нова старша цифра.
- Файл проєкту `project.p.prml` потрібен тестам: без нього корінь — каталог тесту, і `|import("../iban")` виходить за корінь (P2613). Проєкт, який підключає бібліотеку, цього файла не читає.
- Шляхи `load_*` і `|import` усередині бібліотеки — від файла модуля, без `../` за межі каталогу бібліотеки.

## Модуль

```prml file=lib/iban.m.prml
---
kind: module
---
|code:
VERSION = "0.1.0"
_LETTERS = "ABCDEFGHIJKLMNOPQRSTUVWXYZ"


def normalized(text):
    """IBAN without spaces, in capitals."""
    return "".join(text.split()).upper()


def problem(text):
    """Why the text is not an IBAN UA, or "" if it is valid."""
    s = normalized(text)
    if not s.startswith("UA") or len(s) != 29 or not s[2:].isdigit():
        return "очікується UA і 27 цифр"
    digits = "".join([c if c.isdigit() else str(_LETTERS.find(c) + 10) for c in s[4:] + s[:4]])
    return "" if int(digits) % 97 == 1 else "не збігається контрольне число"


def check(text):
    """The normalized IBAN; a wrong one stops the build with the reason."""
    reason = problem(text)
    if reason:
        fail(f"IBAN «{text}»: {reason}")
    return normalized(text)
|end
```

Помилку даних документа бібліотека повідомляє через `fail()`: збирання зупиняється з повідомленням бібліотеки, місцем `fail` у модулі й рядком документа, звідки прийшов виклик. Для м'якої перевірки поруч дається функція, яка повертає причину (`problem`) або `True`/`False`.

## Тести

Тест — звичайний документ: код порівнює результати з очікуваними й викликає `fail()` за першої розбіжності. Виклики на верхньому рівні `|code:` — дії, вони виконуються під час кожної перевірки.

```prml
|import("lib/iban")
|code:
def expect(name, got, wanted):
    if got != wanted:
        fail(f"{name}: отримано {repr(got)}, очікувалося {repr(wanted)}")


expect("check", iban.check("ua21 3223 1300 0002 6007 2335 6600 1"), "UA213223130000026007233566001")
expect("problem", iban.problem("UA223223130000026007233566001"), "не збігається контрольне число")
|end
Бібліотека ua-iban |(iban.VERSION).
```

`primula check tests/iban-test.prml` завершується кодом 0, якщо всі очікування збіглися, і кодом 2 з повідомленням `fail` інакше; `run-tests.sh` зразка перевіряє всі `tests/*.prml`. Перевіряйте граничні випадки й помилки, а не лише вдалий шлях: неправильна контрольна цифра, хибна довжина, чужа країна.

## Підключення до проєкту

Три способи, від зручного для розробки до найбільш відтворюваного:

| Спосіб | Як | Коли |
| --- | --- | --- |
| символічне посилання | `ln -s ../shared/ua-iban lib` у корені проєкту | розробка, кілька проєктів на одній машині; збирання видає попередження P2639 |
| копія | каталог бібліотеки копіюється в `lib/` проєкту | випуск документа: проєкт збирається однаково без зовнішніх каталогів |
| підмодуль Git | `git submodule add <url> lib/ua-iban` | проєкт у Git: версію бібліотеки закріплено комітом |

```sh
cd мій-проєкт
ln -s ../shared/ua-iban lib
```

```prml skip
|import("lib/iban")
IBAN: |(iban.grouped(рахунок)) (код банку |(iban.bank_code(рахунок))).
```

Посилання перевіряється за записаним шляхом (рішення 136): `lib` усередині проєкту може вести будь-куди, а `../` у тексті документа й модуля, як і раніше, не виходить за корінь. Файли бібліотеки потрапляють до звіту збирання й до `--embed-sources` як `lib/iban.m.prml`, із гешами — за звітом видно, якою версією бібліотеки зібрано документ.

## Дані з датою дії

Ставки, довідники й календарі змінюються з часом, а старий документ має збиратися так само, як під час випуску. Зберігайте значення з датою початку дії й вибирайте за датою, яку передає документ (дата документа, а не дата збирання):

```yaml file=lib/data/rates.yaml
vat:
  - {from: 2011-01-01, value: 20}
```

```prml
|code:
_rates = load_yaml("lib/data/rates.yaml")


def vat_on(day):
    """VAT rate on a date; the document passes doc.created or the contract date."""
    found = None
    for r in _rates.vat:
        if r["from"] <= day:
            found = r["value"]
    if found is None:
        fail(f"немає ставки на {fmt_date(day, 'short')}")
    return found
|end
Ставка ПДВ: |(vat_on(date(2026, 10, 26))) %.
```

Нове значення додається рядком із новою датою; старі рядки не змінюються.

## Випуск

- README: призначення, функції з прикладами, версія, ліцензія, джерела правил (стандарт, закон, постанова) — і дата, на яку їх звірено.
- Перед випуском: `run-tests.sh` без помилок; номер у `VERSION` і в README збігається; зміни описано.
- Не додавайте до бібліотеки реальних персональних даних і реквізитів у прикладах — використовуйте свідомо навчальні значення.

Для розробки бібліотеки за допомогою AI є skill `skills/primula-library`: він веде ту саму схему — модуль, тести, перевірка транслятором.

# Імпорт документів із Word та інших форматів

Готовий договір, інструкція чи акт лежать у Word, ODT, Markdown або HTML. Команда `primula import` переводить їх у чернетку Primula: текст, заголовки, нумеровані пункти, списки, таблиці, зображення, виноски та посилання. Це початок роботи, а не її кінець: чернетку треба переглянути й довести — але передруковувати не потрібно.

Зразок — `examples/16-import`: три джерела (`договір.md`, `інструкція.html`, `акт.docx`) і результати імпорту поруч.

## Команда й вікно Studio

```sh
primula import договір.docx                 # договір.prml і assets/ поруч
primula import інструкція.odt -o doc/інструкція.prml --language uk-UA
primula import договір.docx --list-styles   # лише перелічити стилі Word, нічого не писати
```

У Studio — «Файл → Імпортувати документ…» (і «Імпортувати в Primula…» в контекстному меню файла): вікно питає шлях результату, мову, чи розпізнавати структуру, і показує зведення.

Джерело читає pandoc, тому він має бути встановлений (https://pandoc.org); старий двійковий `.doc` pandoc не читає — його спершу перетворює на DOCX LibreOffice. У збірці для Windows pandoc немає: там імпорт недоступний. Формат визначається за розширенням: `.docx`, `.odt`, `.doc`, `.rtf`, `.md`, `.html`, `.epub`, `.txt`; інший читач — `--from`.

Наявний результат не замінюється без `--force`. Після запису команда сама запускає `primula check` і друкує зведення: що перетворено, що пропущено та результат перевірки. Код повернення 2 — у чернетці лишилися помилки (файл усе одно записано).

## Що переноситься

| У джерелі | У Primula |
| --- | --- |
| абзаци, жирний, курсив, підкреслений, верхній і нижній індекс, закреслений | абзаци, `\|*{}`, `\|/{}`, `\|_{}`, `\|^{}`, `\|,{}`, `\|—{}` |
| заголовки | `\|<`, `\|<<`… |
| списки з вкладенням | `\|-`, `\|#`, `\|--`, `\|#-`… (абзаци всередині пункту — оточення `\|list:`) |
| таблиці, об'єднання комірок, вирівнювання, ширини | `\|table` з `\|&(span=…, rows=…, align=…)` |
| зображення | `\|img` з розмірами в мм, файли — в `assets/` (EMF і WMF Word — у SVG через LibreOffice) |
| виноски, посилання, цитати, код | `\|footnote{}`, `\|link`, `\|.Quote:`, `\|verbatim` |
| метадані | `doc.title`, `doc.creator`; назва береться ще з першого рядка ВЕЛИКИМИ літерами або з першого заголовка |

Не переносяться й називаються у зведенні: верстка сторінки (колонтитули, поля, колонки), пряме форматування без стилю, виправлення й коментарі, поля Word, формули (лишається їхній текст), таблиця всередині комірки таблиці (текст склеюється), сира розмітка.

## Як розпізнається структура

У документах із Word номери пунктів часто набрані руками, а заголовки — просто жирні рядки. Імпорт відновлює структуру, щоб номери й посилання потім робила Primula:

- **Набрані номери.** Абзац «2.1. Покупець оплачує…» стає пунктом `|>`, «2.1.1.» — `|>>`, короткий рядок «2. Ціна і порядок розрахунків» — заголовком `|<`. Номер прибирається з тексту: нумерацію дає Primula. Набрані номери звіряються з нумерацією результату; якщо вони не збіглися (пропущено «1.2», номер «4.» після «2.»), зведення каже скільки — номери результату йдуть за структурою.
- **Автонумерація Word.** Нумерований список з одного пункту — так Word і ODT зберігають нумерацію заголовків — стає заголовком (короткий текст) або пунктом (довге речення); вкладені списки — наступними рівнями.
- **Жирні рядки.** Короткий рядок цілком жирним після першого заголовка — заголовок наступного рівня; рядки титульної сторінки до першого заголовка («©…», назва) лишаються текстом.
- **Зміст.** Набраний зміст («Назва ….. 5» поспіль або список посилань під «Зміст») замінюється на `|toc()`.
- **Рівні без пропусків.** Перший заголовок — першого рівня, далі не глибше за «попередній + 1»; пункти — так само.

Правила евристичні: вони помиляються там, де автор документа не дотримувався жодних правил. Тому зведення називає, що зроблено, а `--no-structure` вимикає розпізнавання, `--keep-numbers` лишає набрані номери в тексті (заголовки тоді без номерів Primula, `number=False`).

## Стилі Word

DOCX зберігає імена стилів абзаців і знаків, і імпорт зіставляє їх зі стилями Primula:

- заголовки Word («Heading 2», «Заголовок 2») — заголовки; `Clause` і `SubClause` — пункти (так повертається DOCX, зроблений `primula export`); «Quote», «Цитата» — `|.Quote:`; звичайні стилі («Normal», «Основний текст», «Hyperlink») — звичайний абзац; імена стилів Primula (`Body`, `Requisites`, `Strong`…) лишаються як є;
- власні стилі описуються в `import-styles.yaml` — поруч із результатом або в каталозі вище (або `--styles ФАЙЛ`):

```yaml
paragraphs:
  "Пункт": {clause: 1}          # абзаци стилю «Пункт» — пункти |>
  "Заголовок договору": {heading: 1}
  "Реквізити": {style: Requisites}   # |.Requisites: …
  "Службовий": ignore           # абзац пропускається
characters:
  "Важливе": {style: Strong}    # |.Strong{…}
```

Значення: `{heading: N}`, `{clause: N}`, `{style: Ім'я}`, `plain` (звичайний абзац), `ignore`. Незіставлений стиль лишається звичайним абзацом і називається у зведенні; `--list-styles` показує всі стилі джерела, `--write-styles import-styles.yaml` пише заготовку для них. У ODT та інших форматів pandoc імен стилів не дає — там працюють лише правила структури.

## Результат

Типова чернетка — документ без параметрів і посилань:

```prml
---
doc:
  title: "ДОГОВІР ПОСТАВКИ № 15"
  language: uk-UA
---
ДОГОВІР ПОСТАВКИ № 15

|toc()

|< Предмет договору

|> Постачальник зобов'язується поставити, а Покупець — прийняти й оплатити товар.

|< Ціна і порядок розрахунків

|> Покупець оплачує товар протягом 10 банківських днів.

|>> Зміна ціни можлива лише за згодою сторін.
```

## Що зробити після імпорту

1. Виконати `primula check` (команда вже зробила це) і виправити попередження; зібрати `primula build` і подивитися результат.
2. Замінити посилання «п. 2.1» у тексті на `|@("id")` з `id=` у пункта (див. сторінку [«Договір»](02-contract.md)): набрані номери в посиланнях самі не оновлюються.
3. Винести дані (сторони, дати, суми) в параметри заголовка чи проєкту й підставляти `|(ім'я)`.
4. Призначити стилі з набору комплекту (сторінка [«Стилі»](07-styles.md)) замість `|.Body:` і звичайних абзаців; підписи та реквізити — таблицею або стилем.
5. Якщо документів багато — скласти `import-styles.yaml` за результатами `--list-styles` і імпортувати решту тим самим файлом.
6. Для вичитки й доопрацювання результату — AI у Studio («Запитати AI…» з рецептами «вичитка», «терміни договору»): правки застосовуються з перевіркою транслятором.

Межі: імпорт — чернетка. Він не вгадує змісту (який рядок — реквізити, а який — умова), не знає верстки й не замінює вичитки.

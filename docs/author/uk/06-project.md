# Проєкт із кількох документів

Коли документів кілька — договір, акти, рахунки, листи однієї компанії, — спільні дані, стилі й повторювані тексти збирають у проєкт. Проєкт — каталог із файлом `project.p.prml`. Транслятор знаходить його сам, піднімаючись від документа вгору (до каталогу з `.git`).

```
договори-2026/
  project.p.prml        параметри, стилі, ключі, цілі збирання
  договір.prml
  акт.prml
  fragments/            тексти для |include (*.f.prml)
  lib/                  макроси й функції для |import (*.m.prml)
  styles/               власний модуль стилів (*.s.prml)
  data/                 CSV, YAML, JSON
```

## Файл проєкту

```prml file=project.p.prml
---
kind: project
name: "Договори 2026"
language: uk-UA
styles: [styles/компанія.s.prml]
doc_defaults: {organization: "ТОВ «Виконавець»", creator: "Відділ договорів"}
params:
  місто: "м. Харків"
  виконавець: {назва: "ТОВ «Виконавець»", код: "00000000", директор: "П. П. Петренко"}
  ставка_пдв: 20
targets:
  - {source: договір.prml, output: out/договір.odt, pdf: true}
---
```

- `params:` — спільні параметри. Документ бачить їх за іменем (`|(місто)`) і як `|(project.місто)`. Параметр документа з тим самим іменем замінює значення проєкту для цього документа.
- `doc_defaults:` — типові метадані ODT для всіх документів; ключ `doc:` документа замінює їх поштучно.
- `styles:` — модулі стилів проєкту; вони підключаються до всіх документів.
- `targets:` — цілі пакетного збирання.

Власний модуль стилів проєкту побудовано на наборі комплекту (сторінка [«Стилі»](07-styles.md)):

```prml file=styles/компанія.s.prml
---
kind: styles
extends: std/styles/business
paragraphs:
  Реквізити: {parent: Details, keep_together: true}
---
```

## Документ проєкту

```prml
---
doc: {title: "Договір про надання послуг"}
---
|(виконавець.назва), |(місто). Ставка ПДВ — |(percent(ставка_пдв)).

|.Реквізити: Код ЄДРПОУ |(виконавець.код)
```

Документ не називає ні стилів, ні мови: усе приходить із проєкту.

## Фрагменти: спільний текст

Фрагмент `*.f.prml` — шматок тексту для вставлення. Параметри фрагмента оголошуються в його заголовку й передаються аргументами `|include`:

```prml file=fragments/гарантія.f.prml
---
params: {місяців: 12}
---
|> Гарантійний строк становить |(місяців) |(plural(місяців, "місяць", "місяці", "місяців")).
```

```prml
|< Гарантія
|include("fragments/гарантія.f.prml", місяців=24)
```

- Шлях — від файлу з командою; розширення можна пропустити (`fragments/гарантія`).
- Імена, визначені у фрагменті, документові не видно; щоб передати значення назовні, фрагмент експортує його: `|export(строк=…)`, функцію — декоратором `@export` над `def`, готовий макрос — `|export("підпис")` (сторінка [«Код»](10-code.md#модулі-й-фрагменти)).
- Частину фрагмента позначають `|part("назва"):` … `|end part` і вставляють `|include("файл", part="назва")`.

## Модулі: макроси й функції

Модуль `*.m.prml` містить лише визначення — макроси `|def`, функції й дані в `|code:`. Тексту в ньому немає.

```prml file=lib/підписи.m.prml
|def підпис(сторона, особа):
|.SignatureRole: |(сторона)
|.SignatureLine: ______________ |(особа)
|enddef
```

```prml
|import("lib/підписи")
|підписи.підпис("Виконавець", виконавець.директор)
```

Після `|import("lib/підписи")` визначення доступні як `підписи.ім'я`; `|import("lib/підписи", "підпис")` — без префікса, `alias="п"` — під коротким іменем. Експортувати з модуля нічого не треба: відкриті всі імена, крім тих, що починаються з `_`. `|import` документа діє й у його фрагментах. Модуль обчислюється один раз на збирання.

### Спільна бібліотека кількох проєктів

Шлях `|import` не виходить за корінь проєкту, але символічне посилання, створене всередині проєкту, може вести до спільного каталогу (рішення 136):

```sh
ln -s ../shared-lib lib     # у корені проєкту
```

Після цього `|import("lib/ціни")` бере модуль із `../shared-lib`. Збирання видає попередження P2639 з іменем посилання та його ціллю: каталог поза проєктом не потрапляє до архіву вихідних текстів, тому зберігайте його разом із проєктами (або в тому самому репозиторії). Шляхи всередині бібліотеки відраховуються від `lib/…`, і `../` у тексті, як і раніше, не виводить за корінь. У звіті й повідомленнях файл записується як `lib/ціни.m.prml`.

## Дані з файлів

```csv file=data/акти.csv
номер,дата,сума
1,2026-10-31,5400.00
2,2026-11-30,5400.00
```

```prml
|code:
акти = load_csv("data/акти.csv", types={"номер": "decimal", "дата": "datetime", "сума": "money"})
|end
|for(а in акти):
|- Акт № |(а.номер) від |(fmt_date(а.дата, "short")) на |(money(а.сума, "UAH")).
|endfor
```

Без `types=` усі значення CSV — рядки (коди з провідними нулями не псуються). YAML і JSON читають `load_yaml` і `load_json`; відображення стають записами з доступом через крапку.

Таблиці LibreOffice Calc і Excel читають `load_ods` і `load_xlsx` (рішення 138): аркуш — `sheet="Позиції"` або номер з 1, діапазон — `range="A1:D20"`, перший рядок — імена полів (`header=False` — поля `A`, `B`, …), `types` — як у CSV.

```prml skip
|code:
позиції = load_ods("data/позиції.ods", sheet="Позиції", types={"ціна": "money"})
|end
```

Формули не обчислюються: береться результат, збережений у файлі, — збережіть таблицю в Calc або Excel після правки. Числа — `decimal` до 15 значущих цифр, дати — `datetime`; помилка в клітинці (`#DIV/0!`) або формула без результату зупиняють збирання з назвою аркуша й клітинки. Файли `.xls` спершу збережіть як `.xlsx` або `.ods`.

Увесь текстовий файл одним рядком повертає `load_text` (рішення 140): UTF-8, кінці рядків — LF, без розбору. Так зручно тримати поза документом SVG малюнка, знака чи схеми і вставляти його через `svg=`:

```prml skip
|img(svg=load_text("img/знак.svg"), width="12mm")
```

## Збирання проєкту

```sh
primula build project.p.prml --pdf      # усі цілі проєкту
primula check project.p.prml            # перевірка всіх цілей без запису
primula build договір.prml              # один документ (з параметрами й стилями проєкту)
primula check project.p.prml --dump-project   # опис проєкту в JSON
```

Цілі можна породжувати кодом: секція коду файлу проєкту (після заголовка) читає дані й викликає `build()` — наприклад, по акту на кожен рядок CSV:

```prml skip
---
kind: project
---
for row in load_csv("data/акти.csv", types={"номер": "decimal", "сума": "money"}):
    build("акт.prml", params={"номер": row.номер, "сума": row.сума}, output=f"out/акт-{row.номер}.odt", pdf=True)
```

Помилка однієї цілі не зупиняє інших. Повний приклад із договором, актами з CSV, картою ключів і зведеним пакетом — `examples/07-project`.

## Експорт у Markdown, HTML, DOCX

`primula export` записує обчислений документ в інші формати через [pandoc](https://pandoc.org): номери пунктів, посилання, виноски, таблиці й підписи зберігаються, розмітка сторінок (колонтитули, колонки, номери сторінок) — ні.

```sh
primula export договір.prml                    # договір.md
primula export договір.prml --to html          # один файл HTML із зображеннями
primula export договір.prml --to docx          # стилі абзаців — за іменами (custom-style)
primula export договір.prml --to json          # AST pandoc, pandoc не потрібен
```

## Швидкий перегляд: primula view

`primula view` збирає документ у тимчасовому каталозі (ODT і PDF, як `build --pdf`), відкриває PDF у переглядачі й видаляє файли, коли вікно закрито. Якщо збірка не вдалась, замість PDF показується журнал збірки — у терміналі або у вікні. Команда потрібна для файлових менеджерів: коротке ім'я `primula-view` лежить поруч із `primula`.

```sh
primula view договір.prml
primula view договір.prml --param номер=12 --viewer "okular --unique"
primula view --text договір.prml | less        # без LibreOffice: простий текст через pandoc, близько секунди
```

Переглядач береться з `--viewer`, потім зі змінної `PRIMULA_VIEWER`, потім це переглядач PDF стільниці (okular, evince, atril, xreader, zathura, mupdf, qpdfview), потім `xdg-open`. Заданий і впізнаний переглядач очікується; `xdg-open` повертається одразу, тому файли залишаються в `$XDG_RUNTIME_DIR/primula-view` і видаляються пізніше. LibreOffice стартує з профілем у `~/.cache/primula`, що трохи прискорює повторні запуски; основний час забирає верстка в LibreOffice, тому для документа на кілька сторінок чекайте кілька секунд, а для швидкого погляду на текст використовуйте `--text`.

F3 у Midnight Commander — у `~/.config/mc/mc.ext.ini`:

```ini
[primula]
Extensions=prml
View=primula-view %f
```

Для тексту в самому терміналі: `View=%view{ascii} primula view --text %f`.

## Зведений документ

Кілька документів збираються в один ODT командою `|document`:

```prml skip
|document("договір.prml", scope="договір")
|document("акт.prml", scope="акт1", params={"номер": 1})
```

Кожна частина починається з нової сторінки, нумерується у своїй області й обчислюється окремо; зміст і нумерація сторінок — спільні. Посилання на іншу частину — за повним ID: `|@("акт1:перелік")`.

## Посилання на інший документ

Акт може посилатися на пункт договору, якщо договір названо в `ref_documents:` проєкту, а акт перелічує його в `references:` свого заголовка: `|@("оплата", "label")` в акті дасть «п. 2.2» договору. Текст посилання береться з реєстру договору, який транслятор оновлює під час збирання.

## Карта ключів

Ключі `keys:` проєкту дають ресурсам і фрагментам імена: `|img(key="логотип")`, `|include(key="умови.оплата")`. Ціль збирання може підмінити ключ (`keys:` у цілі) — так один текст збирається з різними логотипами чи варіантами умов.

## Проєкт замовлення

Для серії замовлень за одним договором роблять проєкт у підкаталозі з `extends: ../../project.p.prml`: він успадковує параметри, стилі, ключі й документи базового проєкту та додає власні дані замовлення. У Studio — «Файл → Створити → Проєкт замовлення».

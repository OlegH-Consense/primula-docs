# Стилі

Оформлення документа задають стилі, а не текст: шрифт, відступи, інтервали, рамки таблиць, поля сторінок. У тексті пишеться лише *що* це — заголовок, пункт, реквізити, — а *як* це виглядає, вирішує модуль стилів. Тому той самий документ можна надрукувати інакше, підключивши інший набір, а правка оформлення не зачіпає тексту.

## Вибір набору

У комплекті транслятора — набори стилів для типових документів:

| Набір | Для чого | Основа |
| --- | --- | --- |
| `std/styles/default` | підключається сам, якщо стилі не названо | — |
| `std/styles/business` | договори, акти, рахунки, протоколи; ДСТУ 4163:2020 | `default` |
| `std/styles/letter` | службові листи; ДСТУ 4163:2020 | `business` |
| `std/styles/technical` | настанови, інструкції, технічні описи | `default` |
| `std/styles/report` | звіти у сфері науки і техніки; ДСТУ 3008:2015 | `default` |
| `std/styles/compact` | пам'ятки, довідки, шпаргалки | `default` |

Документ називає набір одним рядком заголовка:

```prml
---
doc: {title: "Акт", language: uk-UA}
styles: [std/styles/business]
---
|.DocumentTitle: АКТ № 14
```

Основу (`default`) перелічувати не треба: набір сам її підключає. Стилі кожного набору, їхні властивості й типовий шрифт — у додатку [«Стилі комплекту»](generated/styles.md); зразки — документи `examples/08-styles` (їх можна зібрати й переглянути PDF).

## Застосування стилів у тексті

| Запис | Що робить |
| --- | --- |
| `\|.DatePlace: м. Харків` | стиль абзацу для абзацу цього рядка |
| `\|.Note:` … `\|end.Note` | стиль абзацу для кількох абзаців (оточення) |
| `\|.DefinedTerm{Замовник}` | символьний стиль для фрагмента всередині рядка |
| `\|*{…}`, `\|/{…}`, ``\|`{…}`` | напівжирний, курсив, моноширинний — це теж символьні стилі (`Strong`, `Emphasis`, `Code`) |
| `\|table(style="TableCompact")` | стиль таблиці |
| `\|list("DashList")` | стиль наступного списку |

Ім'я стилю в `|.Ім'я` — ідентифікатор: воно не перекладається й не змінюється під час вичитування тексту. Невідоме ім'я — помилка з позицією.

Заголовки, пункти, списки, таблиці й підписи отримують стилі автоматично — їх задає прив'язка конструкцій у модулі стилів (`Heading1`…`Heading6`, `Clause`, `BulletList`, `TableGrid`, `TableCaption` …). Змінити стиль конструкції до кінця оточення можна командою `|set`:

```prml
|set(list="DashList")
|- перший пункт;
|- другий пункт.
```

Пряме форматування `|fmt(bold=True){…}` теж є, але дає попередження: разове оформлення губиться під час зміни набору, а однакові місця оформлюються по-різному. Якщо оформлення повторюється — заведіть стиль.

## Власний модуль стилів

Не правте наборів комплекту — зробіть власний модуль над набором. Він містить лише відмінності й називає основу ключем `extends`:

```prml file=styles/компанія.s.prml
---
kind: styles
extends: std/styles/business
defaults: {font: Roboto, size: 11pt}
paragraphs:
  Body:        {line_height: "120%"}
  Реквізити:   {parent: Details, keep_together: true}
characters:
  Акцент:      {bold: true, color: "#1F4E79"}
tables:
  TableServices: {header_background: "#DDE6F0"}
---
```

```prml
---
doc: {title: "Договір", language: uk-UA}
styles: [styles/компанія.s.prml]
---
Текст з |.Акцент{акцентом}.

|.Реквізити: Код ЄДРПОУ 00000000
```

- Документ (чи проєкт) називає лише власний модуль: основа та її основа (`business` → `default`) підключаються самі.
- Властивість стилю з тим самим іменем доповнює стиль набору: `Body: {line_height: "120%"}` змінює лише інтервал, решта лишається від набору.
- Новий стиль успадковує наявний через `parent`.
- Шрифт усього документа змінюється одним рядком `defaults: {font: …}`. Шрифт має бути встановлений там, де документ відкривають чи збирають PDF.

Групи стилів у модулі: `paragraphs` (стилі абзаців), `characters` (символьні), `tables`, `lists`, `blocks`, `frames` (розміри й розміщення зображень), `pages` (сторінки). Властивості — `font`, `size`, `bold`, `align`, `line_height`, `space_before`, `space_after`, `left`, `first_line`, `keep_with_next` та інші; повний перелік — розділ 11.3 специфікації. Підказки щодо властивостей і стилів дає Studio (наведення миші, `Ctrl+Space`).

## Шари

Якщо стилі названо в кількох місцях, вони накладаються шарами, від раннього до пізнього:

1. модулі зі `styles:` проєкту;
2. модулі, передані під час збирання `--style ФАЙЛ`;
3. модулі зі `styles:` документа;
4. стилі, визначені кодом самого документа.

Пізніший шар доповнює й перевизначає ранні. Основа модуля (`extends`) — шар одразу перед ним. Які шари справді підключено й звідки взявся кожен стиль, показує панель «Стилі» Studio або `primula check документ.prml --dump-styles`.

## Сторінки й колонтитули

Поля й розмір сторінки — стиль сторінки (`pages:` модуля, типово `Portrait`; у наборах є `Landscape`). Колонтитули задаються в коді модуля стилів або в документі:

```prml
|footer("Portrait"):
|.Footer: Договір № П-2026/017 — сторінка |field.page з |field.pages
|end footer
```

Зміна сторінки з цього місця — `|page(style="Landscape")`, розрив — `|newpage`.

## Перехід з ODT Markdown Kit

Діловий набір Kit 1.2 (`business-styles.yaml`) перенесено в `std/styles/business` і `default` під тими самими іменами, крім наведених нижче:

| Kit | Primula |
| --- | --- |
| `TocTitle`, `TocEntry` | `ContentsTitle`, `Contents1`…`Contents6` |
| `StrongText`, `EmphasisText`, `UnderlinedText` | `Strong`, `Emphasis`, `Underline` (короткі форми `\|*{}`, `\|/{}`, `\|_{}`) |
| `DraftPlaceholder` | `Placeholder` (коротка форма `\|?{…}`) |
| `BodyRoboto`, `FontCarlito` і подібні | немає: шрифт задається `defaults: {font: …}` власного модуля |
| `Recipient`, `LetterSubject`, `Salutation` | у наборі `letter` |
| `Approval` | у `business`, на 100 мм від лівого поля (ДСТУ 4163:2020) |
| `NumberedList` з літерами `a)` | `NumberedList` (`1.`, `1.`, `a)`), `LetterList` — літери мови документа «а)», `LatinLetterList` — «a)» |
| пресети зображень `Logo`, `Illustration` … | стилі фреймів з тими самими іменами: `\|img(…, style="Logo")` |

Номери пунктів і посилання в Kit писалися текстом; у Primula їх ставить транслятор (`|>`, `|@("id")`), а стиль `Clause` застосовується до пунктів сам.

# Код: діалект Python

Код Primula пишеться як Python: вирази `|(…)`, аргументи команд, блоки `|code:`, функції й макроси. Синтаксис — підмножина Python 3.11, але зміст подекуди інший: числа десяткові, глобальні імена незмінні, виведення (`print`) немає. Ця сторінка перелічує те, що треба знати авторові, який знає Python; що працює як у Python, тут не повторюється.

Повний приклад із таблицями «вираз → Primula → Python 3» — `examples/10-code` (документ `code.prml`, фрагменти за темами, файли помилок `forbidden.prml` і `mistakes.prml`). Приклад показує вихідний текст: код і визначення в PDF не друкуються, тому PDF читається разом із вихідним текстом. Функції бібліотеки — у додатку [«Функції виразів»](generated/functions.md).

## Де пишеться код

| Запис | Призначення |
| --- | --- |
| `\|(сума * 2)` | вивести значення в текст |
| `\|table(cols=["*", "30mm"])` | аргументи команд — вирази |
| `\|if(n == 1){день}\|else{дні}`, `\|for(p in позиції){…}` | умова й цикл; тіло — розмітка, а не код |
| `\|code:` … `\|end` | визначення, функції, розрахунки |
| `\|let(n=5)` | визначення посеред тексту |
| `\|def підпис(роль):` … `\|enddef` | макрос: функція, тіло якої — розмітка |

## Числа: decimal замість int і float

Ціле число й число з крапкою без експоненти — `decimal`: точне десяткове число до 64 значущих цифр, яке пам'ятає кількість знаків після коми. Окремого `int` немає: `type(5)` — `"decimal"`. Двійковий `float` виходить лише з літерала з експонентою (`1.5e3`) або `float(x)`; `decimal` разом із `float` дає `float`.

| Вираз | Primula | Python 3 |
| --- | --- | --- |
| `0.1 + 0.2 == 0.3` | `True` | `False` |
| `2.20 * 3` | `6.60` | `6.6000000000000005` |
| `7 / 2` | `3.5` (`decimal`) | `3.5` (`float`) |
| `round(2.5)` | `3` | `2` |
| `round(2.675e0, 2)` | `2.68` | `2.67` |
| `10 ** 70` | помилка P2309 | ціле з 71 цифри |
| `True + 1` | помилка P2304 | `2` |

Округлення одне для всіх чисел — половина від нуля, `float` округлюється за своїм десятковим записом. Гроші — лише `decimal`: грошові функції не приймають `float`.

```prml
Ціна: |(money(2.20 * 3, "UAH")), разом із ПДВ |(money(round(2.20 * 3 * 1.2, 2), "UAH")).
```

## Рядки

Рядок — символи Unicode, як у Python 3: `len("Київ") == 4`. Відмінності:

- є лише методи зі списку специфікації (розділ 12.10): `split`, `join`, `strip`, `replace`, `startswith`, `find`, `upper`, `lower`, `title`, `zfill`, `format` і деякі інші; `center`, `partition`, `encode` — помилка P2313;
- f-рядки — за синтаксисом Python 3.11: усередині фігурних дужок не можна лапок того самого виду, що навколо рядка (P1208); пишіть `f"{d['k']}"`;
- `"{0.name}".format(r)` — помилка P2330; поле запису читається за ключем: `"{0[name]}"`;
- специфікація формату (`f"{x:,.2f}"`) — англійська й мови документа не знає; для тексту є `num()`, `money()`, `fmt_date()`.

```prml
|code:
сума = 1234.5
|end
Python-формат: |(f"{сума:,.2f}"); формат документа: |(num(сума, 2)).
```

## Списки, кортежі, словники

Як у Python, разом із генераторами списків і словників та розпакуванням. Відмінності:

- множин немає: `{1, 2}` — помилка P2101; унікальність — словником або `not in`;
- операторів `|`, `&`, `^`, `<<`, `~` немає; словники об'єднують `{**a, **b}`;
- `is` — лише з `None` (P2103);
- ключ словника — незмінне значення; `float` і довжина ключем бути не можуть (P2317); `5` і `5.00` — один ключ;
- `range()` і `reversed()` повертають список;
- `lambda` немає: функція для `key=` — звичайний `def`.

```prml
|code:
def мінус(x):
    return -x
порядок = sorted([3, 1, 2], key=мінус)
|end
|(join_list([str(x) for x in порядок]))
```

## Записи

Запис (`record`) — незмінне значення з полями: `r.назва` або `r["назва"]`. Записами стають параметри заголовка YAML, дані проєкту, результати `load_csv`, `load_yaml`, `load_json`. У Python схожий `namedtuple`, але запис — не послідовність:

- `"назва" in r` і `len(r)` — помилки; поле перевіряють `hasattr(r, "назва")`;
- відсутнє поле — помилка P2314; `getattr(r, "ціна", 0)` дає значення за замовчуванням;
- новий запис зі зміненим полем — `r.replace(кількість=4)`; у словник — `dict(r)`.

```prml
---
doc: {language: uk-UA}
params:
  сторона: {назва: "ТОВ «Альфа»", код: "12345678"}
---
|(сторона.назва), ІПН: |(getattr(сторона, "ІПН", None) or "—").
```

YAML читається за правилами Primula: `15.00` — `decimal` із двома знаками, дата без лапок — `datetime`.

## Дати й довжини

Дата й момент — один вбудований тип `datetime`, без `import`; точність — секунда, поясів немає.

- `дата + 30`, `дата - 30` — зсув на доби; `дата - дата` — число діб (`decimal`), а не `timedelta`;
- `hours(36)`, `weeks(2)` — числа діб: `дата + hours(36)`; календарні місяці — `add_months(дата, 1)` (31 січня + 1 місяць = 28 лютого);
- `weekday` — атрибут від 1 (понеділок) до 7, а не метод від 0;
- у текст дата виводиться `fmt_date(дата, "contract")`.

Довжина — число з одиницею: `10*mm` або `"10mm"`; константи `mm`, `cm`, `pt`, `inch` (не `in`). Результат — в одиниці лівого операнда, порівняння — з допуском 0,001 мм.

```prml
|code:
підписано = date(2026, 10, 12)
оплата = підписано + 10
|end
Оплата до |(fmt_date(оплата, "contract")) — через |(оплата - підписано) днів, |(fmt_date(add_months(підписано, 1), "long")) — через місяць.
```

## Функції

`def` зі значеннями за замовчуванням, `*args`, `**kwargs`, параметрами лише за іменем, рекурсією, вкладеними функціями й замиканнями; усередині функції змінні змінювані, є `while`. Відмінності:

- немає `lambda`, генераторів (`yield`), `global`, `nonlocal`; декоратор єдиний — `@export` (розділ «Модулі й фрагменти»);
- значення за замовчуванням обчислюються один раз і заморожуються: пастка Python `def f(x, acc=[])` тут — помилка P2318 під час першого `append`;
- глобальний список, переданий у функцію, теж заморожений: будується новий список;
- замість межі рекурсії Python — ліміти: глибина 500, 20 с на одне обчислення, 10 000 000 елементів.

```prml
---
doc: {language: uk-UA}
params:
  позиції:
    - {назва: "Папір", кількість: 20, ціна: 120.50}
    - {назва: "Ручки", кількість: 100, ціна: 15.00}
---
|code:
def рядки(позиції):
    result = []
    for i, p in enumerate(позиції, 1):
        result.append(record(n=i, назва=p.назва, сума=p.кількість * p.ціна))
    return result
|end
|table(cols=["10mm", "*", "35mm"]):
|: № |& Найменування |& Сума, грн
|for(р in рядки(позиції)):
|: |(р.n) |& |(р.назва) |& |(num(р.сума, 2))
|endfor
|end table
```

## Глобальні імена: ліниві й незмінні

Це друга велика відмінність після чисел. Python виконує модуль згори донизу й дозволяє переприсвоїти ім'я. У Primula визначення верхнього рівня — `x = …`, `def`, `|let`, параметри заголовка — збираються з усього файла заздалегідь, обчислюються під час першого звернення й заморожуються.

- Порядок у тексті неважливий: ім'я можна використати вище за його визначення.
- Повторне визначення — помилка P2203, `x += 1` на верхньому рівні — P2105, цикл визначень — P2204. Параметр заголовка теж не можна перевизначити в коді.
- Визначення, яке ніхто не читає, не обчислюється — і його помилка не проявиться, доки ім'я не знадобиться.
- Решта операторів верхнього рівня (`for`, `if`, виклики) — дії: виконуються після збирання визначень, а імена всередині них локальні (попередження P2501).
- Умовне значення — умовний вираз: `ставка = 20 if платник_пдв else 0`.
- Накопичення — генератор списку або функція, а не `append` у циклі верхнього рівня (P2318).

```prml
|code:
разом = ціна * кількість
ціна = 250.00
кількість = 4
ставка = 20 if разом > 500 else 0
|end
Разом |(num(разом, 2)), ПДВ |(ставка) %.
```

```prml error=P2203
|code:
x = 1
x = 2
|end
```

## Модулі й фрагменти

**Модуль** (`.m.prml`, `|import`) містить лише визначення. Усі його імена без `_` на початку відкриті, експортувати нічого не треба; ім'я з `_` закрите насправді (`модуль._имя` — помилка).

```prml file=lib/ціни.m.prml
|code:
_ставка = 20

def з_пдв(сума, ставка=_ставка):
    return round(сума * (100 + ставка) / 100, 2)
|end
```

| Підключення | Звернення |
| --- | --- |
| `\|import("lib/ціни")` | `ціни.з_пдв(…)`, макрос — `\|ціни.ім'я(…)` |
| `\|import("lib/ціни", "з_пдв")` | `з_пдв(…)` без префікса |
| `\|import("lib/ціни", alias="ц")` | `ц.з_пдв(…)` (`as` — ключове слово Python) |

`|import` документа діє й у фрагментах, які документ підключає; `|import` усередині фрагмента — лише в цьому фрагменті. Шлях пишеться від файла з командою.

```prml
|import("lib/ціни")
Разом із ПДВ: |(num(ціни.з_пдв(1000.00), 2)) грн.
```

**Фрагмент** (`.f.prml`, `|include`) — текст документа з власними визначеннями, і вони закриті: один фрагмент можна підключити двічі без конфлікту. Документ бачить лише експортоване (рішення 135):

| Запис у фрагменті | Що експортується |
| --- | --- |
| `@export` над `def f(…)` верхнього рівня `\|code:` | функція під своїм ім'ям |
| `@export(name="g")` над `def _f(…)` | функція під ім'ям `g`; `_f` лишається закритою |
| `\|export("підпис", "f")` | уже визначені імена: макроси `\|def`, функції, `\|let` |
| `\|let(x=…, export=True)`, `\|export(x=…)` | нове значення |

```prml file=fragments/знижки.f.prml
---
kind: fragment
---
|code:
@export
def знижка(сума, відсоток):
    return round(сума * (100 - відсоток) / 100, 2)
|end
|def рядок(назва, сума):
|(назва) — |(num(сума, 2)) грн
|enddef
|export("рядок")
```

```prml
|include("fragments/знижки")
|рядок("Папір зі знижкою", знижка(2410.00, 5))
```

Якщо два фрагменти експортують одне ім'я, конфлікт розв'язується під час підключення: `|include(…, ns="f")` кладе експорт у `f.*`, `rename={…}` перейменовує. `@export` поза фрагментом — помилка P2610, над вкладеною функцією — P2106, у модулі — попередження P2638 (там усе й так відкрите). Функціям, якими користуються кілька документів, місце в модулі; із фрагмента експортують те, що стосується його тексту.

## Значення в тексті й макроси

Виведення немає: значення потрапляє в документ лише виразом `|(…)`, і тип вирішує, як саме.

- Рядок, число, дата, розмітка (`content`) вставляються. Дробове число чи дата без оформлення — попередження P2604: оформлюйте `num()`, `money()`, `fmt_date()`.
- `None`, `bool`, список, словник, запис — помилка P2603, а не «None» чи «[1, 2]», як дав би `str()`. Необов'язкове значення — `|(x or "—")`, список — `join_list()`.
- Розмітка непрозора: `markup("…") + "…"` — помилка; рядки спершу з'єднують, потім викликають `markup()`.
- Функція з `|code:`, викликана як команда `|f(…)`, вставляє свій результат; макрос `|def` отримує тіло виклику параметром `body`.

```prml error=P2603
|(None)
```

```prml
|code:
def жирно(текст):
    return markup("|*{" + текст + "}")
|end
|def позначка(текст, body):
|.Note: |*{|(текст):} |(body)
|enddef
|позначка("Увага"):
Текст із |жирно("виділенням").
|end
```

## Чого в ядрі немає

Документ має збиратися однаково на будь-якій машині, тому в ядрі немає вводу-виводу (крім `load_*`), годинника (`build_date()` фіксується `--build-date`), випадкових чисел і доступу до внутрішніх об'єктів Python. Заборонено `import` (модулі підключаються `|import` у розмітці), `class` (дані — `record`), `try`/`raise` (помилка зупиняє збирання з позицією; `fail("…")` — навмисна помилка), `lambda`, `yield`, `async`, `global`, `nonlocal`, `del`, `with`, множини, побітові оператори, анотації, `else` у циклах, декоратори, крім `@export`, імена на кшталт `__class__`. Усе це виявляється ще під час розбору коду, до обчислення; повний перелік із замінами — у прикладі (`forbidden.prml`) і в розділі 12.2 специфікації.

```prml error=P2101
|code:
квадрат = lambda x: x * x
|end
```

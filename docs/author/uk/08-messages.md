# Повідомлення транслятора

Транслятор перевіряє документ цілком — від кодування до посилань і таблиць — і повідомляє про все, що знайшов, а не лише про першу помилку. Документ з помилками не збирається; з попередженнями — збирається, але попередження майже завжди вказує на справжню проблему.

## Як читати повідомлення

```
договір.prml:6:9: error[P2201]: ім'я 'сумма' не визначено
 6 | Сума: |(сумма).
   |         ^^^^^
договір.prml: 1 помилка, 0 попереджень
```

- `договір.prml:6:9` — файл, рядок, стовпець. Помилка у фрагменті чи модулі вказує їхній файл і місце підключення.
- `error` — помилка, `warning` — попередження.
- `P2201` — код. Перша цифра — область: P0 командний рядок і файли, P1 синтаксис, P2 імена й обчислення, P3 стилі, P4 структура й посилання, P5 таблиці, P6 сторінки й графіка, P7 модулі й проєкт, P8 запис ODT, P9 технічна документація. Повний перелік із текстами — додаток [«Повідомлення»](generated/diagnostics.md).
- Рядок із `^^^` показує місце; рядки `= help:` і `= note:` — підказка й пояснення.

Мова повідомлень — `--lang uk|ru|en` або змінна `PRIMULA_LANG`. Для програм і редакторів — `--format json`: список повідомлень із полями `code`, `severity`, `message`, `file`, `line`, `column`. Код завершення: 0 — без помилок, 2 — є помилки.

У Studio повідомлення перевірки зібрано в панелі; клацання відкриває місце в редакторі, F1 на конструкції — її розділ специфікації.

## Попередження і випуск

`--strict` перетворює попередження на помилки з тим самим кодом. Так збирають остаточну редакцію: незаповнені місця `|?{…}`, неоформлені числа й пряме форматування не пройдуть.

```sh
primula build договір.prml --strict --pdf
```

## Часті помилки

### Стиль без тексту — P1209

Ім'я стилю після `|.` — ідентифікатор, а не текст. Якщо під час правки воно змінилося («Місце-дата» → «Місце і дата»), рядок перестає бути стилем:

```prml error=P1209
|.Місце-дата
```

Поверніть ім'я стилю й пишіть текст після двокрапки: `|.Місце-дата: м. Харків, 12.10.2026`. Список імен стилів — панель «Стилі» Studio або `--dump-styles`.

### Ім'я не визначено — P2201

```prml error=P2201
Сума: |(сумма).
```

Помилка в імені параметра чи змінної, параметр не оголошено в `params:` документа чи проєкту, функція модуля без `|import`. Модуль `std/math` у документі підключають явно: `|import("std/math")`.

### Команда «з'їла» слово — P2601

```prml error=P2601
|(1)|sellerом
```

Літера одразу після імені команди продовжує ім'я: `|sellerом` — це команда `sellerом`. Роздільник `|;` закінчує ім'я: `|seller|;ом`.

### Пробіл після риски — P1201

```prml error=P1201
Ціна | 100 грн.
```

Після `|` мають іти літера, `(` або знак короткої форми. Сама риска в тексті пишеться двома: `||`.

### Неправильне закриття — P1218, P1219, P1224

`|end` закриває найближче оточення, але не керівні конструкції: `|if` закривається `|endif`, `|for` — `|endfor`, `|def` — `|enddef`. Блок `|code:` закривається рядком з одного `|end`, без імені (`|end code` — помилка P1224). Пункт у рядковій формі (`|> текст`) оточенням не є, і `|end` після нього — зайвий (P1218).

```prml error=P1218
|> Пункт.
|end
```

### Значення не можна вивести — P2603, P2604

`|(…)` виводить рядок, число, дату або розмітку. `None`, логічне значення, список чи запис — помилка P2603: використовуйте `str()`, `join_list()` або поле запису.

Дробове число, сума чи дата без функції оформлення — попередження P2604:

```prml error=P2604
|(dec("1.5"))
```

Оформлюйте бібліотекою: `num(x, 2)`, `money(x, "UAH")`, `fmt_date(d, "long")`.

### Невідомий стиль — P3108

```prml error=P3108
|.Невідомий: текст
```

Стилю немає в жодному підключеному модулі: помилка в імені або не підключено набір (`styles:`). Які модулі підключено — `--dump-styles` або панель «Стилі».

### Посилання й ID — P4301, P4102

```prml error=P4301
Див. |@("оплата").
```

Цілі з таким `id=` немає: помилка в імені, ціль вилучено чи виключено умовою. Повторний `id=` — помилка P4102 з позиціями обох місць.

### Пропуск рівня — P4201

```prml error=P4201
|< Розділ
|<<< Підрозділ
```

Заголовки йдуть за рівнями: після `|<` — `|<<`, а не `|<<<`. Так само зі списками й пунктами.

### Таблиця — P5103, P1226

```prml error=P5103
|table(cols=["*", "*"]):
|: а |& б |& в
|end table
```

Кількість клітинок рядка не збігається з кількістю стовпців (з урахуванням `span=`). Порожня клітинка пишеться явно: `|&` без тексту. Текст усередині таблиці поза рядком `|:` — помилка P1226.

### Ключ заголовка перейменовано — P1120

Ключі `document:` і `documents:` попередніх версій перейменовано: метадані — `doc:`, у проєкті — `doc_defaults:` і `ref_documents:`.

### Заповнювач — P2635

`|?{…}` залишено в документі. Під час чорнового збирання це попередження, з `--strict` — помилка.

## Якщо незрозуміло, що не так

- Перевірте ділянку окремо: `primula console документ.prml` відкриває консоль обчислювача з іменами документа — там можна обчислити вираз (`:help ім'я` — опис функції).
- `primula check документ.prml --dump-tree` показує, як транслятор зрозумів структуру: де закінчується пункт, що ввійшло до таблиці.
- У Studio права кнопка миші на конструкції дає підказку й розділ специфікації.

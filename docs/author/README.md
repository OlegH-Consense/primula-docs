# Руководство автора Primula — устройство и правила

Руководство для автора документов (этап 15.4): как написать договор, акт, письмо, техническое описание, проект из нескольких документов, как выбрать и настроить стили и что делать с сообщениями транслятора. Начало — [ru/index.md](ru/index.md) ([uk](uk/index.md), [en](en/index.md)). Исходный язык — русский; переводы на украинский и английский делаются по зафиксированному промпту с глоссарием (этап 15.5).

## Состав

Каждый язык — свой каталог с одинаковой раскладкой: `ru/` (исходник), `uk/`, `en/` (переводы).

- `<язык>/index.md` и `<язык>/01-start.md` … `11-libraries.md` — страницы руководства (пишутся вручную; русские — исходник).
- `<язык>/generated/` — приложения, сгенерированные из справочника транслятора: `constructs.md` (конструкции), `functions.md` (функции выражений с вычисленными примерами), `header-keys.md` (ключи заголовка), `diagnostics.md` (сообщения), `styles.md` (стили комплекта `std/styles/*`: основа, шрифт, стили каждого набора). **Вручную не правятся.**
- `glossary.md` — единые термины ru/uk/en (общий; со страниц — `../glossary.md`); `README.md` — эти правила; `translation-prompt.md` — промпт перевода.

## Правила

1. Справочные данные не переписываются в текст: аргументы, списки функций, коды сообщений — в приложениях. Страница объясняет задачу и ссылается на приложение.
2. Каждый пример Primula — блок ` ```prml `; его проверяет транслятор. Блок, начинающийся с `---`, — целый документ; иначе к нему добавляется заголовок `doc: {language: uk-UA}`. ` ```prml skip ` — не проверять (намеренно неполный код), ` ```prml error=P1209 ` — пример с ожидаемым сообщением (ошибкой или предупреждением), должен дать ровно этот код. ` ```prml file=styles/local.s.prml ` (а также ` ```csv file=… `, ` ```yaml file=… `) — файл, который используют остальные примеры страницы: фрагмент, модуль, модуль стилей, данные, `project.p.prml` (с ним примеры проверяются в проекте); сам он не проверяется. Каждая страница проверяется в своём каталоге.
3. Страница перечисляет разделы спецификации, на которые опирается, комментарием в начале: `<!-- spec: 2.3 5.7 8 -->` (`8` охватывает `8.*`). По нему находится страница, которую надо проверить после изменения спецификации.
4. Термины — из `glossary.md`.
5. В строках таблиц Markdown черта внутри кода экранируется: `` `\|include` `` (иначе GitHub делит ячейку).
6. Переводы uk и en — в `uk/` и `en/` с теми же именами файлов, по промпту `translation-prompt.md`; `tools/author_docs.py translations` показывает отсутствующие и устаревшие переводы, `--stamp` отмечает перевод актуальным.

Пример проверяемого блока:

```prml
|<(id="price") Ціна
|> Ціна становить |(money_full(dec("1200"), "UAH")).
|> Див. п. |@("price").
```

Пример намеренной ошибки:

```prml error=P1209
|.Місце-дата
```

## Инструмент `tools/author_docs.py`

```sh
python3 tools/author_docs.py appendices [--lang ru|uk|en] [--check]   # приложения из справочника
python3 tools/author_docs.py examples [ФАЙЛ.md…]                      # проверка примеров
python3 tools/author_docs.py affected [--since REV]                    # страницы, чьи разделы спецификации изменились
python3 tools/author_docs.py archives [--lang ru uk en] [--out DIR]    # архивы руководства для читателей
```

`archives` собирает по архиву zip на язык: `dist/primula-author-guide-<язык>-<версия>.zip` с каталогом `primula-author-guide-<язык>/` — содержимое каталога языка (страницы, приложения в `generated/`) и глоссарий в корне. Ссылка `../glossary.md` переписывается в `glossary.md`, все ссылки проверяются: ссылка за пределы архива — ошибка. Метка перевода (`<!-- translation: … -->`) удаляется, `README.md` и `translation-prompt.md` в архив не входят. Устаревшие переводы и приложения выводятся предупреждениями — перед выдачей архивов их стоит обновить. Архив собирается стандартным модулем `zipfile` Python; одинаковые исходники дают одинаковый архив (даты файлов — по последнему коммиту `docs/author`).

### PDF руководства

```sh
python3 tools/author_docs.py pdf [--lang ru uk en] [--check] [--force]
```

`pdf` собирает по PDF на язык — `<язык>/primula-author-guide-<язык>.pdf`: титул, оглавление с номерами страниц, страницы 01–11 (нумерованные главы), страница `index.md`, приложения А–Д и глоссарий; ссылки между страницами — переходы внутри PDF, заголовки — закладки. Собирает **сама Primula**: pandoc читает страницы Markdown, `tools/md_to_prml.py` переводит их дерево в разметку Primula (заголовки, абзацы, списки и окружения `|list:`, таблицы, код — `|verbatim` в стиле `Preformatted`, ссылки `|link`), документ со стилями `tools/author_guide.s.prml` (поверх `std/styles/technical`) собирает `primula build --pdf` через LibreOffice. Нужны pandoc и LibreOffice. PDF хранятся в репозитории (как шпаргалка): их берут пакет установки (`guide/<язык>/`, в Studio — «Справка → Руководство автора (PDF)») и комплект GitHub. Рядом — `….pdf.sources`: хеш исходников (страницы, приложения, глоссарий, стили, конвертер); `pdf` пересобирает только устаревшие PDF (`--force` — все), `--check` их перечисляет; тест требует актуальных PDF — после правки страниц: `pdf` и коммит.

`tests/test_author_docs.py` проверяет, что приложения `ru/generated/` (и `uk/`, `en/`) совпадают со справочником (после изменения транслятора — `appendices` и коммит), что примеры страниц проходят проверку, и работу поиска затронутых разделов.

# Примеры Primula (спецификация v1.1)

Шестнадцать примеров используют только то, что уже реализовано: разметку, вычислительное ядро, стандартную библиотеку (13.9, 13.9c), стили, структуру, таблицы, страницы и графику, средства техдокументации (13.10), файл проекта, пакетную сборку и сводные документы (13.11), стили комплекта (15.3), параллельные потоки (этап 16); пример 10 — справочник по диалекту Python вычислительного ядра; пример 11 — общая библиотека, подключённая символической ссылкой (решение 136); пример 12 — счёт с платёжным QR-кодом НБУ (библиотека `libraries/payment_qr`, решение 137); примеры 13–15 — команды, которые задают модули (направление 28): смета (`libraries/estimate`), библиографические ссылки (`libraries/bib`, накопитель `collect`/`collected`), собственная команда и словарь терминов; пример 16 — импорт документов Markdown, HTML и DOCX (`primula import`).

Примеры следуют спецификации v1.1:
- фрагменты, модули и модули стилей имеют подрасширения `.f.prml`, `.m.prml`, `.s.prml`; вид файла берётся из подрасширения, если в заголовке нет `kind`;
- строчная форма всегда заканчивается в конце строки (режима `para` больше нет), многострочное содержимое оформляется окружением;
- целые и дробные числа — один тип `decimal`, даты — `datetime`.

## Требования

- Python ≥ 3.11 и PyYAML 6. Этого достаточно для ODT.
- Для PDF — LibreOffice (`soffice` в `PATH`).
- Чтобы в PDF были номера страниц в оглавлении и ссылках «стор. N», нужен мост UNO (`libreoffice-pyuno` в openSUSE, `python3-uno` в Debian). Без него будет предупреждение P8008.
- Необязательно: fontTools и `fc-match` для точных ширин колонок `auto`. В примерах колонки `auto` не используются.

Устанавливать пакет не нужно: скрипт запускает транслятор из `../src`.

## Быстрый запуск

```sh
cd examples
./run.sh                 # ODT + отчёты JSON в out/
./run.sh --pdf           # то же плюс PDF
./run.sh --pdf --lang uk # сообщения транслятора по-украински (en, uk, ru)
```

Результаты появляются в `out/`:

- `*.odt` и `*.pdf`;
- `*.report.json` — отчёт сборки: файлы с SHA-256, фазы, параметры, лимиты, ширины таблиц;
- `basics.tree.txt` — вычисленное дерево документа примера 1;
- `project.report.json` — отчёт пакетной сборки примера 7 (проект и список целей с вложенными отчётами); сами результаты примера 7 пишутся внутрь проекта, в `07-project/out/`;
- `basics-print.*` — пример 1 с дополнительным слоем стилей `--style` (см. ниже);
- `manual-review.*` — пример 3 в режиме `--review`: в документ попадают все варианты, в том числе отключённые `features`: перед условным фрагментом — подпись «[when: …] — так/ні», подложка зелёная (вариант включён) или красная, строки таблицы — фоном, строчные ветки `|if` — примечаниями Writer; водяной знак «НЕ ДЛЯ ВИПУСКУ» вместо «ЧЕРНЕТКА».

Пример 4 намеренно содержит ошибки и предупреждения: скрипт выполняет для него только `check` и печатает диагностику.

Дополнительный модуль стилей можно передать параметром `--style` (повторяется; слои: `--style` → `styles` документа → код документа). Названный `--style` отключает встроенный `std/styles/default`, поэтому его указывают явно. Так `run.sh` собирает `basics-print`: документ без ключа `styles` получает слой `01-basics/styles/print.s.prml` (шрифт с засечками, цвет заголовков, поля, верхний колонтитул):

```sh
cd 01-basics
../../primula build basics.prml --style std/styles/default --style styles/print.s.prml
```

Модули из ключа `styles` документа — более поздний слой, чем `--style`. Поэтому `--style` удобен для документов без собственных стилей, а у документов с `styles:` он меняет только то, что их модули не переопределяют.

Отдельный файл собирается так:

```sh
cd examples/02-contract
../../primula build contract.prml --pdf     # contract.odt, contract.pdf рядом
../../primula check contract.prml --dump-tree
../../primula check contract.prml --dump-parsed
```

## Примеры

### 01-basics — базовая разметка

`01-basics/basics.prml` показывает:
- абзацы и внутристрочные короткие формы (`|*{}`, `|/{}`, `|_{}`, индексы, `|"{}`, `|?{}`);
- неразрывный пробел и разрыв строки (перевод строки сразу после `|\` пробела не даёт);
- заполнитель `|?{ДАТА}` — предупреждение P2635: каждый оставленный заполнитель виден при сборке;
- имена команд, переменных и макросов на украинском и разделитель `|;` (`|виріб|;М` → «X300М»);
- параметры заголовка и `|let`;
- выражения `|(…)`;
- внутристрочные и блочные `|if`/`|elif`/`|else`, цикл `|for`;
- маркированные и нумерованные списки с вложенностью;
- поля `|field.page`, `|field.pages`, `|field.title`;
- оглавление `|toc()`.

Что попробовать:
- поменять `n` в `|let` или `pages_planned` в заголовке;
- открыть `out/basics.tree.txt`: в нём видно, во что превратилась разметка.

### 02-contract — договор поставки

Файлы:
- `contract.prml` — документ;
- `styles/contract.s.prml` — модуль стилей поверх встроенного `std/styles/default`;
- `lib/business.m.prml` — модуль макросов: реквизиты и подписи; подключается как `|import("lib/business")`: расширение можно опустить, сначала ищется `business.m.prml`;
- `data/items.csv` и `data/parties.yaml` — данные.

Пример показывает:
- нумерацию разделов и пунктов (профиль `business`, ДСТУ 4163);
- перекрёстные ссылки `|@("id")` и `|@("id", "label")`;
- сноску;
- оглавление;
- приложение `|appendix` с позначением и подзаголовком;
- нижний колонтитул «сторінка N з M»;
- загрузку CSV и YAML в `|code:` и макросы из модуля `|import`.

Таблица спецификации:
- типизированные колонки `decimal` и `money` с выводом по локали uk (`1 150,00`, `грн`);
- строки из данных через `|for`;
- формулы ячеек `|=(…)`: `this_row`, `cell`, `sum(column(…, rows=body_rows()))`;
- итоги с ПДВ и объединение ячеек `span`.

Стандартная библиотека: дата договора `fmt_date(…, "contract")`, ставка `percent(20)`, загальна ціна прописью `money_full`, ПДВ `with_vat` — итоги в тексте совпадают с итогами таблицы. Параметр заголовка `vat` закрывает одноимённую функцию библиотеки (имена документа главнее встроенных, §10.4), поэтому налог считается как `with_vat(net, 20) - net`.

Что попробовать:
- `vat: false` в заголовке;
- добавить строку в `items.csv` — итоги пересчитаются;
- `live=True` в `|table(…)` — в ODT появятся формулы Writer для `this_row` и `sum(column(…))`. Строки ПДВ дадут ошибку P5114: `round()`, `len()` и переменная `rate` в формулу Writer не переводятся (решение 82). Это тоже показательно;
- `|@("pay", "page")` — ссылка на страницу (нужен UNO).

### 03-manual — настанова з експлуатації

Файлы:
- `manual.prml`;
- `styles/manual.s.prml` — профиль `report` (ДСТУ 3008), колонтитулы, альбомный стиль страницы, варианты стилей, сгенерированные циклом;
- `fragments/power.f.prml` — фрагмент с параметром (`|include("fragments/power", …)`);
- `img/*.svg`; `img/sign-warning.svg` — собственный рисунок предупреждающего знака (не пиктограмма ISO 7010).

Пример показывает:
- варианты по набору свойств изделия: `features` в заголовке и `when=has("wifi")` на пунктах и строке таблицы;
- `|include` с параметром;
- рисунок `|figure` с подписью и ссылкой;
- плавающее изображение с обтеканием;
- фрейм с логотипом, позиционированный от края страницы;
- раздел в две колонки с линией;
- смену стиля страницы на альбомный и обратно;
- водяной знак «ЧЕРНЕТКА» при `draft: true`;
- перечни рисунков и таблиц;
- блок `|!("danger", hazard=…, consequence=…)` со знаком (`admonition_symbols` в модуле стилей) и `|!("notice")` с цветной границей; группу примечаний под таблицей («Примітки:» и список); совет `|!("tip")`;
- сокращения `|abbr` (расшифровка при первом употреблении, `show=False`) и перечень `|list_of("abbr")`;
- алфавитный указатель: `|index(…, sub=…)` и `|list_of("index")`.
- значения с единицами: `qty`, `qty_range` («−20…+55 °C»), `convert` (0,15 А → 150 мА), напряжение прописью во фрагменте; единица `GHz`, которой нет в словаре библиотеки, добавлена в модуле стилей функцией `unit(…)`.

Что попробовать:
- `features: [bluetooth]`;
- `draft: false`;
- `model: "X500"` — изменится напряжение во фрагменте.

### 05-loan — договір позики з графіком платежів

Файлы:
- `loan.prml` — договор и приложение «Графік платежів»;
- `lib/фінанси.m.prml` — модуль с кириллическим именем (`|import("lib/фінанси")` → пространство `фінанси`): календарные функции, аннуитет, график, временное оформление сумм и дат, макрос подписи;
- `fragments/умови.f.prml` — фрагмент с частями `|part("дострокове")` и `|part("штрафи")`;
- `data/сторони.yaml` — реквизиты; ключи YAML — украинские идентификаторы (`сторони.позикодавець.назва`);
- `styles/позика.s.prml` — стили с украинскими именами (`Підпис`, `Реквізити`, `Графік`, `Без-рамок`).

Пример показывает:
- **decimal**: аннуитет `S·r / (1 − (1 + r)^−n)` и проценты считаются точно до копейки; сумма погашений тела совпадает с суммой займа, это проверяет `fail()` в блоке кода — при расхождении сборка остановится с позицией;
- **datetime**: `date()`, `dt + n`, `dt − dt` (дни периода), `weekday` (перенос с выходных на понедельник), собственный календарный сдвиг на месяц с усечением дня (30 → 28 февраля);
- функции и записи (`record`) в модуле, имена на украинском;
- `|include(…, part=…)` с параметром фрагмента;
- таблицу графика: двухстрочная шапка через `|row:`/`|cell(rows=2)`/`|cell(span=3)`, столбец `datetime`, столбцы `money`, фон строк по условию, формулы `|=(…)` и `live=True`;
- таблицу реквизитов без рамок с блочными ячейками;
- сноску с `id` и ссылку на неё, приложение с подзаголовком из f-строки.

`live=True`: итоги и «Усього» записаны формулами Writer (`<E3>+<F3>`, `sum <E3:E14>`). Если поменять число в ODT и обновить таблицу (Сервис → Обновить), Writer пересчитает итоги в том же числовом формате.

Что попробовать:
- `строк: 24`, `день_платежу: 15`, `ставка: 21.75`, `сума: 350000.00`;
- `строк: 12.5` — ошибка P2322 (`range` принимает только целое значение) в функции модуля, с примечанием о месте вызова.

Суммы, проценты и даты в тексте оформляет стандартная библиотека: `money_full`, `money`, `percent`, `words` с `plural(…, frac=…)` («вісімнадцять цілих п'ять десятих відсотка»), `fmt_date(…, "contract")`. Даты платежей считает модуль на `add_months` и `workdays` с календарём `data/календар.yaml`. Пока действует военное положение, праздники не являются выходными (ч. 6 ст. 6 Закону № 2136-IX), поэтому `holidays` в календаре пуст; переносятся только даты, выпавшие на субботу и воскресенье.

### 06-safety — інструкція з охорони праці

Файлы: `safety.prml`, `styles/інструкція.s.prml`. Пример посвящён системе стилей:

- имена стилей на украинском в YAML и в коде (`Гриф`, `Небезпека`, `Зразок`, `Колонтитул-праворуч`, `Список-дужка`, `Таблиця-ЗІЗ`, `Група-підписів`);
- параметрическая функция стиля `Відступ(base, n)` через `derive` и её применение `|.(Відступ("Body", 2)):`;
- параметры по месту `|.Body(before="l", after="s"):` и стили, порождённые циклом (`Абзац-після-вел`);
- вычисляемый стиль `|.("Небезпека" if заземлення else "Body"):` … `|end style`;
- `|list("Список-дужка")` для одного списка и `|set(numbered_list=…)` для окружения пункта, вложенный маркированный уровень `|#-`;
- именованный нумерованный список `|#(id="перевірки")` и его продолжение `|#(continues="перевірки")` после абзаца;
- стиль блока `|block("Група-підписів"):` (держать подписи вместе);
- зеркальные страницы (`mirror`) с разными нижними колонтитулами для левых и правых страниц, титульная страница со своим стилем (`next: Portrait`) без колонтитула;
- раздел с неравными колонками и `|newcolumn` (грифы «ПОГОДЖЕНО» и «ЗАТВЕРДЖУЮ»);
- стиль таблицы со свойствами шапки и каскад: фон столбца, фон и объединение ячейки, рамка отдельной ячейки, `valign`; подпись `|caption:` с разметкой;
- строка таблицы `when=` и условный текст `|if` по классу защиты;
- `|verbatim:` внутри стиля `|.Зразок:` (буквальные строки получают стиль окружения), `|comment:`;
- ссылки с падежом `|@("перед", "label", case="loc")` → «розділі 2», сноска и концевая сноска;
- макрос `розділ(…)`, который выводит заголовок с вычисляемым `level=` (в приложении — уровень из параметра).

Что попробовать:
- `клас_захисту: "II"` — исчезнут строка таблицы и абзац о заземлении, изменится пункт перечня;
- `рівень_додатка: 2` — ошибка P4201 (пропуск уровня в нумерованной зоне).

Список пронумерован «а), б)» форматом `а` (кириллица, решение 115): Writer нумерует по полному алфавиту, без пропуска букв. Даты оформлены `fmt_date`, срок пересмотра — `add_years` и `plural`.

### 07-project — проект: договір, акти, зведений пакет

Файлы:
- `project.p.prml` — файл проекта: параметры (`місто`, `договір`, `виконавець`, `замовник`, `абонплата`, `ставка_пдв`), карта ключей (`логотип`, `оплата`), слой стилей проекта, цели сборки; секция кода — `акти` из CSV, функция `параметри_акта` и пакетная сборка актов `build()` под `if batch_mode():`;
- `договір.prml`, `акт.prml`, `реєстр.prml`, `пакет.prml` — документы проекта;
- `fragments/оплата.f.prml` — две части условия об оплате (`передоплата`, `післяплата`);
- `styles/проєкт.s.prml` — слой стилей проекта (альбомная страница, нижний колонтитул с номером договора из параметра проекта);
- `data/акти.csv`, `assets/логотип.svg` (рисунок нарисован для примера).

Пример показывает:
- параметры проекта в документах: по имени (`|(місто)`) и как `project.*`; параметры документа `акт.prml` со значениями по умолчанию, чтобы его можно было собрать отдельно;
- карту ключей: `|img(key="логотип")`, `|include(key="оплата")` — ключ указывает на часть фрагмента (`файл#часть`); цель `договір-післяплата` переопределяет ключ (`keys:` в `targets`);
- пакетную сборку `primula build project.p.prml`: три цели заголовка и по акту на строку CSV (`build(…, params=…, output=…)`), ошибки одной цели не останавливают остальные;
- сводный документ `пакет.prml`: части `|document(…, scope=…)` с общей нумерацией страниц и общим оглавлением, у каждой части своя нумерация разделов; параметры актов передаются `params=` через функцию секции кода проекта; реестр — часть на альбомной странице (`page="Альбомна"`), его ссылки на страницы актов — по полным ID `акт-1:акт`.

Запуск (результаты в `07-project/out/`):

```sh
cd examples/07-project
../../primula build project.p.prml --pdf     # все цели
../../primula check project.p.prml           # проверка целей без записи
../../primula check project.p.prml --dump-project   # JSON описательной секции
../../primula build акт.prml -o out/акт.odt  # один документ проекта
```

Что попробовать:
- `on_conflict`, `limits`, `build_date` в заголовке проекта;
- в `договір.prml` объявить `місто: 5` — ошибка P7110 (тип не совпадает с параметром проекта);
- цель с неизвестным параметром (`params: {сумма: 1}`) — P7105 при проверке целей.

### 08-styles — стили комплекта

По документу на каждый набор стилей комплекта (§11.9, решение 133). Документ называет только набор — `styles: [std/styles/business]`; основа `std/styles/default` подключается через `extends` набора.

- `business.prml` — акт приймання-передачі: шапка організації, гриф «ЗАТВЕРДЖУЮ», назва, місце й дата, преамбула, таблиця послуг (`TableServices`) з формулами, графік (`TableSchedule`), реквізити сторін (`TableParties`);
- `letter.prml` — службовий лист за ДСТУ 4163:2020: бланк, вихідний номер, адресат на 90 мм, заголовок «Щодо …», текст з абзацним відступом, додаток, підпис, виконавець; номер сторінки — з другої сторінки вгорі;
- `technical.prml` — настанова: нумеровані заголовки, кроки (`StepList`) і їх результат, клавіші й пункти меню, текст програми та вивід, терміни, примітки `|!`, компактна таблиця, рисунок з SVG, лист реєстрації змін;
- `report.prml` — звіт за ДСТУ 3008:2015: титульний аркуш без номера, структурні елементи з нової сторінки, розділи без крапки після номера, назва таблиці над нею, рисунка — під ним, примітка, виноска, «ДОДАТОК А»;
- `compact.prml` — пам'ятка у дві колонки (`|section(cols=2)`).

### 09-parallel — параллельные потоки

Тексты рядом с выровненными началами блоков: `|parallel`, `|segment`, `|track` (§7.7, решение 134).

- `agreement.prml` — двомовний договір (uk/en) на наборі `business`: назви потоків над колонками, лінія між ними, заголовок і таблиця підписів на всю ширину, сегменти рядком (`|segment |track("uk"){…} |track("en"){…}`) і окруженням; кожен потік — своєю мовою (сума прописом, дата, лапки, мітки посилань «п. 1.1» / «cl. 1.1», виноски з однаковими номерами); однакова нумерація потоків; зміст основного потоку і `|toc(track="en")`; `parity="translation"` — потоки звіряються (структура, ID, посилання, імена, числа); перекладені сегменти підтверджено `primula parallel --stamp` (`rev`, `status`), сегмент `price` — у стані `translated`, `law` — без стану.
- `protocol.prml` — протокол розбіжностей: редакція постачальника (необов'язкова: нового пункту в ній немає), редакція покупця (основний потік) і коментар юриста (без нумерації, вузька колонка, дрібний шрифт); номери пунктів договору — явним текстом.

Работа с переводом из командной строки (или из Studio: «Сборка → Параллельные потоки» и контекстное меню редактора):

```sh
cd examples/09-parallel
../../primula parallel agreement.prml --check-status reviewed     # какие блоки не подтверждены (код 2)
../../primula parallel agreement.prml --stamp --track en --segment price --status reviewed
../../primula parallel agreement.prml --stub --track de           # заготовки нового потока (если он описан)
```

После правки украинского текста подтверждённого сегмента `check` выдаёт P5320 («перевод устарел»), после правки английского — P5321.

### 10-code — диалект Python вычислительного ядра

Код Primula — подмножество Python со своей семантикой (§12, также §3.7, §4.2, §10.4). Пример — документ-справочник по этому диалекту: тематические фрагменты `fragments/01-numbers.f.prml` … `10-forbidden.f.prml` собраны документом `code.prml` (набор `technical`, свой модуль стилей `styles/code.s.prml`, модуль `lib/ціни.m.prml`). Пример показывает исходный текст: код, определения и комментарии в PDF не печатаются, поэтому PDF читается вместе с исходником — об этом предупреждает блок в начале документа. В каждой таблице рядом стоят выражение, его значение и тип, вычисленные этой сборкой (функция `показ()`), и что даёт CPython 3 (колонка проверена запуском Python 3.13). Комментарии исходника (на английском) подробно объясняют места, где диалект расходится с Python.

- числа: `decimal` вместо `int` и `float`, количество знаков, деление, округление половины от нуля, 64 значащие цифры, `bool` вне арифметики;
- строки: символы Unicode, разрешённые методы, f-строки по синтаксису 3.11, `format` без атрибутов, формат не знает языка документа;
- списки, кортежи, словари: нет множеств и `|`, `is` только с `None`, ключи словаря, `range`/`reversed` возвращают список, `key=` без `lambda`;
- записи `record` в сравнении с `namedtuple`: не последовательность, `replace`, `getattr` с умолчанием, параметры YAML — записи;
- даты и длины: один тип `datetime`, сутки как число, `weekday` 1–7, `add_months`, `hours`; `length` с единицами;
- функции: `*args`, только именованные параметры, замыкания, `while`, лимиты глубины и цифр, замороженные умолчания (ловушка `acc=[]`);
- глобальные имена: ленивые, неизменные, порядок в тексте не важен; определения и действия; накопление функцией или генератором; пространство имён фрагмента и `export=True`;
- модули и фрагменты: три формы `|import`, закрытые имена `_`, `|import` документа виден во фрагментах, экспорт из фрагмента — `@export`, `@export(name=…)`, `|export("имя")` (решение 135), `ns=`;
- значения в тексте: какие типы вставляются, `None`/`bool`/список — ошибка, оформление `num`/`money`/`fmt_date`, `|if`/`|for` в строке, макрос с телом, `markup()`, функция как команда;
- чего нет и что писать вместо этого.

Два файла с намеренными ошибками (`run.sh` выполняет для них только `check`):

- `forbidden.prml` — запрещённые конструкции Python (`import`, `class`, `try`, `lambda`, `yield`, `global`, `with`, множества, `|`, `is 5`, аннотации, `for … else`, `__class__`, `x +=` на верхнем уровне, f-строка с вложенными кавычками того же вида, декоратор кроме `@export`, `@export` над вложенной функцией): находятся при разборе, все сразу;
- `mistakes.prml` — код, верный в Python, но ошибочный в Primula: повторное определение, переопределение параметра, цикл определений, `append` к замороженному списку, накопление в цикле верхнего уровня, изменяемое умолчание, `True + 1`, переполнение, `float` как ключ, `in` для записи, отсутствующее поле, сравнение разных типов, `{0.name}`, `float` в денежной функции, `@export` в документе, `None`/`bool`/список в тексте, `content + str`. Определения ленивы: ошибка в имени, которое никто не читает, не выводится, поэтому файл обращается к каждому имени.

### 12-payment-qr — счёт с платёжным QR-кодом

Счёт на оплату (`рахунок.prml`) с таблицей позиций и QR-кодом для оплаты приложением банка. ### 13-estimate — смета

`кошторис.prml`: смета с разделами, подитогами, скидкой и НДС. Команда `|estimate.table(позиції, vat=…, discount=…)` — макрос библиотеки `libraries/estimate` (подключена ссылкой `lib`, предупреждение P2639); `|estimate.total_words(…)` пишет итог цифрами и прописью. Показано:
- команда модуля вызывается через пространство имён, поэтому может называться как встроенная (`table`, решение 142);
- итог стоит в тексте **раньше** таблицы: он считается из данных (`estimate.totals`), а не из ячеек;
- валюта берётся из параметра `currency` заголовка: модуль читает параметры документа функцией `param` (решение 144);
- сумма в тексте, в таблице и прописью одинакова: каждая строка округляется до копеек, скидка — от «Разом», НДС — от суммы после скидки.

Что попробовать: заменить `currency: UAH` на `EUR` или `USD`, убрать `знижка` и `ставка_пдв` (итоговая строка станет одной), добавить позицию без `section`.

### 16-import — документы, импортированные из других форматов

В `source/` лежат три источника: `договір.md` (Markdown: номера пунктов набраны руками, набранное содержание), `інструкція.html` (HTML: заголовки, списки, таблица с объединением, код) и `акт.docx` (DOCX со стилями Word «Пункт» и «Службовий»). Рядом — результаты `primula import`: `договір.prml`, `інструкція.prml`, `акт.prml`; они собираются как обычные документы (`run.sh` делает `import-*.odt`).

```sh
cd examples/16-import
../../primula import source/договір.md -o договір.prml --force
../../primula import source/акт.docx -o акт.prml --force      # import-styles.yaml рядом: «Пункт» → пункт, «Службовий» → пропустить
../../primula import source/акт.docx --list-styles            # стили источника и во что они переходят
```

Показано: набранные номера «1.», «2.1.», «2.1.1.» становятся `|<`, `|>`, `|>>` с автонумерацией Primula (в сводке — сколько набранных номеров не совпало с нумерацией результата); набранное содержание — `|toc()`; таблица HTML с `colspan` — `|&(span=2)`; стили DOCX сопоставляются файлом `import-styles.yaml`; результат проверяется. Тест `tests/test_example_import.py` повторяет импорт и сравнивает с этими файлами. Нужен pandoc.

Что попробовать: добавить в `import-styles.yaml` свой стиль; запустить импорт с `--keep-numbers` (номера остаются текстом) или `--no-structure`; импортировать свой DOCX или ODT.

### 04-errors — диагностика

- `syntax.prml` — ошибки разбора: удалённый ключ `lines` (v1.1), запрещённый `import`, неизвестные короткие формы (`|$`, символ Unicode `|«`), `|–` вместо `|—` (с подсказкой), `level=` вместе с `|<<`, незакрытое окружение, YAML `yes`.
- `evaluation.prml` — ошибки вычисления: циклическое определение, переполнение числа (больше 64 значащих цифр), неизвестное имя и стиль, слипшееся имя команды `|продавецьом` (с подсказкой `|;`), неверное число ячеек, изменение замороженного списка.
- `warnings.prml` — документ собирается, но с предупреждениями линтера: смесь алфавитов в имени (P2502), имена-омоглифы `vat`/`vаt` (P2503), номер в тексте заголовка (P4202), число без оформления (P2604), оставленный заполнитель (P2635), прямое форматирование `|fmt` (P3118), строка после строчной формы (P1236). С `--strict` всё это — ошибки.

Ошибки следующей фазы выводятся, только если предыдущая прошла. Например, повтор ID и ссылка на несуществующую цель в `evaluation.prml` будут показаны, когда остальные ошибки исправлены. Формат сообщений как у gcc/rustc (`файл:строка:столбец`), поэтому редакторы умеют переходить по ним.
